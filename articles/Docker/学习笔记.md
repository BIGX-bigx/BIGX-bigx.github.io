# 1 Docker 核心概念回顾

## 1.1 镜像与容器的关系

**镜像（Image）** 是一个只读的静态文件包，里面打包好了操作系统基础、运行环境（比如 PHP）和应用代码，可以理解为一个"模板"，本身不会运行。

**容器（Container）** 是镜像的一个运行实例，是一个隔离的沙箱，具有自己的文件系统、进程、网络，是动态可变的。

类比理解：镜像 = 光盘，容器 = 把光盘装进机器后跑起来的系统。

```
镜像（只读模板）  →  docker run  →  容器（运行实例）
      ↑                                    ↓
  docker build                        可以有多个容器
  从 Dockerfile 构建                  基于同一个镜像
```
## 1.2 整体工作流程

```
编写 Dockerfile
       ↓
docker build  →  生成本地镜像
       ↓
docker run    →  启动容器（题目跑起来）
       ↓
docker exec   →  进入容器调试
       ↓
docker stop / rm  →  停止清理
```

# 2 镜像拉取问题与解决方案

## 2.1 为什么拉不下来

Docker 镜像默认从 Docker Hub（境外服务器）拉取，国内访问经常超时或被墙。

常见报错：

```
Error response from daemon: Get "https://registry-1.docker.io/...": dial tcp: i/o timeout
```

另一个容易踩的坑：即使你开了代理，`docker pull` 默认也不走系统代理。原因是拉取请求由 **Docker Daemon（守护进程）** 发出，Daemon 是系统级服务，不会继承你终端的代理环境变量。

## 2.2 最简单的办法：手动 pull 基础镜像（治标）

这是最省事的民间解法，文章里也提到过：

`docker build` 失败的根本原因往往是拉不下来 Dockerfile 第一行 `FROM` 后面的基础镜像。

**解决步骤：**

1. 看 Dockerfile 第一行，找到基础镜像名

```dockerfile
FROM php:7.4-apache   # ← 就是这个
```

2. 在魔法开着的情况下，手动先拉取这个镜像

```bash
docker pull php:7.4-apache
```

3. 本地有缓存了，再执行 `docker build` 就不会再去拉了，成功构建

> 适合临时出题调试，不想折腾代理配置的时候用这个就够了。

## 2.3 方案二：让科学上网对 Docker Daemon 生效（治本）

### Linux 配置 Docker Daemon 走代理

```bash
# 创建配置目录
sudo mkdir -p /etc/systemd/system/docker.service.d

# 创建代理配置文件
sudo nano /etc/systemd/system/docker.service.d/http-proxy.conf
```

写入以下内容（端口换成你自己代理端口，常见是 7890）：

```ini
[Service]
Environment="HTTP_PROXY=http://127.0.0.1:7890"
Environment="HTTPS_PROXY=http://127.0.0.1:7890"
Environment="NO_PROXY=localhost,127.0.0.1"
```

重载并重启 Docker：

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker

# 验证是否生效
sudo systemctl show --property=Environment docker
```

### Windows / Mac（Docker Desktop）配置代理

Docker Desktop → Settings → Resources → **Proxies**，填入：

```
HTTP Proxy:  http://127.0.0.1:7890
HTTPS Proxy: http://127.0.0.1:7890
```

点击 Apply & Restart。

## 2.4 方案三：配置国内镜像源（备用，稳定性差）
> 2023 年底大量国内镜像源陆续关闭，稳定性无法保证，优先走前两个方案。

编辑（或创建）`/etc/docker/daemon.json`：

```bash
sudo nano /etc/docker/daemon.json
```

写入：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com",
    "https://mirror.baidubce.com"
  ]
}
```

重启 Docker：

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker

# 验证
docker info | grep -A5 "Registry Mirrors"
```

> Windows/Mac：Docker Desktop → Settings → Docker Engine，在 JSON 里直接加 `"registry-mirrors"` 字段。

# 3 基础操作命令大全

## 3.1 镜像命令

```bash
# 查看本地所有镜像
docker images

# 在 Docker Hub 搜索镜像（比如找现成的 sqli-labs 靶场）
docker search sqli-labs

# 拉取镜像（不写标签默认拉 latest）
docker pull ubuntu
docker pull ubuntu:22.04

# 从 Dockerfile 构建镜像（-t 指定镜像名，. 表示当前目录为构建上下文）
docker build -t myimage .
docker build -t myimage:v1 .

# 删除镜像（如果报错说有容器在用，先删容器再删镜像）
docker rmi myimage
docker rmi myimage:v1
```

## 3.2 容器命令

```bash
# 查看正在运行的容器
docker ps

# 查看所有容器（包括已停止、报错闪退的）排错必用
docker ps -a

# 停止容器（优雅停止）
docker stop <容器名/ID>

# 启动已停止的容器
docker start <容器名/ID>

# 重启容器
docker restart <容器名/ID>

# 强制删除容器（加 -f 可以删除运行中的容器）
docker rm <容器名/ID>
docker rm -f <容器名/ID>

# 查看容器实时日志（-f 持续跟踪，不加 -f 只看历史）
docker logs <容器名/ID>
docker logs -f <容器名/ID>
docker logs --tail 50 <容器名/ID>    # 只看最后 50 行

# 进入运行中的容器（详见第 7 章）
docker exec -it <容器名/ID> /bin/bash

# 查看容器或镜像的详细信息（网络、挂载、环境变量等）
docker inspect <容器名/ID>
```

## 3.3 docker run 参数速查

```bash
docker run [参数] <镜像名> [命令]
```

|参数|全称|说明|示例|
|---|---|---|---|
|`-d`|Detach|后台运行，不占用终端|`docker run -d ubuntu`|
|`-i`|Interactive|保持标准输入开启|配合 `-t` 使用|
|`-t`|TTY|分配伪终端|配合 `-i` 使用|
|`-it`|—|交互式终端，进容器必用|`docker run -it ubuntu /bin/bash`|
|`-p`|Publish|端口映射，宿主机端口:容器端口|`-p 8080:80`|
|`-e`|Env|设置环境变量|`-e FLAG=flag{test}`|
|`-v`|Volume|目录挂载，本地路径:容器路径|`-v /本地/代码:/var/www/html`|
|`--name`|Name|自定义容器名|`--name my_ctf`|
|`--rm`|Remove|容器停止后自动删除，一次性测试用|`--rm`|

## 3.4 运行容器的三种典型场景

**场景一：一次性执行命令**（执行完就退出）

```bash
docker run ubuntu:22.04 /bin/echo "Hello world"
# Docker 创建容器 → 执行命令 → 输出结果 → 容器退出
```

**场景二：交互式进入容器**（适合调试探索）

```bash
docker run -it ubuntu:22.04 /bin/bash
# 出现 root@xxxx:/# 说明已进入容器内部
# 可以执行 ls、cat、python 等任意命令
# 输入 exit 退出
```

**场景三：后台常驻运行**（跑 Web 靶场必用）

```bash
docker run -d -p 8080:80 --name my_ctf php:7.4-apache
# -d 后台运行，终端不会被卡住
# 访问 http://localhost:8080 即可
```

## 3.5 容器生命周期操作

```
docker run  →  运行中(running)
                  ↓
             docker stop
                  ↓
            已停止(exited)
                  ↓
             docker start       docker rm
                  ↓                 ↓
             运行中(running)      已删除
```

修改代码后重新部署的标准流程：

```bash
docker stop my_ctf
docker rm my_ctf
docker build -t myimage .
docker run -d -p 8080:80 --name my_ctf myimage
```

## 3.6 其他命令

```bash
# 网络相关
docker network ls                    # 查看所有网络
docker network create my_net         # 创建网络
docker network inspect my_net        # 查看网络详情

# 数据卷相关
docker volume ls                     # 查看所有卷
docker volume rm <卷名>              # 删除卷

# 系统信息
docker info                          # Docker 系统详细信息（镜像数、容器数、存储驱动等）
docker version                       # 客户端和守护进程版本
docker stats                         # 实时查看所有容器资源占用（CPU/内存）
docker stats <容器名>                # 查看指定容器资源占用

# 仓库登录
docker login                         # 登录 Docker Hub
docker logout                        # 登出
docker push myimage                  # 推送镜像到仓库
```

# 4 Dockerfile 编写

## 4.1 常用指令速查

| 指令           | 执行阶段   | 说明                              |
| ------------ | ------ | ------------------------------- |
| `FROM`       | 构建时    | 指定基础镜像，必须是第一条指令                 |
| `RUN`        | 构建时    | 执行 shell 命令，结果打包进镜像层            |
| `COPY`       | 构建时    | 将宿主机文件复制进镜像，行为明确，推荐使用           |
| `ADD`        | 构建时    | 类似 COPY，但支持自动解压 tar，不推荐常规使用     |
| `ENV`        | 构建+运行时 | 设置环境变量，容器运行后依然存在                |
| `ARG`        | 仅构建时   | 构建参数，容器启动后不存在                   |
| `WORKDIR`    | 构建+运行时 | 设置工作目录，不存在会自动创建                 |
| `EXPOSE`     | 声明     | 声明容器监听的端口（不会真正映射，需配合 -p）        |
| `CMD`        | 运行时    | 容器启动时的默认命令，可被 docker run 末尾参数覆盖 |
| `ENTRYPOINT` | 运行时    | 容器启动时固定执行的入口，CMD 作为其参数传入        |
| `USER`       | 构建+运行时 | 切换执行命令的用户（安全加固用）                |
| `LABEL`      | 构建时    | 添加元数据，如作者、版本信息                  |
| `VOLUME`     | 运行时    | 声明匿名数据卷挂载点                      |
| `ONBUILD`    | 延迟构建   | 本次构建不执行，作为子镜像 FROM 该镜像时才执行      |

## 4.2 易混淆指令辨析

### CMD vs ENTRYPOINT

```dockerfile
# CMD：启动时执行的默认命令，可以被 docker run 后面的参数覆盖
CMD ["apache2-foreground"]
# docker run myimage /bin/bash  ← 这样会覆盖 CMD，执行 bash 而不是 apache

# ENTRYPOINT：固定入口，docker run 后面的参数会作为它的参数传入，不会被覆盖
ENTRYPOINT ["python", "app.py"]
CMD ["--port", "8080"]           # 作为 ENTRYPOINT 的默认参数

# 常见组合：ENTRYPOINT 定死执行什么程序，CMD 给默认参数
```

### ENV vs ARG

```dockerfile
# ENV：构建时和运行时都有效，容器启动后 env 命令能看到
ENV FLAG=flag{fake_flag}
ENV DB_HOST=localhost

# ARG：只在 docker build 过程中有效，构建完成后消失，更安全
ARG BUILD_VERSION=1.0
RUN echo "Building version $BUILD_VERSION"
# 容器启动后 BUILD_VERSION 就不存在了
```

### COPY vs ADD

```dockerfile
# COPY：单纯复制文件，行为透明，推荐日常使用
COPY src/ /var/www/html/
COPY flag /flag

# ADD：额外支持自动解压 tar.gz，支持从 URL 下载
# 除非明确需要解压功能，否则都用 COPY
ADD app.tar.gz /app/    # 会自动解压
```

## 4.3 CTF 题目 Dockerfile 模板

### 最简单的 PHP 题

```dockerfile
# 基础镜像：PHP 7.4 + Apache，开箱即用
FROM php:7.4-apache

# 设置工作目录
WORKDIR /var/www/html/

# 复制网站源码到 Web 根目录
COPY src/ /var/www/html/

# 复制 flag 到容器根目录
COPY flag /flag

# 设置 flag 权限为只读
# 444 = 所有人可读不可写（选手能读但不能改）
# 400 = 只有 root 可读（需要提权才能读）
RUN chmod 444 /flag

# 启用 Apache rewrite 模块（路由重写用，按需加）
RUN a2enmod rewrite

# 注入假 flag 供本地调试，避免真 flag 泄露到代码逻辑里
ENV FLAG=flag{this_is_a_fake_flag}

# 声明 80 端口
EXPOSE 80

# 启动 Apache
CMD ["apache2-foreground"]
```

### 带 SQLite 数据库的题目（参考极客题型）

```dockerfile
FROM php:7.4-apache

# 安装 SQLite 扩展
RUN apt-get update && apt-get install -y libsqlite3-dev sqlite3 \
    && docker-php-ext-install pdo pdo_sqlite \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /var/www/html/
COPY src/ /var/www/html/

# 创建数据库目录
RUN mkdir -p /databases

# 初始化正常业务数据库（可读写）
RUN sqlite3 /databases/app.db \
    "CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT, pass TEXT); \
     INSERT INTO users VALUES (1,'admin','123456');"

# 初始化 flag 数据库（只读 444，选手需要 ATTACH 跨库查询）
RUN sqlite3 /databases/flag.db \
    "CREATE TABLE secret (flag TEXT); \
     INSERT INTO secret VALUES ('flag{sqlite_attach_is_fun}');"
RUN chmod 444 /databases/flag.db

# Web 目录设为不可写，防止上传 Webshell
RUN chmod -R 555 /var/www/html/

EXPOSE 80
CMD ["apache2-foreground"]
```

### 带 MySQL 的题目（配合 Compose 使用，见第 6 章）

```dockerfile
FROM php:7.4-apache

# 安装 MySQL 扩展
RUN docker-php-ext-install mysqli pdo pdo_mysql

WORKDIR /var/www/html/
COPY src/ /var/www/html/
COPY flag /flag

RUN chmod 444 /flag
RUN chmod -R 555 /var/www/html/
RUN a2enmod rewrite

EXPOSE 80
CMD ["apache2-foreground"]
```

数据库连接时 host 直接写 compose 里的服务名（见 6.7）：

```php
$conn = new mysqli("db", "ctf", "ctf123", "ctf_db");
```

## 4.4 出题安全加固清单

|安全点|操作|原因|
|---|---|---|
|flag 文件权限|`chmod 444 /flag` 或 `chmod 400 /flag`|防止直接读写或修改|
|Web 目录不可写|`chmod -R 555 /var/www/html/`|防止上传 Webshell 直接 RCE|
|过滤输出|PHP 用 `htmlspecialchars()`|防止 XSS 非预期解|
|忽略敏感文件|配置 `.dockerignore`|防止 exp/源码被选手直接访问|
|假 flag 调试|`ENV FLAG=fake_flag`|本地调试时避免把真 flag 写进代码逻辑|
|flag 数据库只读|`chmod 444 /databases/flag.db`|SQLite 题防止直接写入绕过|

# 5 .dockerignore 文件

## 5.1 为什么需要它

执行 `COPY . /var/www/html/` 时，**当前目录下所有文件都会被复制进镜像**，包括：

- 你写的 exp 脚本、解题思路文件
- `.git/` 历史记录（可能泄露源码修改过程）
- `docker-compose.yml`（泄露题目整体结构）
- `.env` 里的数据库密码
- 源码备份、日志文件

选手一旦能访问这些文件，题目直接崩。`.dockerignore` 的作用就是告诉 Docker 在执行 `COPY` 时忽略哪些文件。

`.dockerignore` 必须放在 **Dockerfile 同级目录**（构建上下文根目录）。

## 5.2 语法规则

|写法|含义|
|---|---|
|`node_modules/`|忽略整个目录|
|`.git/`|忽略 .git 目录|
|`.env`|忽略单个文件|
|`*.log`|忽略所有 .log 后缀文件|
|`temp*`|忽略所有 temp 开头的文件/目录|
|`!important.txt`|例外：即使前面有 `*.txt`，也不忽略此文件|
|`# 注释内容`|注释行|

## 5.3 CTF 出题推荐配置

```gitignore
# .dockerignore —— CTF 出题专用

# 忽略出题者的解题脚本和 exp
exp.py
exp/
solver/
writeup/
*.exp

# 忽略 compose 文件，防止泄露题目整体结构
docker-compose.yml
docker-compose.yaml

# 忽略版本控制目录
.git/
.gitignore

# 忽略环境变量文件（里面可能有数据库密码）
.env

# 忽略编辑器配置
.vscode/
.idea/
*.swp

# 忽略日志和临时文件
*.log
*.tmp
temp*

# 忽略备份文件
*.bak
*.backup
```

# 6 docker-compose.yaml 编写

## 6.1 为什么需要 Compose

单个 Dockerfile 只能构建一个镜像/服务。CTF 题目经常需要多个服务协同：

- PHP Web + MySQL 数据库
- Web 服务 + Redis 缓存
- 前端 + 后端 + 数据库

手动逐个 `docker run` 还需要手动配置容器间通信网络，非常麻烦。用 `docker-compose.yaml` 只需一条命令 `docker compose up -d` 全部搞定。

## 6.2 六个顶级元素

```yaml
version: '3.8'    # 可选，指定 Compose 文件版本

services:         # 必需，定义所有服务（每个服务对应一个容器）
  ...

networks:         # 可选，定义自定义网络
  ...

volumes:          # 可选，定义持久化数据卷
  ...

configs:          # 可选，定义配置信息（较新特性，了解即可）
  ...

secrets:          # 可选，定义敏感信息（密码、密钥等，了解即可）
  ...
```

## 6.3 services 核心字段详解

### image —— 直接使用现成镜像

```yaml
services:
  db:
    image: mysql:5.7          # 直接用官方镜像，不需要写 Dockerfile
  cache:
    image: redis:latest
```

### build —— 从 Dockerfile 构建

```yaml
services:
  web:
    build: .                  # 简写，使用当前目录的 Dockerfile

    # 完整写法
    build:
      context: ./web          # Dockerfile 所在目录
      dockerfile: Dockerfile  # 文件名（默认就叫 Dockerfile 可省略）
      args:                   # 传递 ARG 构建参数
        BUILD_ENV: production
```

### ports —— 端口映射

```yaml
# 短语法（常用）
ports:
  - "8080:80"        # 宿主机 8080 → 容器 80
  - "3306:3306"      # 宿主机和容器端口相同
  - "80"             # 只写容器端口，宿主机端口随机分配

# 长语法（需要指定协议时用）
ports:
  - target: 80
    published: 8080
    protocol: tcp
    mode: host
```

### environment —— 环境变量

```yaml
# Array 写法
environment:
  - MYSQL_ROOT_PASSWORD=toor
  - MYSQL_DATABASE=ctf_db

# Map 写法（更直观）
environment:
  MYSQL_ROOT_PASSWORD: "toor"
  MYSQL_DATABASE: "ctf_db"
  FLAG: "flag{fake}"
```

### volumes —— 目录挂载

```yaml
# 短语法：本地路径:容器路径
volumes:
  - ./src:/var/www/html       # 本地改代码，容器实时生效，无需重启
  - ./logs:/var/log/apache2   # 日志持久化到本地

# 只读挂载（容器内不能修改）
volumes:
  - ./config:/etc/config:ro
```

### depends_on / restart / command / container_name

```yaml
services:
  web:
    build: .
    container_name: ctf_web        # 自定义容器名，方便 exec 进入

    depends_on:
      - db                         # 等 db 启动后再启动 web，防止连接失败

    restart: always                # 崩溃自动重启
    # restart: "no"                # 不重启
    # restart: on-failure          # 仅异常退出时重启
    # restart: unless-stopped      # 手动 stop 才不重启

    command: ["apache2-foreground"] # 覆盖 Dockerfile 里的 CMD
```

## 6.4 networks 详解

### 默认自动创建

不写 networks 配置时，Compose 会自动创建一个名为 `<项目目录名>_default` 的网络，同一 compose 文件里的所有服务自动加入，互相可通信。

### 自定义网络（推荐）

```yaml
services:
  web:
    networks:
      - ctf_internal
  db:
    networks:
      - ctf_internal

networks:
  ctf_internal:
    driver: bridge    # 默认就是 bridge，可省略
```

### 使用外部已有网络

```yaml
networks:
  my_existing_net:
    external: true    # 使用已存在的网络，不会自动创建
```

手动创建外部网络：

```bash
docker network create my_existing_net
```

### 四种网络驱动类型

|驱动|说明|适用场景|
|---|---|---|
|`bridge`|默认模式，容器之间隔离通信，通过虚拟网桥连接|单机多容器，CTF 出题常用|
|`host`|容器直接使用宿主机网络，无隔离|需要最高网络性能时|
|`overlay`|跨多台主机的容器网络，基于 VxLAN|多主机集群（Swarm）|
|`macvlan`|每个容器分配独立 MAC 地址，像真实物理机|需要容器直接接入物理网络|

> CTF 出题基本只用 `bridge`。

## 6.5 volumes 详解

### 绑定挂载（Bind Mount）

将宿主机的具体路径挂载进容器，本地改文件容器实时生效：

```yaml
volumes:
  - ./src:/var/www/html       # 相对路径
  - /home/user/data:/data     # 绝对路径
```

### 命名卷（Named Volume）

由 Docker 管理的持久化卷，数据不会因为容器删除而消失：

```yaml
services:
  db:
    volumes:
      - db_data:/var/lib/mysql   # 引用命名卷

volumes:
  db_data:                       # 顶级声明，Docker 自动管理存储位置
```

> CTF 出题一般用绑定挂载调试代码，用命名卷持久化数据库数据。

## 6.6 结合 .env 文件使用环境变量

创建 `.env` 文件（与 docker-compose.yaml 同目录）：

```env
MYSQL_ROOT_PASSWORD=toor
MYSQL_DATABASE=ctf_db
FLAG=flag{fake_flag_for_debug}
```

在 `docker-compose.yaml` 中引用：

```yaml
services:
  db:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ${MYSQL_DATABASE}
  web:
    environment:
      FLAG: ${FLAG}
```

好处是修改密码和 flag 只需改 `.env` 文件，不用动 yaml 文件。同时记得把 `.env` 加进 `.dockerignore` 和 `.gitignore`。

## 6.7 CTF 完整示例：PHP + MySQL

### 目录结构

```
sqli_challenge/
├── docker-compose.yaml
├── .env
├── .dockerignore
├── web/
│   ├── Dockerfile
│   └── src/
│       └── index.php
└── db/
    └── init.sql
```

### 完整 yaml 文件

```yaml
version: '3.8'

services:
  # 前端 Web 服务
  web:
    build:
      context: ./web
      dockerfile: Dockerfile
    container_name: ctf_web
    ports:
      - "8080:80"           # 访问 http://localhost:8080
    depends_on:
      - db                  # 等数据库启动后再启动 web
    environment:
      FLAG: "flag{fake_flag}"
    networks:
      - ctf_internal
    restart: always

  # 后端 MySQL 数据库
  db:
    image: mysql:5.7
    container_name: ctf_db
    environment:
      MYSQL_ROOT_PASSWORD: "toor"
      MYSQL_DATABASE: "ctf_db"
      MYSQL_USER: "ctf"
      MYSQL_PASSWORD: "ctf123"
    # 注意：不写 ports，数据库只暴露给内网，外部无法直连
    networks:
      - ctf_internal
    restart: always

networks:
  ctf_internal:
    driver: bridge
```

### 容器间通信说明

Compose 同一网络内的容器，**直接用服务名作为 hostname** 互相访问，不需要知道 IP：

```php
// web 容器内连接 db 容器，host 直接写服务名 "db"
$conn = new mysqli("db", "ctf", "ctf123", "ctf_db");
//                  ↑
//            docker-compose 里的服务名
```

# 7 进入容器 Shell 调试

## 7.1 docker exec -it 详解

```bash
docker exec -it <容器名/ID> /bin/bash
```

|参数|说明|
|---|---|
|`-i`|保持标准输入（STDIN）开启，允许输入命令|
|`-t`|分配一个伪终端（TTY），让界面正常显示|
|`-it`|两者组合，提供完整交互式 Shell 体验|
|`-u root`|以 root 身份进入（即使容器配置了低权限用户）|

```bash
# 标准进入方式
docker exec -it my_ctf /bin/bash

# 容器用的是 Alpine 镜像（没有 bash），用 sh
docker exec -it my_ctf /bin/sh

# 强制以 root 进入
docker exec -it -u root my_ctf /bin/bash
```

## 7.2 Compose 环境下进入容器

```bash
# 通过服务名进入，不需要知道容器名
docker compose exec web /bin/bash
docker compose exec db /bin/bash

# 以 root 进入
docker compose exec -u root web /bin/bash
```

## 7.3 进入后常用调试操作

```bash
# 查看 flag 文件权限和内容
ls -la /flag
cat /flag

# 查看 Web 目录结构和权限
ls -la /var/www/html/

# 查看当前所有环境变量（确认 FLAG 有没有注入）
env
env | grep FLAG

# 查看 Apache 错误日志
tail -f /var/log/apache2/error.log
tail -f /var/log/apache2/access.log

ps aux

# 测试数据库连通性（在 web 容器里 ping db 容器）

mysql -h db -u ctf -pctf123 ctf_db

# 查看网络配置
cat /etc/hosts          # 能看到 compose 自动配置的服务名解析
ip addr                 # 查看容器 IP
```

## 7.5 完整出题调试工作流

```bash

```
