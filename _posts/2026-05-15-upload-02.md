**为什么要理解目录结构**
```
核心问题：文件上传到服务器之后，我怎么知道能不能通过浏览器访问到它？

答案取决于：
  1. 文件存放在哪个物理路径
  2. Web 服务器的根目录（Web Root）在哪里
  3. 物理路径和 URL 路径是如何映射的
```
# 1 Web 根目录

## 1.1  概述
Web 根目录 = Web Root = Document Root

- **定义**：Web 服务器对外提供访问的起始目录

- **规则**：只有在这个目录【及其子目录】下的文件，才能通过 URL 被访问到


**比喻理解**
```
把 Web 服务器想象成一栋大楼：

整栋大楼 = 服务器的整个文件系统（/）
  ├── 地下室（/etc/ /var/ /root/）← 外人不能进，访客看不到
  ├── 大厅入口 = Web 根目录      ← 访客（用户）只能从这里进入
  │     ├── 一楼展厅（/index.html）
  │     ├── 二楼展厅（/uploads/）
  │     └── 三楼展厅（/admin/）
  └── 后台管理区（/root/）        ← 访客完全无法到达

结论：访客（浏览器用户）只能访问"大厅入口"里的内容
      上传的文件必须在"大厅"里，才能被访问到
```

# 2 不同 Web 服务器的默认目录结构
## 2.1 Apache（Linux 环境）
```
Linux 文件系统根目录：/
│
├── etc/
│   └── apache2/                   ← Apache 配置文件目录
│       ├── apache2.conf           ← 主配置文件
│       ├── sites-available/
│       │   └── 000-default.conf   ← 虚拟主机配置（重要！）
│       └── sites-enabled/
│
├── var/
│   └── www/                        
│       └── html/               ← ✅ Apache 默认 Web 根目录
│           ├── index.html      ← 对应 URL：http://x.x.x.x/
│           ├── uploads/        ← 对应 URL：http://x.x.x.x/uploads/
│           │   └── shell.php   ← 对应URL:http://x.x.x.x/uploads/shell.php
│           ├── admin/          ← 对应 URL：http://x.x.x.x/admin/
│           └── shell.txt       ← 这个是由我们自己创建，用于写入flag等内容
│
├── tmp/                        ← ❌ 临时目录，Web 无法访问
│   └── phpXXXXXX               ← 文件上传时的临时存放位置
│
└── root/                       ← ❌ root 家目录，Web 无法访问
```

**关键配置文件：`/etc/apache2/sites-available/000-default.conf`**

```apache
<VirtualHost *:80>
    # DocumentRoot 就是 Web 根目录的配置项
    DocumentRoot /var/www/html       ← 这里决定了 Web 根目录在哪
    
    <Directory /var/www/html>
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
```

## 2.2 Nginx（Linux 环境）
```
Linux 文件系统根目录：/
│
├── etc/
│   └── nginx/                      ← Nginx 配置文件目录
│       ├── nginx.conf              ← 主配置文件
│       └── sites-available/
│           └── default             ← 站点配置（重要！）
│
├── var/
│   └── www/
│       └── html/                   ← ✅ Nginx 默认 Web 根目录
│           ├── index.html
│           └── uploads/
│
├── usr/
│   └── share/
│       └── nginx/
│           └── html/               ← ✅ 部分发行版的默认 Web 根目录
│
└── tmp/                            ← ❌ 不可访问
```

**关键配置文件：`/etc/nginx/sites-available/default`**

```nginx
server {
    listen 80;
    
    # root 指令决定 Web 根目录
    root /var/www/html;              ← 这里决定了 Web 根目录在哪
    
    index index.html index.php;
    
    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php7.4-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }
}
```

## 2.3 IIS（Windows 环境）

```
Windows 文件系统根目录：C:\
│
├── Windows\                        ← 系统目录，不可访问
├── Program Files\                  ← 程序目录，不可访问
├── Users\                          ← 用户目录，不可访问
│
└── inetpub\                        ← IIS 相关目录
    ├── wwwroot\                    ← ✅ IIS 默认 Web 根目录
    │   ├── index.html              ← 对应 URL：http://x.x.x.x/
    │   ├── uploads\                ← 对应 URL：http://x.x.x.x/uploads/
    │   │   └── shell.aspx          ← 对应 URL：http://x.x.x.x/uploads/shell.aspx
    │   └── web.config              ← IIS 配置文件
    │
    ├── logs\                       ← 日志目录，不可访问
    └── temp\                       ← 临时目录，不可访问
```

## 2.4 常见 PHP 集成环境

```
PHPStudy / XAMPP / WAMP 等集成环境：

PHPStudy（Windows）：
  Web 根目录：C:\phpstudy\WWW\          或
              C:\phpstudy_pro\WWW\

XAMPP（Windows）：
  Web 根目录：C:\xampp\htdocs\

XAMPP（Linux）：
  Web 根目录：/opt/lampp/htdocs/

Docker 环境（CTF 题目最常用）：
  Web 根目录：/var/www/html/            ← 99% 的 CTF 题目都是这个
```

# 3 URL 与物理路径的映射关系

## 3.1 核心映射规则
```
URL 路径  =  Web 根目录  +  相对路径

举例（Apache，Web 根目录为 /var/www/html）：

http://target.com/              → /var/www/html/
http://target.com/index.php     → /var/www/html/index.php
http://target.com/uploads/      → /var/www/html/uploads/
http://target.com/uploads/a.php → /var/www/html/uploads/a.php
http://target.com/admin/login   → /var/www/html/admin/login
```

## 3.2 可访问 vs 不可访问
```
以 Web 根目录 /var/www/html/ 为界：

/var/www/html/uploads/shell.php   ✅ 可以访问
→ http://target.com/uploads/shell.php

/var/www/html/../shell.php        ✅ 等价于 /var/www/shell.php
→ 但通常服务器会禁止 ../ 路径穿越

/var/www/shell.php                ❌ 在根目录之外，无法访问
/tmp/shell.php                    ❌ 在根目录之外，无法访问
/root/shell.php                   ❌ 在根目录之外，无法访问
/etc/shell.php                    ❌ 在根目录之外，无法访问
```

```
文件系统                              URL 可见性
─────────────────────────────────────────────────
/                                    
├── etc/                             ❌ 浏览器无法访问
├── tmp/           
    └─- phpXXXXXX        ←上传临时文件 ❌ 无法访问
├── root/                            ❌ 无法访问
└── var/

        └── html/          ← Web根目录（这条线是边界）
            ├── index.php            ✅ http://x.x.x.x/index.php
            ├── config.php           ✅ http://x.x.x.x/config.php（能访问但不执行则返回源码）
            └── uploads/
                └── shell.php        ✅ http://x.x.x.x/uploads/shell.php
```

# 4 文件上传后的存储路径分析

## 4.1 存储在 Web 根目录内（危险）
```php
<?php
// 代码中的路径写法 → 实际物理路径 → 是否可访问

// 相对路径（相对于当前脚本所在位置）
move_uploaded_file($tmp, 'uploads/' . $name);
// 若脚本在 /var/www/html/upload.php
// 则实际存储到 /var/www/html/uploads/$name     ✅ 可访问

move_uploaded_file($tmp, './uploads/' . $name);
// 同上，./ 代表当前目录                          ✅ 可访问

move_uploaded_file($tmp, '../uploads/' . $name);
// 上级目录，存储到 /var/www/uploads/$name       ❌ 可能不可访问
?>
```

## 4.2 存储在 Web 根目录外（相对安全）
```php
<?php
// 存到 /tmp/ 或其他非 Web 目录
move_uploaded_file($tmp, '/tmp/uploads/' . $name);
// 存储到 /tmp/uploads/$name                     ❌ 无法直接访问

// 正确的安全做法：
// 存储路径在 Web 根目录外
// 读取时通过 PHP 脚本中转输出，而不是直接访问文件
?>
```

## 4.3 CTF 题目中最常见的路径

```php
<?php
$uploadDir = './uploads/';
// 等价于 /var/www/html/uploads/
// 对应 URL：http://题目IP:端口/uploads/

// 所以上传成功后，访问路径就是：
// http://题目IP:端口/uploads/你的文件名
?>
```

# 5 上传目录的权限配置对执行的影响
> 即使文件在 Web 根目录内可以访问，**能否执行**还取决于目录权限配置

## 5.1 Linux 文件权限
```bash
# 查看上传目录的权限
ls -la /var/www/html/uploads/

# 输出示例：
drwxrwxrwx  www-data www-data  uploads/
# d = 目录
# rwx = 所有者可读可写可执行
# rwx = 组可读可写可执行  
# rwx = 其他人可读可写可执行

# 注意：这里的"可执行"是对目录而言（可以进入目录）
# PHP 文件能否被 Web 服务器执行，取决于下面的配置
```

## 5.2 Apache 上传目录的执行权限配置
```apache
# 危险配置（CTF 题目和很多真实环境是这样）：
<Directory /var/www/html/uploads>
    # 什么都没配置 = 继承父目录配置 = PHP 可以执行
</Directory>

# 安全配置（正确做法）：
<Directory /var/www/html/uploads>
    php_flag engine off      ← 禁止 PHP 引擎解析此目录
    Options -ExecCGI         ← 禁止 CGI 执行
    RemoveHandler .php .phtml .php3
</Directory>
```

## 5.3 Nginx 上传目录的执行权限配置
```nginx
# 危险配置：location 规则匹配到了 uploads 目录下的 .php 文件
location ~ \.php$ {
    fastcgi_pass 127.0.0.1:9000;  ← 所有 .php 都会被执行，包括 uploads 下的
}

# 安全配置：
location /uploads/ {
    # 对 uploads 目录单独处理，不转发给 PHP 处理
    location ~ \.php$ {
        deny all;                  ← 禁止访问 uploads 下的 php 文件
    }
}
```

# 6 综合判断上传文件是否可访问可执行

## 6.1 快速判断流程
```
拿到题目后，判断上传文件能否被访问和执行：

Step 1：找到 Web 根目录
  → 看配置文件：DocumentRoot / root 指令
  → CTF 环境：大概率是 /var/www/html/
  → PHPStudy：大概率是 C:\phpstudy\WWW\

Step 2：确认上传路径在 Web 根目录内
  → 看源码中 move_uploaded_file 的第二个参数
  → 是相对路径（./uploads/）→ 在根目录内 ✅
  → 是绝对路径（/tmp/）→ 确认是否在根目录内

Step 3：确认能访问到文件
  → URL = http://目标/（上传路径去掉Web根目录部分）/文件名
  → 服务器是否返回了文件路径？直接用
  → 没有返回？看代码推断路径规律

Step 4：确认文件能被执行
  → 上传目录有没有禁止执行的配置？
  → CTF 中大多数没有 → 直接执行
  → 真实环境中需要测试
```

## 6.2 一张图总结
```
文件上传后
    ↓
路径在 /var/www/html/ 内？
    ├── ❌ 否（在/tmp/等）→ 无法直接访问，需要其他漏洞配合
    └── ✅ 是
         ↓
    URL 能推算出来吗？
         ├── ❌ 文件名完全随机且无返回 → 难以利用
         └── ✅ 能（返回了路径 / 文件名可预测）
              ↓
         目录禁止脚本执行吗？
              ├── ✅ 禁止了 → 无法执行，只能访问（有限危害）
              └── ❌ 没禁止
                   ↓
              文件扩展名被识别为脚本？
                   ├── ✅ 是（.php/.asp/.jsp）→ 🔴 完整利用
                   └── ❌ 否（.jpg/.png）
                        ↓
                   有无解析漏洞？
                        ├── ✅ 有 → 🔴 结合解析漏洞利用
                        └── ❌ 无 → 🟡 有限危害
```

> 💡 **核心记忆点**
> - **Web 根目录是边界**：只有根目录内的文件才能被 URL 访问
> - **CTF 中的 Web 根目录**：几乎固定是 `/var/www/html/`
> - **上传临时目录 `/tmp/`**：不在 Web 根目录内，无法直接访问
> - **可访问 ≠ 可执行**：还需要目录没有禁止脚本执行的配置
> - **看源码定路径**：`move_uploaded_file` 第二个参数就是存储路径
