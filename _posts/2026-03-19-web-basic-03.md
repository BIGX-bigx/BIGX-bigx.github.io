# 1. 前置基础
## 1.1  定义
PHP 内部提供的一套用于访问<u>本地文件系统、各种网络协议以及输入输出流（I/O streams）</u>的 URL 风格的**封装协议**。
## 1.2  使用原因
- **绕过防御与过滤 (Bypass)：** 规避服务器的后缀黑名单、内容过滤（WAF）或自动执行机制（将“执行”转化为“读取”）。
  
- **无文件落地 (Fileless)：** 恶意代码直接存在于内存或请求报文中，无需在服务器磁盘上生成实体文件，增加溯源和被杀毒软件查杀的难度。
  
- **触发隐藏机制：** 例如将常规的文件检查函数（`file_exists`）转化为危险的反序列化漏洞触发点（`phar://`）。
  
- **跨越网络边界 (SSRF)：** 将 Web 服务器作为跳板，将简单的 HTTP 请求转换为复杂的内网协议报文（如操作 Redis/MySQL）。

## 1.3  核心配置开关

| **配置项**             | **作用**                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `allow_url_fopen`   | PHP 中控制是否允许通过URL形式（如http://、php://）访问文件或数据流的开关，当它设为On时，PHP才会支持所有基于封装协议的操作，这是php://input、php://filter等伪协议能被解析和使用的前提 |
| `allow_url_include` | 主要控制是否允许通过include/require包含远程URL文件，当它设为On时，意味着可以直接用include(“php://input”)这种方式来执行伪协议中的代码，这在文件包含漏洞中是关键利用条件           |
# 2. 伪协议总结
## 2.1  文件系统与读取类
>此类伪协议主要利用 **LFI** 或**任意文件读取漏洞**，用于获取服务器上的敏感文件或代码
### `file://`协议
- **作用：** 用于访问本地文件系统，是标准的文件协议。常用于读取系统级的敏感文件。
  
- **前提：** 无特殊配置要求（不受 `allow_url_fopen` 和 `allow_url_include` 限制）。
  
- **使用：** 后面直接跟本地文件的绝对路径。
  
- **例子：** 
    - 读取 Linux 密码文件：`?file=file:///etc/passwd` 
    - 读取 Windows 配置文件：`?file=file:///C:/Windows/win.ini`

### `php://filter`协议
- **作用：** 用于在<u>读取或写入文件数据前</u>，对数据进行**过滤**（如编码、解码）。实战中常利用它将 **PHP 源码**进行 **Base64 编码**后读取出来，防止文件被直接解析执行，从而导致页面空白。也可以**防止乱码**
  
- **前提：** 无特殊限制。
  
- **使用：** `php://filter/read=过滤器/resource=目标文件`
  
- **例子：** 获取含有 flag 的源码（假设源码中包含 `VIDAR{xxxx}`）： `?file=php://filter/read=convert.base64-encode/resource=flag.php` 得到 Base64 字符串后，自己解码即可看到完整的 PHP 代码。
## 2.2  代码执行与数据流输入类
>此类伪协议能够将攻击者构造的恶意代码直接输入给 PHP 引擎执行
### `php://input`协议
- **作用：** 访问请求的原始数据的**只读流**。在文件包含漏洞中，可以利用它读取 POST 提交的数据，并当作 PHP 代码来执行。
  
- **前提：** `allow_url_include = On`。
  
- **使用：** URL 中使用 `php://input`，并在 HTTP 请求的 POST Body 中写入要执行的 PHP 代码。
  
- **例子：** (get和post都用，不是选择其一)
    - URL 参数：`?file=php://input` 
    - POST 数据：`<?php system('ls /'); ?>`

### `data://` 协议
- **作用：** 数据流封装器，允许在 **URL** 中<u>直接嵌入短小的明文或 Base64 编码数据</u>。配合**文件包含漏洞**，可直接执行 **URL** 中的 PHP 代码。
  
- **前提：** `allow_url_fopen = On` 且 `allow_url_include = On`。
  
- **使用：** `data://数据类型,数据内容` 或 `data://数据类型;base64,Base64编码的数据`
  
- **例子：** 
    - 明文直接执行：`?file=data://text/plain,<?php phpinfo(); ?>` 
    - Base64 编码执行（推荐，可绕过部分字符过滤）：`?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCd3aG9hbWknKTsgPz4=`
## 2.3 压缩包与归档文件绕过类
>此类协议常用于配合**文件上传漏洞**，绕过服务端对上传文件后缀的限制（例如只能上传图片）。
### `zip://`协议
- **作用：** 用于访问 ZIP 压缩包内部的文件。即使压缩包的后缀被改成了 `.jpg` 或 `.png`，PHP 依然能通过该协议解析内部的 PHP 脚本。
  
- **前提：** 无特殊限制。但必须使用**绝对路径**。
  
- **使用：** `zip://[绝对路径]#[压缩包内文件名]` （注意：URL 请求中 `#` 需要进行 URL 编码为 `%23`）。
  
- **例子：** 将 `shell.php` 压缩为 `shell.zip`，改名为 `shell.jpg` 上传。 包含利用：`?file=zip:///var/www/html/upload/shell.jpg%23shell.php`

### `compress.zlib://` 与 `compress.bzip2://` 协议
- **作用：** 这两个协议分别用于读取由 `gzip` 和 `bzip2` 压缩的数据流。作用与 `zip://` 类似，用于绕过后缀限制。
  
- **前提：** 无特殊限制（相对路径和绝对路径均可）。
  
- **使用：** `compress.zlib://压缩文件路径`
  
- **例子：** 将含有木马的 `shell.php` 压缩为 `shell.gz` 并改名为 `shell.jpg` 上传。 包含利用：`?file=compress.zlib://./upload/shell.jpg`
     - 注：./upload/shell.jpg是压缩并改名后生成的文件所在的路径。前面需要我们自己用gzip将shell.php压缩又改名(存放)然后上传，伪协议用来解压读取并执行

### `phar://` 协议
- **作用：** PHP 归档文件协议。在安全领域，它是触发 **PHP 反序列化漏洞**的利器。大部分文件系统函数（如 `file_exists`、`is_dir`、`filesize` 等）在解析 `phar://` 文件时，会自动反序列化其内部的 meta-data 数据。
  
- **前提：** 无特殊限制。
  
- **使用：** `phar://压缩文件路径/包内文件`
  
- **例子：** 生成一个含有恶意 meta-data 的 Phar 文件，改名为 `evil.gif` 上传。 触发反序列化：`?file=phar://upload/evil.gif/test.txt`
     - test.txt是占位符，可以是任意不存在的文件名
## 2.4  SSRF 探测与内网攻击类
>这些协议通常在 `curl`、`file_get_contents` 等函数发起的 **SSRF**（服务器端请求伪造）漏洞中使用，用于打穿内网。
### `dict://` 协议
- **作用：** 字典服务器协议。在 SSRF 中，主要用于**探测内网端口指纹**和部分服务的简单交互。
  
- **前提：** 服务端支持该协议（如 cURL 编译时未禁用）。
  
- **使用：** `dict://目标IP:端口/命令`
  
- **例子：** 
    - 探测内网 Redis 是否开放及版本信息：`?url=dict://127.0.0.1:6379/info` 
    - 探测内网 MySQL 端口：`?url=dict://192.168.1.100:3306/`

### `gopher://` 协议
- **作用：** **万能协议**，支持发送极其纯粹的 TCP 数据流。在 SSRF 中，它可以伪造几乎任何基于 TCP 的应用层协议请求（如 HTTP、Redis、MySQL、SMTP 等），常用于**反弹 shell** 或深度内网漫游。
  
- **使用前提：** 服务端支持且目标服务允许无认证或弱认证交互。
  
- **怎么使用：** `gopher://目标IP:端口/_经过多次URL编码的TCP载荷`
  
- **实战例子：** 利用未授权的 Redis 写定时任务来反弹 shell（这里仅展示结构框架，实际载荷需经过严格的 URL 编码）： `?url=gopher://127.0.0.1:6379/_*3%0d%0a$3%0d%0aset...[省略的具体Redis通信协议内容]...`
